# Optional taxonomy graph JSON

Current JSON output enumerates the transitive relation even when a fast route already holds a compact named-class graph. On 10689 this produced a 1.5-GiB raw output with 14,809,043 edges and 981,149 components. Its diagnostic classification completed in 41 seconds, but canonicalization failed under the existing audit contract. This motivates measuring output representation costs; it does not prove a new representation is faster.

The candidate adds explicit --json-edges (or KM_JSON_GRAPH_EDGES=1). Normal JSON remains byte-compatible and --lines remains separate. Opt-in JSON carries subsumptions_are_graph_edges=true: consumers must take transitive closure, and the edges need not be a transitive reduction. For graph-backed results it emits the same original edges excluding vertex self-loops; for other routes it retains the existing pairs. Consistency, unsatisfiable classes and dropped counts are unchanged. Unset the flag to roll back; no stored data is migrated or removed.

The existing frozen benchmark adapter already interprets both KM and baseline taxonomy edges through the same closure fingerprint. It accepts the optional metadata field without changing the relation or verification contract. Other readers must explicitly opt into graph semantics; default output is unchanged.

TaxonomyGraphSerialization.lean proves equality of the closures of mapped graph edges and mapped expanded reachability pairs, including cycles, self-loops and arbitrary name aliases. It does not prove the original source graph correct; that remains the existing routing and publication boundary. The module and its five axiom audits are added to the production routing gate, together with Rust serialization and CLI checks.

The Rust regression enumerates all 512 directed three-vertex graphs with distinct names and with aliases/escaping, and compares independently computed closures. It also retains prior default-byte tests, checks fallback routes and a 128-vertex chain whose optional output is linear. CLI checks cover explicit and environment selection, refusal preservation for invalid rdfs:Literal literals, and conflicting --lines options. All four production certification gates passed for the 705-file pinned source manifest, with no sorryAx. The production LTO build passed. See graph-json-certification-receipt.json, graph-json-production-build.json and graph-json-validation.json. End-to-end performance measurements remain pending; the option is not promoted to the default.
