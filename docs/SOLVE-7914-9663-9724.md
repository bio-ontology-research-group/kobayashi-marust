### Precise root cause in the port

Konclude's `CReapplyConceptLabelSet::insertConceptGetClash` preserves an intrusive,
newest-first descriptor chain on every successful insertion:

```cpp
mConceptDesLinker = conceptDescriptor->append(mConceptDesLinker);
```

See `CReapplyConceptLabelSet.cpp:210-244`. KM's production insertion path in
`completion/u36.rs::insert_concepts_to_individual_concept_set` changed the label-set
head but never assigned the previous head to `conceptDescriptor.next`. Every successful
insert therefore severed the adding-sorted descriptor chain.

That missing link has semantic impact in Konclude's
`CSaturationNodeExpansionCacheHandler.cpp:441-491`. The writer walks the descriptor
chain from the newest descriptor to `lastConDes`, using
`lastPossiblyNonDeterministicConDes->getNext()` as the start of the deterministic suffix.
With KM's broken chain, `getNext()` was null even though the old confirmed descriptor was
not the end of the logical label history. The faithfully ported C++ fallback at lines
476-477 then reset `conDesStart` to the newest descriptor. Concept 45405 was consequently
written twice: correctly in the nondeterministic prefix and incorrectly in the
deterministic suffix. The next completion probe trusted the deterministic copy and
derived the 29 false subsumptions.

### Exact targeted fix

The production insertion path now performs the Rust equivalent of Konclude's `append`
before calling the lifted label-set insertion:

```rust
let previous = label_set.get_adding_sorted_concept_description_linker();
con_desc_mut(concept_descriptor).set_next(previous);
```

No ontology identifier, concept identifier, cache exception, or new reasoning heuristic
was added. The cache traversal code did not need a special case. Restoring Konclude's
descriptor invariant makes the already-ported deterministic/nondeterministic split run
on the same list structure as the C++ implementation.

One adjacent constructor mismatch was also corrected exactly:
`CSaturationNodeAssociatedExpansionCache.cpp:42-44` defaults
`SaturationExpansionSatisfiabilityCacheCount` to 1, while KM defaulted the allowed
nondeterministic expansion count to 0. KM now defaults it to 1. This alignment is covered
by the cache split test, but it was not the cause of the 7914 extras: changing the count
alone left all 24 subject-9180 extras in place.

### Supporting Konclude ports needed to reach the failing cache path

The final two-line invariant repair closes correctness, but 7914 could not terminate
without the preceding faithful ports:

1. `initializeORProcessing`: priority-gated delay, common-disjunct injection, and
   implication replacement before branching.
2. `planORProcessing`: live-label containment, opposite-polarity and
   saturation-clash pruning, restriction-specification persistence, and trigger/delay

3. `executeORBranching`: revalidation, duplicate/complement pruning, deterministic

4. Satisfiable-cached OR and generating-existential parking/reapplication, saturation

5. Branch dependencies through OR-only, ALL, AQALL, role edges, and connection

The investigation deliberately retained exact ports that were independently verified

### Baseline and first causal gap

The initial production run, IBEX job 48792370, returned 685,932 of Konclude's 725,040
pairs: zero extra and 39,108 missing. Of those, 39,087 were 13,029 subjects each missing
`BFO_0000004`, `BFO_0000002`, and `BFO_0000001`. The ontology declares
`ObjectPropertyDomain(RO_0002202 BFO_0000004)`, followed by the ordinary BFO superclass
chain.

Konclude stores domain and range concepts directly on `CRole`. Its saturation
`createSuccessorForConcept` walks every signed indirect super role and adds the matching
domain concepts to the source node. KM's source-TBox bridge had a representation hole:
`TInput::source_axioms` contains only class axioms, but source mode discarded every
concept-bearing normalized clause. It therefore discarded the separately emitted RBox
domain/range clauses before the native `CRole` linkers were populated.

The first causal candidate recognized the normalized domain/range clause shape: one
non-self role atom in the body and one positive named concept on either role endpoint in
the head. Candidate job 48795405 then produced 724,407 pairs, zero extra, and only 633
missing. This recovered 38,475 pairs and established that native role linkers were the
first missing semantic boundary.

The full corpus gate then exposed why clause shape was not a sufficiently exact final
representation: clausifier-generated class-expression rules can have the same guarded
shape. The promoted fix therefore carries explicit source RBox provenance through
`TInput::role_domains` and `TInput::role_ranges`, installs only those pairs on `CRole`,
and suppresses every concept-bearing clausal duplicate in source mode. The actual 9663
ontology contributes 29 domains and 30 ranges through this channel; 9724 contributes
none. This is the same representation boundary as Konclude, not a broader clause
recognizer.

That provenance correction did not remove 9724's measured sweep movement. The final
trace still constructs 33,678 seeds versus 25,964 before the role-specific successor
port. The additional 7,714 items come from ranges generated by Konclude's role-automata
preprocessing, not from source RBox axioms. At the fixed 180-second saturation cap, the
old and final binaries both stop at the outer queue and emit sound but incomplete partial
labels; the controlled runs had 3,167 and 3,325 missing gold pairs respectively, with
zero extras in both. Instrumented Konclude completes the corresponding 9724 saturation
work in 9.84 seconds. This is a performance movement inside the already-open next target,
not a semantic disagreement or a regression of a previously exact ontology. Stage 3
must close the remaining implementation-efficiency gap rather than omit the required
successor items.

### Exact missing Konclude constructor port

`CTotallyPrecomputationThread.cpp:2057-2074` does not always reuse the ordinary
`(filler, polarity)` item. It calls `hasRoleRanges`; when true it obtains a separate item
keyed by `(role, filler, polarity)` through
`CTotallyOntologyPrecomputationItem::getSaturationRoleSuccessorConceptDataItem`, stores
that item in the restriction's `mExistentialSuccessorSatConRefLinking`, and constructs
its node with `initRole=role`. `createSuccessorForConcept` reads this
existential-specific reference before its ordinary filler fallback.

KM's seed builder explicitly omitted these role-range successor items under an obsolete
assumption that domains and ranges remained only normalized clauses. The final port:

1. reproduces `hasRoleRanges` over the range side of every signed indirect super role;
2. interns a separate seed by `(role, concept, polarity)` only when that predicate is
   true;
3. wires it into the restriction's existential-successor reference;
4. uses the same role-aware item during saturation dependency analysis; and
5. initializes the ontology-side and process-side item with its role, causing node
   initialization to load the role ranges.

The ordinary seed path is unchanged when `hasRoleRanges` is false. No ontology, class,
or role identifier appears in the implementation.

With this port, KM reports 422 residue subjects, closely matching Konclude's 423
insufficient nodes, and completion plus the KPSet barrier finishes all 422 without a
defer. The final signature is gold-exact.

### 7914 — SRIQ, 68k clauses. Konclude 2.7 s; KM 28 min / 25 GB timeout.

Divergence isolated to subject 13031 (UBERON_0009732). KM's completion path:
`apply_or_rule` -> `add_concept_to_individual` inserts concept 5229 -> spawns choice
43541 -> existential 134066 -> root fan-out; nodes proliferate (5005+ at 1M iters);
probe budget hit; defer.

Root cause: KM's OR pipeline branches EAGERLY where Konclude delays and then resolves
deterministically. Verified KM gaps (source spot-checked this session):

- `plan_or_processing` is a STUB returning `false` (`completion/u03.rs:1093`). The whole
  `planORProcessing` operand scan (completion cpp 16545-16724) is unported.
- `initialize_or_processing` (`completion/u03.rs:693`) DEVIATES: it branches eagerly
  in-process plus an invented lazy-OR heuristic (`KM_HT_NO_LAZY_OR`) instead of
  Konclude's priority-gated delay (completion cpp 16448-16482).
- The planned restriction spec is dropped: `apply_or_rule` (`completion/u09.rs:627`)
  passes `INVALID` into `execute_or_branching` (see u09.rs:731-767).
- `has_saturated_clashed_flag` is stubbed `false` in `execute_or_branching`
  (`completion/u09.rs:458`); the real predicate is already ported at
  `completion/u22.rs:794` (`has_saturated_clashed_flag_for_concept`).
- Satisfiable-cache disjunction absorption is W3-DEFER: the gate exists at
  `completion/u09.rs:754-756` but the body is missing. Konclude parks disjunctions on
  `PRFSATISFIABLECACHED | PRFCOMPLETIONGRAPHCACHED` nodes (applyORRule cpp 17100-17102,
  `addSatisfiableCachedAbsorbedDisjunctionConcept` cpp 6340, default-on cpp 188) and
  absorbs the generating existential the same way (applySOMERule cpp 14390-14394, cpp
  190); it reapplies on flag clear (cpp 4968-4972, 6294).

### 9663 — SRIQ, 302k clauses. Konclude 8.2 s; KM 115 GB / 25 GB blowups.

Saturation memory. Konclude bounds it structurally:
- one node per (concept, polarity) + (role, filler), pre-built
  (`CTotallyPrecomputationThread.cpp:2022-2115`); `createSuccessorForConcept` is a lookup,
  never an allocation (saturation cpp 7060-7144).
- once-per-concept firing (`CReapplyConceptSaturationLabelSet::insertConceptReturnClashed`
  cpp 246-281; no label rescans).
- lazy per-creation-role forall-extension + signature-trie resolve (saturation cpp
  999-1052, 2515-2593) so forall-operands never pollute shared fillers.
- task arenas + `INDSATFLAGINSUFFICIENT` fallback instead of completing hard nodes.

KM's `KM_HT_SAT_EXT` extension maps are `HashMap` (nondeterministic iteration, run-to-run
variance) and unbounded; there is no RSS fail-fast.

### 9724 — SHIF / GALEN, pure Horn. Konclude 5 s; KM card_insuff = 98M.

Cardinality + inverse. Konclude decides cardinality from pseudo-model BOUNDS
(`CClassificationClassPseudoModelRoleData` `mLowerAtLeast` / `mUpperAtMost`, `.cpp:90-102`),
never successor counting; uses delayed ATMOST merging above cardinality 100 (saturation

reversed-edge materialization (saturation cpp 6283-6306, 7196-7231, 7242-7258). Pure-Horn
should hit the global zero-test gate
(`isClassificationBySaturationCalculationSufficient`,
