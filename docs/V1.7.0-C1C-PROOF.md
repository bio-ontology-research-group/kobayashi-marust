# C1c proof: a certificate check for the fast SHIQ procedure

Stage C1c, step two (`docs/V1.7.0-C1C-FAST-SHIQ-DESIGN.md`, "Proof plan
after the prototype"). Branch `v170/c1c-proof`. Scratch and raw results:
`/mnt/data1/leechuck/km-work/v170/scratch/c1c/proof/`.

## 1. What is proved

Files (all in `ContextCalculus`, registered in `ContextCalculus.lean`):

- `SRIQ/FastDefs.lean`: candidate sets (`Cand`: context keys, nodes, the
  node indices of each context, the root context of each requested name),
  the indexes of the ontology (`mkIx`), the closure conditions R1 to R6
  (`ClosedP`, executable as `closedB := decide ClosedP`), the elimination
  (`aliveArr`, an exact depth-first support search `dfs`), the readout
  (`fastRows`) and the checked route `fastClassify`.
- `SRIQ/FastBasic.lean`: the indexes mean what they say; `br_guided`;
  `dfs_sound`, `dfs_complete`.
- `SRIQ/FastSound.lean`: soundness for every candidate set.
- `SRIQ/FastComplete.lean`: completeness under `ClosedP`.
- `SRIQ/FastCheck.lean`: `fastClassify_spec`, `fastClassifyGen_spec`.
- `OWLFrontend/SRIQFastRoute.lean`: the OWL route `owlSHIQFast gen`
  (translate, `isSHIQB`, `encTransQ`, generator, `closedB`) and
  `owlSHIQFast_sound`.

Main statements (all depend on `[propext, Classical.choice, Quot.sound]`
only):

```lean
-- every candidate set U, no check
theorem fastRows_sound (hA : IsALCHIQ O) (hp : p ∈ fastRows (mkIx O) U req) :
    p.1 ∈ req ∧ ∀ L, p.2 = some L →
      (∀ b, EntailsSub O p.1 b → b ∈ L) ∧ ¬ (p.1 is unsatisfiable)

-- under the closure conditions
theorem fastRows_complete (hC : ClosedP (mkIx O) U req) (hp : p ∈ fastRows (mkIx O) U req) :
    (p.2 = none → p.1 is unsatisfiable) ∧ ∀ L, p.2 = some L → ∀ b ∈ L, EntailsSub O p.1 b

theorem fastClassify_spec (hA : IsALCHIQ O) (h : fastClassify O req U = some rows) :
    (∀ a ∈ req, ∃ p ∈ rows, p.1 = a) ∧
    ∀ p ∈ rows, p.1 ∈ req ∧ (p.2 = none ↔ p.1 is unsatisfiable) ∧
      ∀ L, p.2 = some L → ∀ b, b ∈ L ↔ EntailsSub O p.1 b

theorem owlSHIQFast_sound (gen) (h : owlSHIQFast gen O requested = some a) :
    a.named = requested.eraseDups ∧
      ∀ i j (hi) (hj), (a.bit i j = true ↔ OWL.EntailsSub O a.named[i] a.named[j])
```

`fastClassify` returns `none` (declines) when `closedB` rejects `U`. No
statement mentions the generator.

## 2. The closure conditions

Notation as in the prototype report, section 2. `κ = (K, L, π)` is the
key of node `ν`'s context, `t` its type, `P` its pool; `pc(R, b)` is
`R ∈ L ∧ b ∈ π`; `ctx(t, σ) = (σ.B ∪ fwd t σ.Lc, flip σ.Lc, t ∩ Rel(flip σ.Lc))`
with the full `Rel` (fillers of every lower clause with number at least 1
and of every upper clause, by role). `Cov(k, s)`: every set computed by
`br s` (branches with one head name per fired gci) contains the type of a
node of context `k` that contains `s`. "Variant" below always means
`Cov(context of ν, t ∪ X)`.

- Checks of each node and entry: the type is closed and holds the seed;
  each pool entry's child context has key `ctx(t, σ)`; each label is
  closed under one-step super-roles. (The elimination also checks these,
  so soundness does not depend on them.)
- R1: the root context of each requested `a` (given in request order) has
  key `({a}, ∅, ∅)` and `Cov(k, {a})`.
- R2: every context `k` has `Cov(k, K_k)`.
- R3: for every lower clause `q = (a, k, R, b)` with `a ∈ t`, `k ≥ 1` and
  not (`k = 1 ∧ pc(R, b)`): `(upS R, {b}) ∈ P`.
- R4: if every need (`pc` below `k`) has a candidate entry, with `F` the
  union over needs of the intersection of the candidates' back sets: if
  `F ⊄ t`, the variant `t ∪ F`; otherwise the variant `t ∪ X` for every
  candidate back set `X ⊄ t`.
- R5: for every upper clause `u = (a, n, S, e)` with `a ∈ t` and
  `pot(u) > n` (the prototype's trigger): if `n = 1` and the definitely
  counted default specs `D` of `C(u)` are not empty, with `M = ⋃ D`:
  `σ ∪ M ∈ P` for every `σ ∈ C(u)`, and `σ₁ ∪ σ₂ ∈ P` for all
  `σ₁, σ₂ ∈ C(u)` that contain `M`; otherwise `σ₁ ∪ σ₂ ∈ P` for all
  `σ₁, σ₂ ∈ C(u)`.
- R6 (at the parent `ν`): for every entry `(σν, k) ∈ P`, every node `c` of
  `k`, every upper clause `u` at `c` with `pc_c(u)` and `pot_c(u) > n`,
  and every `σ ∈ C_c(u)`: if `σ.B ⊆ t`, the grown entry
  `(σν.Lc ∪ flip σ.Lc, σν.B) ∈ P`; otherwise the variant `t ∪ σ.B`.

## 3. The completeness argument

Fix a model. A node simulates `(z, py)` when its type lies below the
type of `z` and its label and projection lie below the label to `py` and
the type of `py`. A simulating node is *type-maximal* when no simulating
node of its context has a strictly larger type; one exists in every
context with a simulating node (finitely many nodes). Every variant
condition instantiated by the model asks for a node of the same context
with a larger type below the model type, so at a type-maximal node it is
already met (`no_variant`); R3, R5 and the first half of R6 act on the
node's own pool.

The kept set `SS`: type-maximal simulating nodes that also meet `PG` (a
spec that may count for an upper clause counted by the parent entry, and
that is valid for the parent element, serves only demands the parent
entry meets). Roots meet `PG` trivially. `SS` supports itself
(`ss_supp`), so it lies in the live set (`subset_al`):

- A *configuration* of `ν` is a finite set of pairs (model neighbour `w`,
  pool entry) whose spec is valid for `w` and maximal among the valid
  specs of the pool, covering every lower clause with as many distinct
  elements as its number (the parent element counts when `pc`). One
  exists by R3 and the model's witnesses (`cfg_exists`); take one of
  least size (`cfg_min`).
- Each pair's child is a type-maximal simulating node of its context
  (R2). It meets `PG` (`child_pg`): an R6 pattern there gives, by R6 at
  `ν` and type-maximality, the grown entry in `P`, which is valid and
  above the pair's maximal spec, so equal to it.
- Back sets: every pair is needed for some lower clause (least size), and
  R4 at the type-maximal `ν` puts every candidate back set into `t`.
- Lower bounds: the covering.
- Upper bounds (`StarData.upper`): if an at-most clause were exceeded,
  the count is below `pot` (each counting pair is the only pair at its
  element for a needed clause that counts toward `pot`), so R5 applies;
  in the model the clause holds, so two counting pairs share an element
  (R5 gives a merged valid spec, a smaller configuration) or a counting
  pair sits at the parent element while the parent entry counts (`PG`
  lets the parent entry serve its demands, a smaller configuration).

## 4. Changes to the plan and to the generator

- Plan step 4 ("a finite chain of model-guided variants reaches a stable
  node") is replaced by choosing a type-maximal node: variants only ever
  enlarge the type in the same context; pool changes happen inside the
  node. Pool inheritance is not needed.
- "Stable `ν` shows no R6 pattern" needs the child's context to come from
  a maximal valid spec of `ν`, and the star must be built from such specs;
  the "block" star of the plan is replaced by a least configuration.
- **Incompleteness found in v8, R5 at-most-1 rule.** It merged only
  default specs, so a merged spec never met a default of another
  functional role. `lean/testdata/sriq-fast/funcmerge-cx.sriq`:
  `A ⊑ ∃R1.B1 ⊓ ∃R2.B2 ⊓ ∃R3.B3`, `R1, R2 ⊑ S`, `R2, R3 ⊑ T`,
  `A ⊑ ≤1 S.⊤`, `A ⊑ ≤1 T.⊤`: v8 answers `A` unsatisfiable, the brute
  force and `KM_SRIQF_FUNCMERGE=0` answer satisfiable. Repaired by the R5
  rule of section 2 (generator flag `checkedMerge`, default on).
- R6 in the at-most-1 case asked only for the merged specs; it now asks
  for every spec of `C(u)`, as the pairwise case did (proof obstacle, not
  shown to lose answers).
- The narrow `Rel` (lower fillers only under a role with an upper role
  above it) blocks the drop step of the upper bound: a pair at the parent
  element may count for an upper clause through another demand. The
  check uses the full `Rel`; the generator default is now
  `KM_SRIQF_FULLREL=1` (proof obstacle, not shown to lose answers; the
  prototype report measured no effect on the 16 inputs).
- R7 (lazy definers) is off (`KM_SRIQF_LAZY=0` is now the default), as
  planned.
