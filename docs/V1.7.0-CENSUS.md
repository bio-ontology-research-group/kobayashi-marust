## Method and limits

Each file is read in 16 MB blocks as text, never parsed into an object model. Per block: (1) string literals are replaced by an empty string, with a carry-over if a literal runs across the block end; (2) full IRIs are shortened and datatype IRIs from the XSD, RDF, RDFS and OWL namespaces are normalised using the file's own `Prefix(...)` lines; (3) every `AnnotationAssertion`, `SubAnnotationPropertyOf`, `AnnotationPropertyDomain` and `AnnotationPropertyRange` axiom is deleted, and so are nested `Annotation(...)` terms, so annotation content never counts; (4) every `Name(` token is counted; (5) cardinality arguments (kind, qualified or not, number) and `ObjectPropertyChain` lengths are read with regular expressions.

Limits:

- The test is syntactic. It looks at construct names, not at what the axioms mean. For example, a `SubClassOf` that is really a domain axiom still counts only as `SubClassOf`.
- Class expressions are counted anywhere they appear, including inside axioms that are never used for reasoning. A single `ObjectUnionOf` puts an input outside EL.
- Qualified versus unqualified cardinality is decided by whether a class follows the property. A qualified cardinality over `owl:Thing` counts as qualified.
- "Transitivity chain" means a chain `R o R <= R` over a plain (non-inverse) role. Any other `ObjectPropertyChain` counts as a general chain.
- Simple-role conditions (SROIQ restricts which roles may appear in number restrictions and Self) are not checked. Regularity of the role hierarchy is not checked. A few inputs may be inside SROIQ syntactically but outside it semantically.
- Datatype use is any non-annotation literal or any Data* construct. A bare `Declaration(DataProperty(...))` does not count as datatype use (declared data properties are counted separately in the TSV).
- Annotation axioms in these files were removed by the corpus builders in many cases; the TSV column `annotation_axioms_skipped` shows how many the scanner dropped.
- Sanity check: lines that start with whitespace (which would break the one-axiom-per-line assumption for the annotation-axiom removal) are counted per input (`oddlines`); total across all inputs: 0.

### Fragment definitions (smallest that contains the input, tested in this order)

1. **EL** (rough): only `ObjectIntersectionOf`, `ObjectSomeValuesFrom`, class axioms (SubClassOf, EquivalentClasses, DisjointClasses), role hierarchy, transitive, domain, range, equivalent roles, and also general role chains and reflexive roles (EL++ style, since the certified EL stage covers those). No union, complement, universal, nominals, inverses, number restrictions, functional roles, symmetric, asymmetric, irreflexive or disjoint roles, Self or ABox assertions. Datatypes do not change the rung (they set the separate datatype flag).
2. **ALC**: the four Boolean constructors plus existential and universal restrictions, with no role axioms except domain and range (those are plain GCIs). No inverses, no cardinalities.
3. **SHI**: ALC plus inverse roles, role hierarchy, transitive, symmetric, equivalent and inverse roles, domain, range, and transitivity-style chains (R o R <= R). No cardinalities.
4. **SHIQ**: SHI plus qualified or unqualified number restrictions and functional or inverse-functional roles. TBox and RBox only.
5. **SHIQ+ABox**: SHIQ plus ClassAssertion, ObjectPropertyAssertion or NegativeObjectPropertyAssertion (no `SameIndividual`/`DifferentIndividuals`).
6. **SHOIQ**: adds `ObjectOneOf`, `ObjectHasValue`, `SameIndividual`, `DifferentIndividuals` (I read "individual axioms" as these two).
7. **SROIQ**: adds general chains, `ObjectHasSelf`, disjoint, reflexive, irreflexive or asymmetric roles.

Datatype use is a separate flag (the "with datatypes" column), not a rung of the ladder. Keys and rules are also flags. `tbox_fragment` in the TSV is the rung ignoring ABox assertions, datatypes, keys and rules.
