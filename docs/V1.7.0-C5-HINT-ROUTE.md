# v1.7.0 stage C5: the hint-only route

Branch `v170/c5-hint-route`. Plan: `docs/V1.7.0-PLAN.md`, sections 17 and 18.

## 1. Idea

`realisation_sound` (`SRIQN/Forest.lean`) holds for every core: a
realisation that passes the proved check gives a model. The C2a condition
of `sroiq-c2a` is needed only for the completeness of the reference search.
A km negative row (a non-subsumption, a non-type, consistency) needs only a
model, so the route `--procedure sroiq-hint` checks a hint on every input
the translations of `sroiq-c2a` handle, without the C2a check, and answers
only when the hint checks.

## 2. Lean

* `SRIQN/HintCheck.lean`. `Proc.hintDNS` is the object-part hint check of
  stage C3e (`checkRedN`, one data-star test per type of the hint) as a
  procedure of its own; `hintDNS_sound`: a hint that checks gives a data
  model, under a bounded oracle, for every SHIQ(D) base part, no C2a.
  `Proc.hintDNSL` adds `loopOKH`: every core element with a loop
  (`lab B B` nonempty) carries a nominal name. `hintDNSL_sound`: for an
  ALCHIQ ontology (no transitive role) such a hint gives a model whose loops
  sit at nominal elements (`ConsistentDL`), which the Self encoding needs
  (`encSelf_down`); the forest of a realisation has loops only at core
  elements (`forestN_loop`), and the transitivity encoding changes no role
  of an ALCHIQ ontology (`downI_rt_of_alchi`). `hintPartsN_sound`,
  `hintPartsNL_sound`: the same over the parts of a cell theory.
* `OWLFrontend/HintRoute.lean`. The three cores of `sroiq-c2a` without C2a:
  the chain route (`owlChainHint`, checks `sroiqHOK`: regularity, chain
  elimination, data ranges), the Self route (`owlSelfHint`, checks
  `sroiqSHOK`: also the simple-role and loop-role conditions), the route
  with `ObjectHasSelf` (`owlHSHint`). `hintCore` takes the `ObjectHasSelf`
  route when the ontology uses it, otherwise the chain route, and the Self
  route when the chain route declines. `hintP` unfolds datatype definitions,
  rewrites `DisjointUnion` and renames anonymous individuals, as
  `owlC3DConsistent` does.
* `OWLFrontend/HintBatch.lean`. Batch forms with every table computed once
  per ontology, proved equal to the per-hint route, and the rows.

### Theorems (every reading `pat` of `xsd:pattern`, every hint)

```
theorem owlHintConsistent_sound (pat : String → String → Prop) {O : Ontology} {hint : RawHint}
    (h : owlHintConsistent O hint = some true) : ConsistentAt (owl2MapP pat) O
theorem hintNonType_sound (pat) (h : hintNonType O C a hint = some true) :
    ¬ EntailsAt (owl2MapP pat) O (.classAssertion (.cls C) (.named a))
theorem hintNonSame_sound (pat) (h : hintNonSame O a b hint = some true) :
    ¬ EntailsAt (owl2MapP pat) O (.sameIndividual [.named a, .named b])
theorem hintNonSub_sound (pat) (h : hintNonSub O A B hint = some true) :
    ¬ EntailsSubAt (owl2MapP pat) O A B
theorem hintNonDiff_sound (pat) (h : hintNonDiff O a b hint = some true) :
    ¬ EntailsAt (owl2MapP pat) O (.differentIndividuals [.named a, .named b])
theorem hintNonRole_sound (pat) (h : hintNonRole O r a b hint = some true) :
    ¬ EntailsAt (owl2MapP pat) O (.objectPropertyAssertion r (.named a) (.named b))
theorem hintNonNRole_sound (pat) (h : hintNonNRole O r a b hint = some true) :
    ¬ EntailsAt (owl2MapP pat) O (.negativeObjectPropertyAssertion r (.named a) (.named b))
theorem hintNonSubs_sound (pat) (h : hintNonSubs O A Bs hint = some true) :
    ∀ B ∈ Bs, ¬ EntailsSubAt (owl2MapP pat) O A B
theorem hintNonTypes_sound (pat) (h : hintNonTypes O a Cs hint = some true) :
    ∀ C ∈ Cs, ¬ EntailsAt (owl2MapP pat) O (.classAssertion (.cls C) (.named a))
theorem hintRowAns_sound (pat) (h : hintRowAns O r hint = some true) : r.Holds pat O
theorem hintPB_eq (O : Ontology) (hs : List RawHint) : hintPB O hs = hs.map (hintP O)
theorem hintRowsB_eq (O : Ontology) (r : HintRowSpec) (hs : List RawHint) :
    hintRowsB O r hs = hs.map (hintRowAns O r)
```

Each row is consistency of `O` with added axioms (`typeAxs`, `sameAxs`,
`subAxs`, `diffAxs`, `roleAxs`, `nroleAxs` of the earlier routes; the batch
rows `nonSubsAxs O A Bs`, a fresh individual in `A` and in the complement of
every `B`, and `nonTypesAxs a Cs`). A row checks that the extension has no
`HasKey`. Axioms: `#print axioms` gives `[propext, Classical.choice,
Quot.sound]` for every result above.

### Not claimed

* No completeness: a hint that does not check, or an input outside the
  route, says nothing. The answer is `some true` or no answer, never a
  negative answer.
* No positive rows (subsumption, type, inconsistency): those come from
  `kmSupervisor_sound` or from the complete route `sroiq-c2a` on C2a.
* A hint whose core children are checked by elimination (no `rec` table)
  is not accepted: the route runs only the local certificate check
  (`CertOK`). A hint without children needs no table.
* On the Self route (irreflexive properties, counted reflexive properties,
  `ObjectHasSelf`) a core element with a loop must carry a nominal name.

## 3. The hint format

No change to the text format of `RawHint.toHintN` (`SHOIQC2aReference.lean`).
Additions in meaning only:

* **Anonymous core elements.** `blocks K` declares core elements
  `0 .. K-1`. A core element whose `ty` lines list no nominal index is an
  anonymous shared element; `NomOK` asks only that each nominal index holds
  at exactly one core element. Example: `testdata/sroiq-hint/share.hint`,
  core 3.
* **Loops on the Self route**: `lab B B ...` only at a core element with a
  nominal index.

The indices are those of the ontology the hint is checked against:
`--procedure sroiq-hint --print-index [--row ROW]` prints them, for the
row's extended ontology when a row is given. The tables are those of
`sroiq-c2a --print-index` on every input where `sroiq-c2a` takes the chain
or `ObjectHasSelf` route; they differ where `sroiq-c2a` takes the at-most-zero
route (`sroiq-hint` never rewrites at-most-zero clauses) or takes the Self
route after the chain route fails C2a (`sroiq-hint` keeps the chain route).

### Index table changes

`--print-index` of `sroiq-c2a` prints the same lines as before (the four
branches moved into the functions `printIndexHS`, `printIndexSelf`,
`printIndexZero`, `printIndexChain`, unchanged). `sroiq-hint --print-index`
prints the chain, Self or `ObjectHasSelf` table of the core it uses (no
`zeros` line).

## 4. The command line

```
km-owl-reference --procedure sroiq-hint --hint FILE [--row ROW] <file.ofn>
km-owl-reference --procedure sroiq-hint --batch FILE|- <file.ofn>
km-owl-reference --procedure sroiq-hint --check|--print-index|--print-clauses [--row ROW] <file.ofn>
```

`ROW` is one argument: `consistent` (default), `nontype C a`, `nonsame a b`,
`nonsub A B`, `nondiff a b`, `nonrole r a b`, `nonnrole r a b`,
`nonsubs A B1 B2 ...`, `nontypes a C1 C2 ...`, with full IRIs; a property is
`IRI` or `^IRI` (its inverse). A certified row prints
`{"format":"owl-hint-v1","row":ROW,"certified":true}`, exit 0; otherwise the
reason goes to stderr, exit 3 (`hint: rejected ...` or the decline).

Batch file: pairs of a line `row ROW`, the hint lines, and a line `end`
(`#` comments). Output, one line per pair, in input order:
`{"format":"owl-hint-batch-v1","pair":I,"row":ROW,"result":"certified"|"rejected"|"declined"}`.
Pairs with the same row share one translation of the extended ontology and
every table (chain and Self encodings, the transitivity encoding, the
object part, the data parts); each pair then costs `checkRedN` and the
data-star tests of its hint. Pairs with different rows have different
extended ontologies and are translated separately; with the batch rows
`nonsubs A B1 ... Bk` one hint per satisfiable class `A` refutes all its
non-subsumers.

`--print-clauses` prints the object clauses (`gci`, `some`, `all`,
`atleast`, `atmost`, `chain`) and nominal names the hint is checked against,
for writing hints by hand.

## 6. DL-safe rules (item 3)

* `OWL/Rules.lean`: atoms (`ClassAtom`, `ObjectPropertyAtom`,
  `DataPropertyAtom`, `DataRangeAtom`, `SameIndividualAtom`,
  `DifferentIndividualsAtom`, `BuiltInAtom`), rules, `OntologyR` (an
  ontology and its rules; `Axiom` is unchanged, so no existing statement
  changes), the DL-safe semantics (`DLRule.sat`: individual variables over
  the named individuals of the ontology and its rules, data variables over
  all data values, built-ins read by a parameter `bi`), `ModelR`, and the
  parser `parseR` (`OWL.parse` still rejects rules). Every theorem holds for
  every reading `bi` of the built-ins.
* `OWLFrontend/RuleGround.lean`: grounding over the named individuals. Each
  instance becomes one OWL axiom read at a fresh individual `h0` through a
  fresh object property `u` with `u(h0, b)` asserted for every named `b`:
  body atoms `∃u.({b} ⊓ C)`, head atoms `∀u.(¬{b} ⊔ C)`.

```
theorem consistentAtR_encRules [Nonempty DM.Val] (bi : BuiltIns DM) {O : OntologyR}
    {O' : Ontology} (h : encRules O = some O') : ConsistentAtR DM bi O ↔ ConsistentAt DM O'
theorem owlRulesC2a_sound (pat) (bi : BuiltIns (owl2MapP pat)) (h : owlRulesC2a O hint = some v) :
    v = true ↔ ConsistentAtR (owl2MapP pat) bi O
theorem owlRulesHint_sound (pat) (bi) (h : owlRulesHint O hint = some true) :
    ConsistentAtR (owl2MapP pat) bi O
```

`encRules` declines: `HasKey`, more than 200,000 instances (named
individuals to the power of the variables of a rule, summed), and instances
with a data variable, a data range atom, a built-in atom or an anonymous
individual. A rule with a variable has no instance when there is no named
individual, so it is dropped whatever its atoms.

Both routes take rules: `sroiq-c2a` decides consistency of the encoding
(the complete route, exact), `sroiq-hint` checks a hint against the
encoding (`--print-index`, `--print-clauses` and `--check` work on it; the
fresh individual is a `nominal` line and the property `u` a `role` line of
the index). Rows over ontologies with rules are not done (declined).

Pool (13 inputs with rules): the hint route accepts 3 (ore_ont_15993, no
named individual; 16630; 2526), the C2a route 2 (16630, 2526; 15993 is not
C2a). The other 10 have built-ins or data variables in their instances, or
too many instances (up to 14 variables per rule; ore_ont_15063 and 7345 have
thousands of individuals). An encoding without grounding (guarded clauses
over nominal names) is open.

## 7. `HasKey` (item 4)

`OWLFrontend/KeyRules.lean`. A key without data properties is a DL-safe
rule (`keyRule`: `C(x) ∧ C(y) ∧ ri(x, zi) ∧ ri(y, zi) → x = y`, all variables
over named individuals, as the `ISNAMED` conditions of the direct semantics
ask):

```
theorem sat_hasKey_iff [Nonempty DM.Val] (bi) (I) (N) (c) (rs) :
    I.sat N (.hasKey c rs []) ↔ (keyRule c rs).sat bi I N
theorem modelR_keyOff [Nonempty DM.Val] (bi) (h : keyOff R = some R') (I) :
    ModelR bi R I ↔ ModelR bi R' I
theorem owlKeysC2a_sound (pat) (bi) (h : owlKeysC2a R hint = some v) :
    v = true ↔ ConsistentAtR (owl2MapP pat) bi R
theorem owlKeysHint_sound (pat) (bi) (h : owlKeysHint R hint = some true) :
    ConsistentAtR (owl2MapP pat) bi R
theorem consistentAtR_nil (bi) (O) : ConsistentAtR DM bi ⟨O, []⟩ ↔ ConsistentAt DM O
```

`keyOff` moves the keys into the rules, and the grounding of section 6 then
removes them, so every later layer sees an ontology without `HasKey`. That
lifts the `noKey` restriction of the routes for consistency: anonymous
individuals in assertions are allowed together with keys (they are not
named, so no key or rule instance reaches them, and the renaming of
`SROIQAnon.lean` runs on the encoded, key-free ontology), and datatype
definitions with keys likewise. Where it is not lifted: keys with data
properties (the shared value is a data variable; declined), rows (negative
rows over an ontology with keys or rules are declined), and the size bound
of the grounding (named individuals to the power `2 + m` for a key over `m`
properties). An ontology without keys keeps its earlier translation and
indices (`rulesOntoK` moves keys only when there are some). No pool input
has `HasKey`.

## 8. Asymmetric and disjoint properties (item 5)

`OWLFrontend/EdgeStrengthen.lean`, hint route only. A hint needs only the
soundness direction, so `edgeOff` replaces each axiom by a stronger one the
route already handles: `AsymmetricObjectProperty(r)` by
`∃r.⊤ ⊓ ∃r⁻.⊤ ⊑ ⊥`, `DisjointObjectProperties(r1 ... rn)` by
`∃ri.⊤ ⊓ ∃rj.⊤ ⊑ ⊥` (`i < j`), `DisjointDataProperties(p1 ... pn)` by
`∃pi ⊓ ∃pj ⊑ ⊥`.

```
theorem model_of_edgeOff {O : Ontology} {I : Interp DM Dom} (h : OWL.Model (edgeOff O) I) : OWL.Model O I
theorem holds_of_models (pat) (hm : ∀ Dom I, OWL.Model O' I → OWL.Model O I) (h : r.Holds pat O') : r.Holds pat O
theorem hintRowAnsE_sound (pat) (h : hintRowAnsE O r hint = some true) : r.Holds pat O
```

`sroiq-hint` checks hints (all rows, batch, `--print-index`) against
`edgeOff O` when `O` has such an axiom. This is the cheapest sound check
and it is far from complete: the strengthening forbids, for an asymmetric
`r`, every element with both an `r`-successor and an `r`-predecessor (an
asymmetric chain `a → b → c` has no model of `edgeOff`). The exact check
needs edge-label conditions on the realisation and a forest built from the
certificate's own supports (the forest of `SRIQN/Forest.lean` picks
supports by choice, so labels of core entries are not controlled), carried
through chain elimination, the Self encoding and the translation for simple
roles; that, the complete route for these axioms and the `xsd:dateTime`
facet range of ore_ont_13077 stay open.

Pool: the 12 inputs declined by `sroiq-c2a` for `AsymmetricObjectProperty`,
`DisjointObjectProperties` or `DisjointDataProperties` pass the fragment
check of `sroiq-hint` (whether a hint exists for them depends on their
models having the strengthened shape).

### 10.1 Check speed (R1, R2, R7, sparse cores)

`SRIQN/HintFast.lean`. The route checks a sparse hint `HF.HintS` (the core
types as an array, the `lab` lines as a list of edges, the `kid` lines as a
list, the certificate rows with their core entries as lists) through the
clauses indexed once per ontology (`HF.mkSIx`: gcis by their first body
name, universals and counting clauses by their left name, one-step role
inclusions by role). No decision enumerates names, labels, records or the
`K × K` core pairs: each core element's neighbours come from its edge list,
sorted by core element and merged.

```
theorem starF_iff (t) (N) : starF (mkSIx O) t N = true ↔ StarOK O t N
theorem checkRedS_eq (h : HintS n m) (A ok N) : checkRedS h A ok N = Proc.checkRedN A ok N h.toN
theorem hintPartsS_eq (O cells size sp E) (h) : hintPartsS O cells size sp E h = hintPartsN O cells size sp E h.toN
theorem hintPartsNLS_eq (O cells size sp E) (h) : hintPartsNLS O cells size sp E h = hintPartsNL O cells size sp E h.toN
theorem toHintS_map (h : RawHint) (n m) : (h.toHintS n m).map HF.HintS.toN = h.toHintN n m
theorem dataSatB_dataOnly (O card) : SRIQD.Proc.dataSatB (dataOnly O) card = SRIQD.Proc.dataSatB O card
```

`HintS.toN` is the dense hint the sparse one denotes (an absent pair has
the empty label), so the sparse check is the dense check on the denoted
core. The hint parser builds its lists in file order with one step per
line (it was quadratic in the number of lines).

### 10.2 Input handling (R8, R9, R13) and rejection reasons

* `--row-file FILE`: the row from a file, words separated by blanks or
  newlines (no argument length limit).
* Batch files: a word that starts with `#` starts a comment; a `#` inside a
  word (an IRI) is kept. Earlier batch files keep their meaning unless a
  comment was glued to a word.
* `--explain`: on a rejection, `hint: reason: ...` on stderr names the first
  failing core element, edge, kid or certificate record and the condition
  (`gci B -> H`, `all a R c`, `atleast a k R b`, `atmost a k R b`, a missing
  super-role, a nominal index at no or at several core elements, a loop
  without a nominal index on the Self route, a record missing from the
  table, a counted core entry). In batch output a rejected pair gets a
  `"reason"` field. Without `--explain` the output is unchanged. The reasons
  are a diagnostic (`SRIQN/HintExplain.lean`), not part of any proved
  statement.

### 10.3 Data (R6, R11)

Text format addition:

```
part I G N      -- the hint names its data part: count N of group G in split cell I (repeatable)
part            -- names the part with no counts (no split cell)
```

A hint with `part` lines is checked on that part only: the counts must form
a part (one list per split cell, `allG` many groups, summing to the cell
size; `HF.validPartB`, `mem_of_validPartB`), and the data-star test runs
with that part's cardinalities. A hint without `part` lines is checked on
every part as before. `HF.hintPartsP_imp` reduces the check to
`hintPartsN` on the denoted hint, so `sroiqHParts_sound`,
`owlHintConsistent_sound` and every row theorem keep their statements.

`--print-clauses` adds, after `data-clauses N`: the data clauses
(`dsome a u pos / neg`, `dall a u l1 ~l2`, `datleast a k u pos / neg`,
`datmost a k u pos / neg`, `dsub u v`), `atom J RANGE`, `free I IRI`,
`groups G`, `group I BITS` (up to 4,096 groups) and `cell I SIZE CELL` for
the split cells a `part` line refers to.

Open here: the data-star test of a type that uses data clauses still
enumerates the candidate data neighbours (`dcands`, exponential in the data
properties and atoms); a hint that gives the data star per element is the
next step.

### 10.4 The global witness row (main result)

`SRIQN/HintModel.lean`, `OWLFrontend/HintWitness.lean`.

One hint for the base ontology (no row axioms) certifies every non-entailment
read off the types of its core elements. The route translates the ontology
with the requested classes `req` given to the translation (default: every
class of the ontology), so their indices come first; `--witness-route` with
`--print-index` or `--print-clauses` prints that translation.

```
def wTab (O : Ontology) (req : List IRI) (hint : RawHint) : Option WTab

theorem hintWitness_sound (pat : String → String → Prop) {O : Ontology} {req : List IRI}
    {hint : RawHint} {W : WTab} (hw : wTab O req hint = some W) :
    ConsistentAt (owl2MapP pat) O ∧
    (∀ (A B : IRI) (iA iB : Fin W.N) (w : Fin W.k), (A, iA) ∈ W.cls → (B, iB) ∈ W.cls →
      iA ∈ W.ty w → iB ∉ W.ty w → ¬ EntailsSubAt (owl2MapP pat) O A B) ∧
    (∀ (a C : IRI) (ia iC : Fin W.N) (w : Fin W.k), (a, ia) ∈ W.inds → (C, iC) ∈ W.cls →
      ia ∈ W.ty w → iC ∉ W.ty w →
      ¬ EntailsAt (owl2MapP pat) O (.classAssertion (.cls C) (.named a))) ∧
    (∀ (a b : IRI) (ia ib : Fin W.N) (w v : Fin W.k), (a, ia) ∈ W.inds → (b, ib) ∈ W.inds →
      ia ∈ W.ty w → ib ∈ W.ty v → w ≠ v →
      ¬ EntailsAt (owl2MapP pat) O (.sameIndividual [.named a, .named b]))
```

`W.ty` are the core types of the hint, `W.cls` the requested classes with
their concept index and `W.inds` the named individuals of `O` with the
index of their nominal class; each index is validated against the
translation's name table. The lemmas behind it: `forest_of_check` (the
forest of an accepted hint, with an injective map of the core into its
domain and `F.c a (f b) ↔ a ∈ ty b`), `hintPartsP_model` (the same through
the data reduction and the transitivity encoding), `chainDown` (chain
elimination keeps the concepts), `downW` (the translation keeps the
requested classes and the named individuals: a core element is in a
requested class exactly when the class's index is in its type, and it is
the individual `a` exactly when `a`'s nominal index is in its type), then
`model_roleOff`, the renaming of anonymous individuals (named individuals
are fixed), `model_duOff` and `model_of_edgeOff`.

What it certifies: consistency; `O ⊭ A ⊑ B` for a requested `A` with a
core witness and every requested `B` outside the witness's type (owl:Nothing
included when requested, which certifies satisfiability); `O ⊭ C(a)` for
every requested `C` outside the type of `a`'s core element; `O ⊭
SameIndividual(a b)` for individuals on different core elements.

What it does not certify: role assertions (an edge of the model between
two core elements can come from a chain or a transitive role through tree
nodes, so a missing label refutes nothing; open), `DifferentIndividuals`
rows, witnesses that are tree records (only core elements, anonymous ones
allowed, are witnesses; a flat hint makes every tree node a core element).
Scope: the chain route (no `ObjectHasSelf`, no irreflexive property and no
counting over a reflexive property, which take the Self routes), no
`HasKey` after the preparation, no datatype definitions. Outside the scope
or when the hint does not check, the command prints the decline and exits 3.

Command line:

```
km-owl-reference --procedure sroiq-hint --witness TABLE --hint FILE [--out FILE] [--classes FILE] [--explain] <file.ofn>
km-owl-reference --procedure sroiq-hint --witness-route [--classes FILE] --print-index|--print-clauses <file.ofn>
```

`TABLE`: lines `witness CLASS W` (`W` a core element; `ind a W` lines are
accepted and ignored: the element of an individual is read off the hint).
The table is not trusted: an entry whose class is not in the type of `W`
is reported with an `"error"` and certifies nothing. `--classes FILE`: the
requested classes (words), default every class of the ontology; repeated
names are dropped. Output (stdout or `--out`), one JSON object per line:

```
{"format":"owl-witness-v1","consistent":true,"classes":N,"individuals":M,"core":K}
{"class":A,"witness":W,"nonsub":[B...]}            -- or "nonsub_except":[the requested classes in the type]
{"individual":a,"element":W,"nontype":[C...]}      -- or "nontype_except":[...]
{"nonsame_groups":[[a,b],[c],...]}                 -- individuals of different groups are certified different
{"counts":{"nonsub":X,"nontype":Y,"table_errors":Z,"element_groups":G}}
```

The complement form is printed when it is shorter. Cost: one translation,
one check, then one pass per table entry over the witness's type. On the
synthetic input of 10.1 with all 5,000 classes requested (4,923 with a
witness): 3.7 s, 150 MB, 24.6 million non-subsumptions and 99.9 million
non-types certified.

Tests (`lean/testdata/sroiq-witness/expected.tsv`; `tools/hints/h2/cover.py`
checks that certified non-subsumptions plus km's subsumptions cover every
ordered pair of distinct classes, and the same for types):

| Input | What it shows | km subsumptions | certified | uncovered |
|---|---|---:|---:|---:|
| `chain.ofn` | anonymous witnesses (an r-successor of `d`, isolated B and C elements) | 3 | 9 | 0 |
| `share.ofn` | nominals, an inverse functional role, one anonymous B witness shared by `a` and `b` | 0 | 6 | 0 |
| `data.ofn` | a functional data property with a value; `data-part.hint` names its part | 2 | 4 | 0 |

Rejections: `data-bad.hint` (a class without its data existential;
`--explain` names the gci), `data-part-bad.hint` (counts that do not add up
to the cell size).

## 11. Stage H2 follow-up (2026-11-15/16)

### 11.0 Built-in class IRIs in requested positions

`EntailsSubAt DM O A B` and the row axioms read a class IRI as `I.cls A`, a
free predicate, while the parser reads `owl:Thing` as `ClassExpr.thing` and
`owl:Nothing` as `ClassExpr.nothing`. `OWLFrontend/HintBuiltin.lean` states
the rows for the parser's class expression `clsOf s` and derives them from
the IRI-level theorems, which stay unchanged:

```
def clsOf (s : IRI) : ClassExpr   -- owl:Thing ↦ .thing, owl:Nothing ↦ .nothing, else .cls s
def EntailsSubCE (DM) (O) (C D : ClassExpr) : Prop
theorem hintNonSubC_sound (pat) (h : hintNonSub O A B hint = some true) (hA : A ≠ owlNothing)
    (hB : B ≠ owlThing) : ¬ EntailsSubCE (owl2MapP pat) O (clsOf A) (clsOf B)
theorem hintNonSubsC_sound … : ∀ B ∈ Bs, B ≠ owlThing → ¬ EntailsSubCE (owl2MapP pat) O (clsOf A) (clsOf B)
theorem hintNonTypeC_sound … (hC : C ≠ owlThing) : ¬ EntailsAt (owl2MapP pat) O (.classAssertion (clsOf C) (.named a))
theorem hintNonTypesC_sound …
theorem hintWitnessC_sound …   -- also A ⋢ owl:Nothing for a witness of A, owl:Thing ⋢ B when a core element lacks B
theorem not_entails_nothing_of_consistent, not_thing_sub_nothing_of_consistent
```

Audit of the places where a built-in IRI can arrive as a plain IRI: the
`sroiq-hint` rows (`--row`, `--row-file`, batch `row` lines), `--type C a` of
the `sriq-kb`, `sriqd-kb`, `shoiq-c2a` and `sroiq-c2a` routes, and the
`--classes` file and table of the witness row. Classification on every route
reads `O.classNames`, which never holds the two built-in IRIs. The cases
with a wrong meaning were `owl:Thing` as object of a subsumption or type and
`owl:Nothing` as subject of a subsumption; `owl:Nothing` as object (used by
the H1 driver, `nonsubs A owl:Nothing …`, for satisfiability) and
`owl:Thing` as subject were faithful. No earlier test expectation was
affected. The CLI refuses (exit 2) rows with `owl:Thing` as object,
`owl:Nothing` as subject, `owl:topObjectProperty` or
`owl:bottomObjectProperty` as row property, and `--type owl:Thing a`; the
witness route removes the two IRIs from the requested classes of the
translation and prints them with their OWL meaning. An unknown IRI in a
class position (such as `rdfs:Literal`) is a fresh class name and keeps its
literal meaning.

### 11.1 The witness row on every route

`OWLFrontend/HintWitnessS.lean`, `HintWitnessA.lean`, `SRIQN/HintModelS.lean`.

```
def wTabA (O : Ontology) (req : List IRI) (hint : RawHint) : Option WTab
def wTabR (R : OntologyR) (req : List IRI) (hint : RawHint) : Option WTab
theorem hintWitnessA_sound (pat) (hw : wTabA O req hint = some W) : ConsistentAt (owl2MapP pat) O ∧ …
theorem hintWitnessR_sound (pat) (bi) (hw : wTabR R req hint = some W) : ConsistentAtR (owl2MapP pat) bi R ∧ …
```

The rows are those of `hintWitnessC_sound` (and non-sameness). The route:
datatype definitions unfolded (`model_of_dtLoop`), the strengthening of
asymmetric and disjoint properties, disjoint unions, anonymous individuals
renamed, then the `ObjectHasSelf` route (on `hsOff`, `model_hsOff_down`),
the chain route, or the Self route (`wTabSCore_facts`: the forest with loops
at nominal elements, `encSelf_core`, `chainSelf_core`, the translation with
`req ++` the pair classes requested). `wTabR` adds keys (as rules) and
DL-safe rules (grounded; `modelR_of_encRules`). `--witness`,
`--witness-route --print-index|--print-clauses|--check` follow the same
route choice; `--check` prints `accepted chain` or `accepted self`. On an
input with rules the fresh individual of the grounding is not printed.

### 11.2 Data stars given per core element

Text format addition:

```
dstar B P1 ... / A1 ...   -- an entry of the data star of core element B: data properties, then the atoms of its value type
dstar B                   -- B's data star is given (with the entries of its dstar lines; none: empty)
```

The indices are those of `--print-clauses` (`dsome a u pos / neg`, `atom J
RANGE`). An element with a given star is checked on that star
(`starGivenB`: at most `dbnd` entries, each a possible entry, the star
conditions `DOK`), with no search over candidate data neighbours; the
value type of an entry lists every atom its value satisfies.
`dataSatB_of_starGivenB`, `okOf_imp`, `hintPartsP_imp`. On `datastar.ofn`
(twelve data existentials) the check takes 0.12 s with the stars and does
not finish in 60 s without.

### 11.3 More rows from the global model

```
theorem hintWitnessMore_sound (pat) (hw : wTabA O req hint = some W) :
  (A ⊓ B satisfiable: ¬ EntailsAt … (.disjointClasses [clsOf A, clsOf B]) when one core element holds both) ∧
  (¬ EntailsAt … (.differentIndividuals [.named a, .named b]) when a, b sit on one core element) ∧
  (¬ EntailsAt … (.objectPropertyAssertion r (.named a) (.named b)) when (r, R) ∈ W.props, a and b sit
     on different core elements w ≠ v, and R ∉ W.lab w v)
```

`W.props` are the named properties whose role term is simple in the normal
form (no chain or transitive role below it; checked with `selfSimpleB`).
For a simple role the model's edges between two core elements are exactly
the hint's label: the forest's core edges are the label, the transitivity
encoding changes no role after chain elimination, chain elimination keeps
simple roles (`downC_rt_simple`), and the Self encoding adds loops only.
Not covered: non-simple roles (a chain or a transitive role can build an
edge through tree nodes; the automaton product over the core and the
certificate records is open), role rows between individuals on one core
element, negative data property values (the model's data values are chosen
by the data reduction and are not read from the hint), rows over inputs
with rules other than the class and type rows of `hintWitnessR_sound`.

Witness output additions: `"sat_with"` on class rows (requested classes
sharing the witness: the conjunction is satisfiable; in the
`nonsub_except` form the excepted classes other than the class itself and
`owl:Thing` are these); `{"simple_properties":[[IRI, ROLE]…]}` and
`{"individual_edges":[[W, V, [IRI…]]…]}` (for ordered pairs of individual
elements with a nonempty label, the listed simple properties whose role is
in the label from `W` to `V`; for every other ordered pair of different
individual elements and listed property, the property assertion is
certified non-entailed); individuals in one `nonsame_groups` group are
certified not entailed different.

`--explain` also names an invalid named data part (a line outside the split
cells or groups, or counts that do not add up to a cell's size).

Tests: `lean/testdata/sroiq-witness/expected.tsv` (14 lines: chain, share,
data, built-ins, self with `ObjectHasSelf`, rules, data stars, roles), all
pass; coverage against km (`tools/hints/h2/cover.py`) on chain, share, data,
self: every ordered pair covered.
