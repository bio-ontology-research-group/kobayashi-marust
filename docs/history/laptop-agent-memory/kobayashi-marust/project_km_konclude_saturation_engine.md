2026-06-27. Studied Konclude's deterministic SATURATION engine from source (the part that builds the pseudo-model FAST on 58k-concept chain-heavy SRIQ) to fix KM's QO saturation, which CHURNS (re-fires lit_work millions of times over a stable ~80k-node model) and EXPLODES (9.7M nodes) when successors aren't shared. Two mechanisms make Konclude fast; KM lacks both at the QO level.

**1. Descriptor-driven rule firing (NO re-scan churn).** `CReapplyConceptSaturationLabelSet::insertConceptReturnClashed` (Kernel/Process/CReapplyConceptSaturationLabelSet.cpp:246-281): label set is a HASH keyed by concept tag (`CPROCESSHASH<cint64,CConceptSaturationDescriptorReapplyData>`), O(1) membership. A concept is processed AT MOST ONCE — insert checks `!conDesDepData.mConSatDes` (line 262); only newly-inserted concepts get appended to the process linker `mConceptSatDesLinker`. Re-firing of a rule happens ONLY via `CImplicationReapplyConceptSaturationDescriptor` (tracks which implications already fired for that concept) — never a full label re-scan. Main loop: `CCalculationTableauApproximationSaturationTaskHandleAlgorithm.cpp:323-349` drains the per-node concept linker; rules fire per newly-taken concept. THIS is what KM's QODRAIN lacks (KM re-propagates the whole literal set each pass = the lit_work churn). KM port = process queue of (node, newly-added concept); fire only the clauses that concept triggers (a per-concept trigger index), mark (node,concept) processed, never re-scan.

**2. Signature-keyed successor node CACHING (NO explosion).** `createSuccessorForConcept` (CCalculationTableauApproximationSaturationTaskHandleAlgorithm.cpp:6918-6990): an existential ∃R.C does NOT make a fresh successor — it looks up a CACHED singleton node keyed by the concept (3-level: (a) the ∃-concept's own ref linking `getExistentialSuccessorConceptSaturationReferenceLinkingData`, (b) operand concepts, (c) fallback ⊤-concept node). Registered once during job gen: `CSatisfiableCalculationTaskFromCalculationJobGenerator.cpp:120` `satConRefLink->setIndividualProcessNodeForConcept(indiNode)`. So a chain reuses ONE successor per concept signature ⇒ ~80 successors not millions. KM port = intern successor nodes by (filler concept / label signature); share across the model. KM's plain-QO path ALREADY shares enough to stay at 79561 nodes (doesn't explode); it's KM_HT_QO_SHIQ (non-shared, for the small-giant recognition) that explodes 9663 — so SHIQ must stay SCOPED to the small card route, never the chain-giant saturation.

**3. Lazy ∀-to-successor extension.** `CSaturationLinkedSuccessorIndividualALLConceptsExtensionData` (per-role hash CRole*→extension, single-role fast path) + `updateSuccessorRoleALLConceptsExtensions` (cpp:932-1000): adding ∀R.C pushes C to shared R-successors via reapply descriptors; `lastExaminedLinkLinker`/`lastExaminedALLConceptReapplyDescriptor` (lines 999-1000) ensure only NEW successors or NEW ∀-concepts propagate. No re-scan.

**4. Disjunctions PARKED (not branched)** in the deterministic saturation — recorded as possible-concepts (CSaturationDisjunctCommonConcept...), choice deferred to the consistency/residue phase. KM's saturate_global already parks.
