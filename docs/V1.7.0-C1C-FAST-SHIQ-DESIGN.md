# Stage C1c: a SHIQ procedure that finishes on real inputs (design)

Supervisor's design note, 2026-11-14. `classifyQ` (C1) eliminates over
every record on all names: 0 of 98 corpus inputs finish. This note
designs the demand-driven replacement. It is built in two steps: an
unproved prototype measured on the corpus, then the proof of the design
that the measurement confirms.

## 1. Certification shape

- `gen O req`: an unverified generator of a finite candidate set `U`.
- `closedB O req U : Bool`: a verified check that `U` is closed under the
  rules of section 3.
- Abstract theorem: if `U` is rule-closed then the answers read from
  `elim U` are exact (in the manner of `SRI/Abstract.lean`).
- `classifyQF O req`: if `closedB (gen O req)` then the answers from
  `elim`, else `classifyQ` (the proved slow procedure). Exact for every
  generator; fast when the generator is right. No worklist proof.

Soundness of non-subsumption needs nothing new: the alive part of any
candidate set is self-supporting, so its records are `Good`. The work is
the other direction: every model must be simulated inside `U`.

## 2. Simulation invariant

For a model `I`: a candidate node with type `t` simulates an element `x`
if `t ⊆ type x`; a candidate edge with label `L` to a candidate with
type `s` simulates `(x, z)` if `L ⊆ label x z` and `s ⊆ type z`.
Candidate types are branches (`SRI.Proc.branches`): for every closed
superset `T` of a seed there is a branch below `T` (`guided` lemmas).
Under the invariant:

- at-most is monotone: if candidate neighbours map injectively to model
  neighbours, the candidate count is at most the model's count;
- at-least and existentials hold if every model witness has its own
  candidate neighbour.

## 3. Rules (first version; the prototype may refine them)

Ontology in ALCHIQ form (after `encTransQ`). `up R` is the up-closure of
`R`; `fwd t L` and `back s L` are the universal propagations through a
label, in the two directions.

- **Demands** of a type `t`: `(R, b)` once per `exRight a R b` with
  `a ∈ t`, and `k` copies per `atLeast a k R b` with `a ∈ t` (the model
  has `k` distinct witnesses, so copies of one clause never merge with
  each other).
- **Child spec**: `(L, K)`, a label and a seed. The default spec of a
  demand `(R, b)` is `(up R, {b} ∪ fwd t (up R))`.
- **Node**: a type `t` (a branch of its seed and augmentation), its
  parent summary, and a list of child specs.
- **Root rule**: for every requested `a`, every branch of `{a}` with the
  default specs of its demands.
- **Child rule**: for every node and spec `(L, K)`, the nodes for every
  branch of `K`, with parent label `flipL L`.
- **Back rule** (as `augRecs` in SHI): if a child `s` of a node with
  type `t` has `back s L ⊄ t`, the parent gets a variant whose type is a
  branch of `t ∪ back s L`.
- **Parent-witness rule**: a child with demand `(R, b)` may be served by
  its parent: variant of the child whose parent label gains `up R`, with
  `b` added to the parent's augmentation (so the parent's type must
  contain `b`), and universals re-propagated through the larger label.
- **Merge rule (lazy)**: if a node's star violates an `atMost a n R b`
  that fires (more than `n` neighbours with `R` in the label and `b` in
  the type), then for every pair of counted neighbours that are not two
  copies of one at-least clause: a variant with the two merged (two
  children: label union, seed union; child and parent: the
  parent-witness variant). Completeness: in the model the count is at
  most `n`, so two counted candidates simulate one element; merging them
  keeps the invariant. Each merge removes a neighbour, so it terminates.
- **Elimination**: a node is supported if every spec has an alive child
  whose back-propagation the node's type contains, such that the
  resulting star satisfies `StarOK`. Remove unsupported nodes until
  stable.

Functional roles make the merge rule deterministic in practice: all
demands under a functional role fall into one child.

## 4. Sharing

A child's elimination status depends on its parent only through: the
seed `K`, the label, and which counting-relevant names the parent's type
contains (the fillers `b` of the child's at-least, at-most and
existential clauses under roles in the flipped label). The prototype
should key children on that summary rather than on the parent's full
type, as SHI keys on `(K, A)`, and measure the difference.

## 5. Step one: prototype and measurement (no proofs)

Plain Lean, `partial` allowed, in `lean/KMSRIQFastProbe.lean` (an
executable, outside `ContextCalculus`). Reuse `translateSRIQ`,
`encTransQ`. Validate answers against `classifyQ` on the small tests and
against km on corpus inputs. Coverage target: the 32 corpus inputs that
reached classification in the C1 probe, 60 s each.

## 6. Step two: proof (after review of step one)

The rule set as measured; the abstract theorem by the simulation
invariant; `closedB`; `classifyQF_spec`.
