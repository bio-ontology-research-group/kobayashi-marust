## 1. What the producer builds

Input: the checker's normal form of the ontology O (`--print-index` and
`--print-clauses` of `km-owl-reference --procedure sroiq-hint`) and km's
rows (`km classify --lines --realize --top`: SUB, UNSAT, TYPE, SAME, TOP).
Output, per input: one or more models (`model<k>.hint`, the core format of
the C5 note: `blocks`, `ty`, `lab`, `dstar`; no tree records) and a witness table
per model (`model<k>.wit`: `class IRI ELEMENT` and, in model 0,
`individual IRI ELEMENT`), plus `producer.json` with the counts below.

Model 0 holds

* one element per named individual, merged per km's SAME rows (an element
  may carry several nominal names; each nominal name is at exactly one
  element, as `NomOK` asks);
* a witness element for owl:Thing and for every class km calls
  satisfiable, aiming at the most general type: its named part is km's
  superclasses of the class (plus the classes equivalent to owl:Thing);
* the successors those elements need, shared wherever a type fits.

A witness of A whose type holds a named class B outside km's superclasses
of A is *dirty*: it certifies every non-subsumer of A except B. The
producer then adds *split witnesses* for A that forbid the dirty names
(one witness forbidding all of them, halves if that fails). A witness
whose construction would add a named class to an earlier witness or to an
individual outside its target (*pollution*: for example `A ⊑ ∃r.{o} ⊓
∀r.B` forces `B(o)` in every model where A is not empty, so the same
model cannot also show `o ∉ B`) is rolled back and built in model 1, then
2, and so on (at most 16 models). When model 0's ABox individuals have
unavoidable disjunctive choices over named classes outside km's entailed
types, the producer also builds clean individual split models (`ind_split`)
that forbid the dirty individual types and emit `individual IRI ELEMENT`
witness entries in subsequent models.

The certified rows a model would give (the H2 witness row: for each class
A with witness w, `A ⋢ B` for every named B not in the type of w; for each
individual a, `a ∉ C` for every named C not in its element's type) are
computed by the producer and reported as **unchecked**. Every pair (A, B)
with A satisfiable must be either a km subsumption or such a row.

## 2. Construction

`engine.rs`, `build.rs`, `data.rs`, `emit.rs`. Types are interned sorted
sets of normal-form names; labels are interned up-closed role sets; edges
are stored at both ends (the reverse label is the inverse set; a loop
carries its label closed under inverse). A worklist saturates the whole
structure at once:

1. **Types.** Names pushed into an element are absorbed by re-closing its
   type: Horn propagation over the gcis (counters per gci, indexed by body
   name), data-range satisfiability checking (`data.rs`), and depth-first
   choice on the first open disjunctive gci. The heads are ordered by a
   one-step lookahead: Horn consequences of each head; heads with a clash,
   a data-range clash, or an unsatisfiable one-step existential (`succ_check`)
   are dropped, then nominal-free heads first, then fewest named classes
   outside the element's target (km's superclasses for a witness, km's types
   for an individual, none for an anonymous element), then unnamed before
   named. The closure first keeps the element's earlier choices (it closes
   the old type plus the new names); if that clashes it re-closes from the
   forced names alone. Closures are memoised by `(seed, forbidden set,
   target, no_nom)`.
2. **Universals** (`all a S c`) push `c` into every neighbour over an edge
   whose label holds S, in both directions. Backward forbidden calculation
   (`bwd_forbid`) also forbids any filler class `c` on a successor over `S`
   when `all c S^- d` would push a forbidden class `d` back into the parent.
3. **Existentials and at-least clauses** (`some`, `atleast`) look for a
   neighbour first. Otherwise the seed `{b} ∪ fwd(type, label)` is closed
   to a type T (with half-splitting of non-nominal backward forbidden sets
   when the full backward forbidden set clashes), and an existing element
   of type T (or a clean supertype when exact reuse fails) is reused when
   the edge changes neither type and no at-most clause at either end would
   be exceeded; only then is a new element created. On Horn inputs this is
   the canonical model: one element per needed filler type, and a class
   whose filler type equals its own type gets a loop (`A ⊑ ∃r.A`). A seed
   that holds a nominal name goes to that individual's element.
4. **At-most clauses** fold a surplus neighbour y1 into another counted
   neighbour y2 from the clause holder's side: the edge to y1 is dropped,
   its label is added to the edge to y2, and y2 absorbs y1's type. When a
   direct fold clashes (for example because y1 and y2 are distinct nominals
   or hold disjoint filler classes), `fold_one` tries alternative pairs
   `(y1, y2)` in checkpointed sub-transactions before failing.
5. **Nominal names** pin an element: a type that gains another element's
   nominal name is merged into it (union-find; edges, pending obligations,
   and transitive third-party nominal holders move to the survivor).
6. **Data stars (`dstar`).** For inputs with data clauses, `data.rs` parses
   all `dsome`, `dall`, and `atom` clauses (`dt`, `not-dt`, `facet`, `lit`,
   `not-lit`), checks per-property data satisfiability during type closure,
   and `emit.rs` emits explicit `dstar <elem> <prop> <val>...` lines in the
   hint file so the checker verifies data constraints directly in linear
   time instead of enumerating global data partitions.

Each witness is built in a **transaction**: every change to an existing
element is journalled (copy on first write) and a failure or a pollution
rolls back. Within a transaction a clash restarts it with nogoods (the
exact non-nominal types blamed for the clash are forbidden as closure
results), up to 16 times; the nogoods are dropped after the transaction.

A class km calls unsatisfiable is tried as a witness too (then rolled
back): a self-checked model with such an element would contradict km.

**Self-check** (`check.rs`, written separately from the construction):
every gci at every element, labels up-closed, edge symmetry, every
universal over every edge, existential, at-least and at-most counts over
distinct neighbours, each nominal name at exactly one element, and every
`dsome`/`dall` data constraint against the witness `dstar` values. Only
self-checked models count, even unchecked.

## 4. Failure-Category Analysis and Fixes (`h3b`)

During `h3b`, every failure category from Section 3 was diagnosed and addressed in `tools/hints-rs/` and `tools/hints/driver_h3.py`:

1. **`individual types not general` (60 -> 0 in `pool1m`, 11 -> 0 in `sample1`):**
   * *Causes:*
     1. When the Lean checker eliminates `owl:topObjectProperty` (`roleOff` in `KMOWLReferenceCheck.lean`), it introduces a fresh synthetic nominal `"%%%%%..."` (a string of `'%'` longer than any IRI in the ontology). `nf.rs` and `build.rs` filtered out `urn:km:` and `#` nominals, but not `%`-prefixed nominals, adding `nclasses` unentailed `nontype` rows (`16630`, `2526`).
     2. When ABox individuals had disjunctive choices over named classes (`10320`, `10321`, `10807`, `12101`, `13584`, `15413`, `16814`), model 0 picked a branch containing an unentailed named class, and earlier logic never split individual witnesses across models (`individuals cannot be split`).
     3. In `13837`, `same_b` in `satisfy` (`engine.rs`) fell back to combining two independent existential fillers `∃R.C₁` and `∃R.C₂` on a nominal element `x` with `fb_comb = 0`, forming `C₁ ⊓ C₂ ⊑ ∀R⁻.D` and pushing unentailed class `D` back into `x`.
     4. In `15514`, `close_succ` (`engine.rs`) dropped the entire backward forbidden set `fb = bwd_forbid(tx, fl)` whenever `fb` as a whole clashed on a disjunction where one element of `fb` was unavoidable on both branches and another element of `fb` was avoidable on one branch.
     5. In `16814`, `ind_split` (`build.rs`) added nominal types from `e.blame` into `en.bad` instead of adding the clashing nominal group to `skip_fb`, and re-applied `close_clean` to already-cleaned groups in `ever_dirty` when `fb == 0`.
   * *Fixes:* Filtered `!iri.starts_with('%')` in `nf.rs`, `build.rs`, and `export.rs`; added multi-model individual splitting (`ind_split` in `build.rs`) that builds clean ABox models forbidding dirty individual types; restricted the `fb_comb = 0` fallback in `same_b` to non-nominal elements; added half-splitting of non-nominal `fb` in `close_succ` before falling back to `fb = 0`; and excluded nominal types from `en.bad` in `ind_split`. Result: **0** inputs remain in `individual types not general` across both `sample1` and `pool1m`.

2. **`no base model` (65 -> 17 in `pool1m`, 6 -> 3 in `sample1`):**
   * *Causes:*
     1. `Engine::merge` (`engine.rs`) dropped `ea.pending` when merging `a` into `b`, and when a third element `z != a, b` already held a nominal in `ta`, `merge` overwrote `m.nom_elem[o] = b` without merging `z` into `b`.
     2. `fold_one` (`engine.rs`) picked a single `(y1, y2)` pair greedily and failed immediately when that pair clashed (for example on Wine and Food ontologies `3156`, `14334`, `3010`, `10702` with nominal cardinality restrictions).
     3. `succ_check(t)` (`engine.rs`) checked one-step existential satisfiability under the outer `ft = self.cur_forbid`, but cached `(t, false)` in `self.succ_ok` keyed only by `t`. Subsequent calls with `ft == 0` read the poisoned `false` entry and memoized spurious `CloseRes::Clash` results (`3411`, `4668`).
   * *Fixes:* Updated `Engine::merge` to preserve `ea.pending` and transitively merge any third element holding a nominal in `ta`; added checkpointed multi-pair backtracking in `fold_one` and `process` (`engine.rs`) that blames non-nominal neighbour types before blaming the center element; and guarded `self.succ_ok.insert(t, ok)` with `if ft == 0 || ok`. Result: 48 of 65 `no base model` inputs in `pool1m` (including all 11 Wine ontologies and `3411`) and 3 of 6 in `sample1` are now `certified-full`. The 17 remaining in `pool1m` (and 3 in `sample1`: `10949`, `778`, `85`) require deep cyclic ABox construction with simultaneous universal/at-most propagation across dozens of nominals.

3. **`self-check violation left` (8 -> 0 in `pool1m`, 2 -> 0 in `sample1`):**
   * *Cause:* When a witness or split model hit an unresolvable at-most fold after partial mutations or left an unclosed GCI after rollback failure, the producer emitted a model with `violations > 0`.
   * *Fix:* Wrapped witness and base steps in strict transactional checkpoints (`ckpt` / `rollback`) and added a post-saturation repair pass (`check::check` + `re_close` + `saturate`) before accepting any model. Result: **0** self-check violations across all 174 `sample1` and 892 `pool1m` inputs.

4. **`split witnesses incomplete` (6 -> 4 in `pool1m`, 2 -> 1 in `sample1`):**
   * *Cause:* On `attempts == 0` of a split witness (`forbid != 0`), `close_clean` added `cfb` (which forbids classes outside the target's superclasses); when that choice later clashed during `saturate` via a nominal push (such as `Sweet` pushing `SweetWine` into `WhiteBordeaux` in `3156`), `try_witness` added the nominal's type to `en.bad`, and on `attempts >= 1` `build_witness` called `close_clean` again, whose `cfb` forbade the only clean superclass (`WhiteNonSweetWine`).
   * *Fix:* In `try_witness` (`build.rs`), use `close_clean` on `forbid == 0 || attempts == 0` and fall back to `close(seed, local_forbid, target, true)` on retry attempts `attempts > 0` of a split witness, while filtering nominal types out of `en.bad` whenever non-nominal blame types exist. Result: all Wine ontologies (`3156`, `3010`, etc.) and `4668`'s 10 seed-clash classes recovered; only 4 inputs in `pool1m` (`6` total uncovered rows out of `896,308,212`) and 1 in `sample1` (`1508`) remain in `split witnesses incomplete`.

5. **Data clauses, `dstar` emission, and checker OOM / rejections (`checker out of memory`: 19 -> 0 in `pool1m`, 1 -> 0 in `sample1`):**
   * *Causes:*
     1. Without `dstar` lines in `.hint`, the Lean checker's fallback data-partition test (`checkDataStar`) blew up in memory (`ore_ont_7839`, 13 GB OOM).
     2. In `Values::new` (`data.rs`), the fallback that pushes `Val::Other(dt, "x")` only checked `in_dt(&Val::Num(Kind::Dec, 0.0), &dt) != Some(true)`. For `xsd:positiveInteger` (`0.0` is not `> 0`) and `xsd:negativeInteger` (`0.0` is not `< 0`), `in_dt(0.0, dt)` returned `Some(false)`, so `Values::new` pushed a spurious `Val::Other("...#positiveInteger", "x")` candidate that matched `xsd:positiveInteger` without matching `xsd:integer` or `xsd:decimal`, causing the checker to reject `dstar` on `ore_ont_12653` (`is not a possible entry`).
   * *Fixes:* Implemented full data-clause parsing (`dsome`, `dall`, `atom`), per-type data-range consistency checking, and explicit `dstar` emission (`data.rs`, `emit.rs`), and added `1.0` and `-1.0` probes to the `Val::Other` guard in `Values::new`. Result: **0** checker OOMs across both sets, and `ore_ont_7839` and `ore_ont_12653` are both `certified-full`.
   * *What blocks the 3 remaining checker rejections in `pool1m` (`12723`, `15526`, `9786`):* All 3 ontologies use `ObjectHasSelf` (`accepted self` route) together with 34 data clauses (`DataSomeValuesFrom` / `DataAllValuesFrom`). In `lean/KMOWLReferenceCheck.lean:1861-1888`, `printClausesHint` (`--print-clauses`) calls `emitData` only on the `chain` route, not on the `self` or `hs` routes. Consequently, `base.cl` on those 3 inputs omits all `dsome`/`dall`/`atom` lines (`data-clauses: 0` in `base.cl`), leaving `km-hints` blind to data-range clashes during type closure and unable to emit `dstar` lines. When the Lean checker then checks the hint on the `self` route, `checkRedN` runs `checkDataStar` against the 34 internal data clauses and fails with `the object part checks; the data-star test fails on every data part`. (Since `lean/` is outside the `h3b` edit scope, this is a 2-line fix in `KMOWLReferenceCheck.lean` to call `emitData` in the `self` and `hs` branches of `printClausesHint`.)

6. **Checker timeouts (`checker too slow`: 5 -> 1 in `sample1`, 14 -> 4 in `pool1m`):**
   * *Cause:* `driver_h3.py` originally invoked `km-owl-reference` sequentially across `model0.hint`, `model1.hint`, ..., sharing a single wall-clock budget and leaving large hints with many redundant unreferenced witness entries.
   * *Fix:* Updated `driver_h3.py` so each model check gets up to `CHECK_TIMEOUT` (`300 s`) when total models `<= 4` (or `>= 90 s` per model otherwise), and deduplicated witness entries across split models so `model<k>.wit` (`k > 0`) only lists classes/individuals that still have uncovered negative rows. Result: `sample1` `checker too slow` dropped from **5 -> 1** (`10992`, `12992`, `15363`, `7401` all became `certified-full`; only `14191`, whose single `model0.hint` is 55 MB with 10,837 elements and 130,331 edges, exceeds 300 s in Lean's `checkHint`), and `pool1m` `checker too slow` dropped from **14 -> 4** (`13035`, `14388`, `6298`, `6934`).

## 5. Producer Mode 2: `km-hints from-export`

In addition to building models from scratch (`km-hints build`), `km-hints` now provides `km-hints from-export` (`tools/hints-rs/src/export.rs`), which consumes the `km-model-v1` JSONL stream emitted by `km classify --export-model FILE` (`docs/MODEL-EXPORT.md`):

```bash
km-hints from-export \
  --index base.idx \
  --clauses base.cl \
  --export model.jsonl \
  --out out_dir/ \
  [--km km.lines]
```

### 5.1 How `from-export` works

1. **Stream parsing (`export.rs`):** Reads the `km-model-v1` header (`route`: `el-canonical`, `cb-horn`, or `ht-bridge`), `individual`, `class_witness`, `element` (`concepts`, `nominals`, `same_as`, `data`, `blocked`), `edge`, and `footer` records.
2. **Unravelling blocked nodes:** For tableau exports (`ht-bridge`) containing `blocked: {"by": b, "kind": "subset"|"equality"}` elements, `from-export` redirects edges targeting a blocked node `u` to its blocker `b` (creating a cycle in the finite core model, which the C5 hint checker accepts directly without tree records) and copies any additional outgoing edges from `b`.
3. **IRI mapping and seeding:** Maps each exported element's named concepts and nominals to the Lean checker's normal-form indices (`base.idx`), creates or merges nominal elements according to `nominals` and `same_as`, and seeds every exported element and role edge in the `Engine` (closing edge labels under the checker's role hierarchy `up` and inverse map `inv`).
4. **Normal-form completion and repair:** Because `km --export-model` exports only original ontology IRIs (not the Lean checker's internal normal-form definers `urn:km:...`), `from-export` closes each seeded element's type under the checker's normal-form clauses (`base.cl`), choosing disjuncts and existential fillers biased toward the exported neighbour types and superclasses, saturates missing existential/universal/cardinality obligations, and runs the independent self-checker (`check::check`). Any class or individual whose exported witness is missing or dirty is then completed via the standard transactional witness / split-witness builder.
