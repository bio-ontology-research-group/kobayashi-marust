## 0. Outcome

On the 174-input stratified sample (`tools/hints/results/h3-sample.tsv`), 155 inputs produce km rows and normal forms; the producer builds self-checked full models covering every negative row on 116 inputs, and the proved checker (`km-owl-reference-h5-0cb85570`) confirms every negative row on **111 inputs** (up from 20 in H1), certifying 140.08 billion of 166.96 billion negative rows (83.9%). Five full models exceed the checker time limit.

On all 892 pool inputs under 1 MB (`tools/hints/results/h3-pool1m.tsv`), 832 inputs produce km rows and normal forms; the producer builds full models on 597 inputs (partial on 162, none on 73), and the proved checker confirms every negative row on **582 inputs** (269 of 382 under 100 KB, 313 of 510 between 100 KB and 1 MB), certifying 830.35 million of 896.25 million negative rows (92.6%). Fourteen full models exceed the checker time or memory limit, and one early-sweep full model (`ore_ont_12360`) was checked before the language-tagged literal fix. Zero disagreements with km were found across both sets.

## 1. What the producer builds

Input: the checker's normal form of the ontology O (`--print-index` and
`--print-clauses` of `km-owl-reference --procedure sroiq-hint`) and km's
rows (`km classify --lines --realize --top`: SUB, UNSAT, TYPE, SAME, TOP).
Output, per input: one or more models (`model<k>.hint`, the core format of
the C5 note: `blocks`, `ty`, `lab`; no tree records) and a witness table
per model (`model<k>.wit`: `class IRI ELEMENT` and, in model 0,
`individual IRI ELEMENT`), plus `producer.json` with the counts below.

Model 0 holds

* one element per named individual, merged per km's SAME rows (an element
  may carry several nominal names; each nominal name is at exactly one
  element, as `NomOK` asks);
* a witness element for owl:Thing and for every class km calls
  satisfiable, aiming at the most general type: its named part is km's
  superclasses of the class (plus the classes equivalent to owl:Thing);
* the successors those elements need, shared wherever a type fits.

A witness of A whose type holds a named class B outside km's superclasses
of A is *dirty*: it certifies every non-subsumer of A except B. The
producer then adds *split witnesses* for A that forbid the dirty names
(one witness forbidding all of them, halves if that fails). A witness
whose construction would add a named class to an earlier witness or to an
individual outside its target (*pollution*: for example `A ⊑ ∃r.{o} ⊓
∀r.B` forces `B(o)` in every model where A is not empty, so the same
model cannot also show `o ∉ B`) is rolled back and built in model 1, then
2, and so on (at most 4 models). Individuals' non-types are read from
model 0 only.

The certified rows a model would give (the H2 witness row: for each class
A with witness w, `A ⋢ B` for every named B not in the type of w; for each
individual a, `a ∉ C` for every named C not in its element's type) are
computed by the producer and reported as **unchecked**. Every pair (A, B)
with A satisfiable must be either a km subsumption or such a row.

## 2. Construction

`engine.rs`. Types are interned sorted sets of normal-form names; labels
are interned up-closed role sets; edges are stored at both ends (the
reverse label is the inverse set; a loop carries its label closed under
inverse). A worklist saturates the whole structure at once:

1. **Types.** Names pushed into an element are absorbed by re-closing its
   type: Horn propagation over the gcis (counters per gci, indexed by body
   name) and depth-first choice on the first open disjunctive gci. The
   heads are ordered by a one-step lookahead: Horn consequences of each
   head; heads with a clash are dropped, then nominal-free heads first,
   then fewest named classes outside the element's target (km's
   superclasses for a witness, km's types for an individual, none for an
   anonymous element), then unnamed before named. The closure first keeps
   the element's earlier choices (it closes the old type plus the new
   names); if that clashes it re-closes from the forced names alone.
   Closures are memoised by (seed, forbidden set, target).
2. **Universals** (`all a S c`) push `c` into every neighbour over an edge
   whose label holds S, in both directions.
3. **Existentials and at-least clauses** (`some`, `atleast`) look for a
   neighbour first. Otherwise the seed `{b} ∪ fwd(type, label)` is closed
   to a type T, and an existing element of type exactly T is reused when
   the edge changes neither type (no universal pushes either way) and no
   at-most clause at either end would be exceeded; only then is a new
   element created. On Horn inputs this is the canonical model: one
   element per needed filler type, and a class whose filler type equals
   its own type gets a loop (`A ⊑ ∃r.A`). A seed that holds a nominal name
   goes to that individual's element.
4. **At-most clauses** fold a surplus neighbour y1 into another counted
   neighbour y2 from the clause holder's side: the edge to y1 is dropped,
   its label is added to the edge to y2, and y2 absorbs y1's type. y1 is
   chosen among elements the holder created itself, y2 preferably with a
   type that already contains y1's.
5. **Nominal names** pin an element: a type that gains another element's
   nominal name is merged into it (union-find; edges move to the survivor).

Each witness is built in a **transaction**: every change to an existing
element is journalled (copy on first write) and a failure or a pollution
rolls back. Within a transaction a clash restarts it with nogoods (the
exact types blamed for the clash are forbidden as closure results, as in
H1), at most 6 times; the nogoods are dropped after the transaction. The
base (the individuals) is built the same way with more restarts.

A class km calls unsatisfiable is tried as a witness too (then rolled
back): a self-checked model with such an element would contradict km.

**Self-check** (`check.rs`, written separately from the construction):
every gci at every element, labels up-closed, edge symmetry, every
universal over every edge, existential, at-least and at-most counts over
distinct neighbours, each nominal name at exactly one element. Violations
are reported (first one) and the elements are re-saturated up to three
times. Only self-checked models count, even unchecked.

**Row mapping** (`rowmap.rs`), for today's per-row checker: the normal
form of a row's extended ontology is the base normal form under a
renaming plus the row's guard clauses. The producer maps listed names by
IRI (for `urn:km:` names, relative to the shortest run of `#` of the same
kind, since the fresh prefix grows with the row's IRIs) and unlisted
names in index order, verifies that every renamed base clause occurs in
the row's clauses, puts the row's fresh nominal at the class's witness,
re-closes every element under the row's clauses, self-checks, and writes
the elements reachable from the witness and the individuals.

## 4. Disagreements with km

No disagreement with km. The checks, on every input with a model:
every witness of A holds every superclass km lists for A
(`sup_missing` = 0); every individual's element holds every type km
lists (`type_missing` = 0); every class km calls unsatisfiable (5 in the
sample) was tried as a witness and got no self-checked model; and no
row the checker proved contradicts a km subsumption or type (driver
check, 0 on the whole sample). Classes where the producer found no witness
although km says satisfiable were checked with HermiT 1.4.3
(`tools/hints/HermitCheck.java`, the protege-parity classpath): all
satisfiable, so producer gaps: ore_ont_3685 PinholeCamera, FilmCamera;
ore_ont_9054 NormalLens, 135Film, 35mm, 4x5inFilm, FullFrame, FilmCamera,
120RollFilm, PinholeCamera. ore_ont_12360 (SIOC) is consistent for
HermiT and km; its one checker rejection was a producer bug (a
language-tagged literal read as an `xsd:string` value), found through
`--explain` and fixed.

Found on the checker side during this stage (reported and fixed by H2):
a requested owl:Thing was an unconstrained name, so the witness row
printed `A ⋢ owl:Thing` (fixed in 4f45169a); the check time on mid-size
hints (3685, 11081, 12330: over 300 s, 312 s, over 600 s; 2.7 s, 2.9 s,
31 s in h4-faa12e12). Reproductions:
`/mnt/data1/leechuck/km-work/v170/scratch/h3/repro/`.


## 5. Gaps and requests

Producer (`tools/hints-rs`):

* **No backtracking over at-most folds and merges.** A fold is chosen
  greedily; when every fold clashes the witness fails ("at-most: no fold
  possible"), and a clash after a fold is only retried through exact-type
  nogoods. ore_ont_3685 (photography, SHIQ): PinholeCamera and FilmCamera
  get no witness, HermiT and km both say satisfiable, so these are producer
  gaps.
* **No tree records.** Every element is a core element. No sampled input
  needed one: every witness failure so far is a search gap, not a missing
  finite model, and the node budget (100,000 + 40 per name) was hit only by
  the two producer bugs fixed during the run (chains of fresh elements that
  never closed, sections 2 and 3). A witness that needs an infinite model
  (for example `B ⊑ ∃r.A`, `A ⊑ ∃r.A`, `⊤ ⊑ ≤1 r⁻.⊤`) would end on the
  node budget today; the witness row also accepts only core witnesses.
* **Data.** The producer reads no data clause; the checker's data-star test
  decides data per type. Inputs with data clauses run out of memory in the
  checker (ore_ont_7839, FOAF: 13 GB with or without a `part` line), the
  open item of section 10.3 of the C5 note. Producer side next: read the
  data clauses now printed by `--print-clauses`, choose data values per
  element and write the data star (once the format exists).
* **km's names with prefixes.** For functional-syntax inputs with
  `Prefix(:=...)`, km prints `:A` instead of the full IRI, so the producer
  does not match km's rows to the index (seen on the H2 test files; the pool
  inputs print full IRIs).
* **Type sizes.** Types are closed sets over every normal-form name, so on
  deep EL hierarchies with many definers they are large (ore_ont_12330:
  26,268 elements, 17.8 million type entries, a 107 MB hint). Nothing in
  the proof needs fewer names, but the hint size drives the check time.

Requests to the checker (H2):

* **Check time on mid-size inputs.** Binary 89daa614: ore_ont_11081 (EL,
  9,470 elements, 32,560 edges, 30,630 gcis, 1,733 universals) checks in
  312 s; ore_ont_12330 and others time out at 600 s. The synthetic
  20,657-element case takes 1.6 s, so some part of the check still grows
  with the product of elements and clauses or with the type sizes on these
  inputs (timing per phase below, section 3).
* **Data stars per element** (section 10.3): needed for every input with
  data clauses.
* **Tree-record witnesses**: only if an input needs an infinite model; none
  met so far.
* Done during this stage at my request: owl:Thing and owl:Nothing with OWL
  meaning in the witness row (binary 4f45169a; before it, a requested
  owl:Thing was an unconstrained name and the row printed `A ⋢ owl:Thing`).

Requests to km (to remove search from the producer):

* **Entailed types of the fresh successors**: for each existential `∃r.C`
  that km's saturation expands, the set of named classes (and the
  normal-form definers, if km can map them) of the successor context. With
  it the producer would not need disjunction search on Horn-like parts and
  could fill the successor types directly.
* **The tableau bridge's completion graph** on the inputs routed to it
  (node labels, edges, merges, blocking): a ready model for the non-Horn
  inputs where the producer's greedy at-most handling fails (ore_ont_3685).
* **CB context cores**: per context, the positive atoms and the successor
  contexts with role labels. For Horn contexts they are the canonical model
  the producer rebuilds; for disjunctive ones they guide the choice.
* **Full IRIs in `--lines` output** (no prefix abbreviation).
