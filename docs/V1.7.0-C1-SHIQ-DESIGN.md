# Stage C1: a complete reference procedure for SHIQ (design)

Supervisor's design note, 2026-11-14. It revises section 4.1 of
`docs/V1.7.0-PLAN.md` for C1: SHIQ has the tree-model property, so C1
extends the good-types method of v1.6.3 (`lean/ContextCalculus/SRI`) and
needs no tableau and no blocking. The tableau question returns at C2
(nominals with inverses and counting).

## 1. Normal form `SRIQ`

New namespace `ContextCalculus.SRIQ`, new files; `SRI` stays untouched.
`RoleT`, `Interp`, `rt`, `path` are reused from `SRI`.

```
inductive Clause (CName Role)
  | gci (body head : List CName)
  | exRight (a) (R : RoleT Role) (b)          -- a ⊑ ∃R.b
  | allRight (a) (R) (b)                      -- a ⊑ ∀R.b
  | atLeast (a) (n : Nat) (R) (b)             -- a ⊑ ≥n R.b
  | atMost (a) (n : Nat) (R) (b)              -- a ⊑ ≤n R.b
  | chain (body : List (RoleT Role)) (sup)
```

Semantics of counting as in the OWL model: at least n is a duplicate-free
list of n `R`-successors in `b`; at most n says every duplicate-free list
of such successors has length ≤ n. `SRI.Clause` embeds (`ofSRI`), and
`SRI.EntailsSub O a b ↔ SRIQ.EntailsSub (O.map ofSRI) a b` (same
interpretations).

`IsALCHIQ O`: every chain has length one. (Transitivity is removed
before, section 5.)

## 2. Stars

Fix an ALCHIQ ontology `O`. A type is a `Finset CName`, `Closed` as in
`SRI`. An edge label is a `Finset (RoleT Role)` that is up-closed under
`RoleLe O` (`UpClosed`); the label of the reverse edge is `L.image flip`
(up-closed again by `roleLe_flip`).

A neighbour is a pair `(L, s)`: label from the centre to the neighbour,
and the neighbour's type. For a centre type `t` and a list `N` of
neighbours:

- `EdgeOK t (L, s)`: for every `allRight a S c ∈ O`: `S ∈ L → a ∈ t → c ∈ s`,
  and `S.flip ∈ L → a ∈ s → c ∈ t`.
- `cnt N R b` = number of entries `(L, s)` of `N` with `R ∈ L ∧ b ∈ s`.
- `StarOK t N`: `Closed O t`; every entry is `EdgeOK` with an up-closed
  label; for `exRight a R b ∈ O` with `a ∈ t`: `cnt N R b ≥ 1`; for
  `atLeast a n R b` with `a ∈ t`: `cnt N R b ≥ n`; for `atMost a n R b`
  with `a ∈ t`: `cnt N R b ≤ n`.

A record is `(t, par)` with `par : Option (label × type)`: the node's
type and, unless it is a root, the label to its parent and the parent's
type. A set `G` of records is self-supporting if every `(t, par) ∈ G` has
a list `C` of children `(L, s)` with `StarOK t (par.toList ++ C)` and
`(s, some (L.image flip, t)) ∈ G` for every child. A record is good if it
lies in a self-supporting set.

## 3. Characterisation theorem (the heart of C1)

`entailsSub_iff_star`: for `IsALCHIQ O`,
`EntailsSub O a b ↔ ∀ t, Good (t, none) → a ∈ t → b ∈ t`.

- **Model to stars.** Given a model `I` and elements `x`, parent `y`:
  `type x`, `label x y = {S | I.rt S x y}` (up-closed by `roleLe_sound`).
  For each `exRight`/`atLeast` clause that fires at `x` choose a
  duplicate-free list of witnesses; let `W` be the duplicate-free union
  of all of them with `y` removed. Children: `(label x z, type z)` for
  `z ∈ W`, as a list with one entry per element (equal pairs repeat).
  Counting: at-least holds because the witnesses are in `W` or equal `y`,
  and `y` is the parent entry; at-most holds because the entries counted
  are distinct elements of the model, all `R`-successors in `b`. The set
  of all records `(type x, none)` and `(type x, some (label x y, type y))`
  with `I.rt S x y` for some `S`... (take all pairs `x, y`; an empty
  label is allowed) is self-supporting.
  Classical choice is fine here; the union needs a finite clause list.
- **Stars to model.** Unravel: nodes are finite paths `r₀ c₁ r₁ … cₖ rₖ`
  of good records where `cᵢ` is an index into the children list chosen
  (by choice, once per record) for `rᵢ₋₁`, and `rᵢ` is that child's
  record. `I.c B p` iff `B` is in the last record's type; `I.r r p q` iff
  `q` extends `p` by one child whose label contains `pos r`, or `p`
  extends `q` by one child whose label contains `inv r`. Then
  `I.rt S p q` holds exactly along tree edges with `S` in the label
  (read in the right direction), the neighbours of a node are exactly
  the entries of its star (distinct children are distinct paths; the
  parent is not a child), and each clause kind follows from `StarOK`.
  Length-one chains hold because labels are up-closed.

## 4. Executable procedure

As `SRI/Procedure.lean`: over `Fin n` names and `Fin m` roles, records
form a `Fintype` (types, optional label and type). `step`-free version
first: start from all records (the full finite set), and eliminate
records with no supporting children list until stable. Deciding
"a supporting children list exists in `G`" needs a bound: if any list
works, one works whose length is at most the sum of the `n` of the
`atLeast` clauses (and 1 per `exRight`) of `O` (prune a list to chosen
witnesses: removing neighbours keeps at-most and edge conditions). So
search lists up to that length over the finite candidate set. Capstone:
`classifyQ_spec` in the shape of `SRI.Proc.classify_spec`
(`Abstract.lean`). This version is exponential on purpose; a
demand-driven fast version (reachable records, per-clause witness
selection) is a later step, as `Fast.lean` was for SHI.

## 5. Transitivity and simple roles

`IsSHIQ O`: chains are inclusions or transitivity, and no role `R` that
occurs in an `atLeast`/`atMost` clause has a transitive role below it or
below its inverse (`RoleLe`), the OWL 2 DL simple-role restriction.
Extend `encTrans` (`SRI/Transitivity.lean`) to `SRIQ`: counting clauses
pass through unchanged. `encTrans_correct` carries over because the
model construction only adds edges to roles above a transitive role,
which no counting clause mentions.

## 6. OWL side (after stage C0 merges)

`translateSRIQ`: cardinalities, functional and inverse functional
properties; negative occurrences by the usual complement names
(`≥n R.C ⊑ D` as `nD ⊑ ≤(n-1) R.C`). Capstone
`owlSHIQReference_sound/complete` on `OWL.Ontology.isSHIQ`.

## 7. Order

1. `SRIQ/NormalForm.lean`, embedding of `SRI`.
2. `SRIQ/Stars.lean`: definitions, both directions,
   `entailsSub_iff_star`, `unsat_iff_no_star`.
3. `SRIQ/Procedure.lean`: elimination, list bound, `classifyQ_spec`,
   tests on small inputs (functionality forcing merges, `≥2` against
   `≤1` clashes, inverse with counting, an input with only infinite
   models).
4. `SRIQ/Transitivity.lean`.
5. Translation and capstone (needs C0).
