  60 s under a 16 GB cap (the C1 `classifyQ` probe: 0); 70 of the 84
  v1.6.3 SHI targets finish (the SHI fast procedure: 68; 66 in common,

## 2. The final rule set (variant v8; v6 to v8 differ only in speed)

Fix an ALCHIQ ontology `O` (after `encTransQ`) over names `0 … n-1` and
role terms. `up R` is the set of super-roles of `R` (closed under the
inclusions and their flips). A *label* is a set of role terms closed under
`up`; `flip L = {R⁻ | R ∈ L}` (again a label).

Clause lists. Lower clauses `(a, k, R, b)`: `atLeast a k R b` with
`k ≥ 1`, and `exRight a R b` as `k = 1`. Upper clauses `(a, n, S, e)`:
`atMost a n S e`. A clause *fires* at `t` if `a ∈ t`.

Propagation. `fwd t L = {c | allRight a S c ∈ O, a ∈ t, S ∈ L}` (the
names a neighbour across `L` must hold). For a node of type `s` whose
edge to its parent has label `L` (child to parent), its *back set* is
`back s = fwd s L`, the names it pushes to the parent.

Relevant names. `Rel L` is the set of
- fillers `e` of upper clauses whose role is in `L`, and
- fillers `b` of lower clauses `(a, k, R, b)` with `R ∈ L` such that some
  upper clause has its role in `up R`.

Branches. `branches σ`: start from `σ`; repeatedly take a gci
`body ⊑ head` whose body holds and no head name holds; if the head is
empty, drop this line (a clash); otherwise branch over the head names,
adding *one* name each (except at a lazy disjunction, below). Every
result is closed. For every closed `T ⊇ σ` some branch is `⊆ T` (pick
a head name in `T` each time). The design note and SHI's `branches` add
every nonempty subset of the head; one name suffices for this property.

Lazy disjunctions. A top gci `⊤ ⊑ h₁ ⊔ … ⊔ hⱼ` (empty body, `j ≥ 2`)
is *lazy* if one head name `w` is a *pure definer*: `w` is not a
requested name, is in the head of this gci only, occurs in no gci body,
is the filler of no clause, has no universal clause, and is the left
name of exactly one lower or upper clause. (The translation makes these
for negative occurrences of number restrictions and universals.) An
at-most definer is preferred. `branches` adds `w` at a lazy gci
(no branching).

Contexts. A context is `κ = (K, L, π)`: a seed `K`, the label `L` from
the child to its parent (empty for a root) and `π ⊆ Rel L`, the parent's
type restricted to `Rel L`. Root contexts are `({a}, ∅, ∅)` for the
requested names `a`.

Nodes. A node is `(κ, t)` with `t` closed and `K ⊆ t`. Each node has a
pool of specs. A spec `σ = (Lc, B)` is a label `Lc` from the node to a
child and a set `B` of fillers the child must hold. The child context of
`σ` at node `(κ, t)` is

    ctx(t, σ) = (B ∪ fwd t Lc, flip Lc, t ∩ Rel (flip Lc)).

The node's *parent entry* counts for a clause with role `R` and filler
`b` when `R ∈ L` and `b ∈ π`.

Needs. For node `(κ, t)` and lower clause `q = (a, k, R, b)` firing at
`t`, the need is `k - p` where `p = 1` if the parent entry counts for
`(R, b)`, else `0`. A *candidate entry* for `q` is a pair (pool spec
`σ` with `R ∈ σ.Lc`, node `c` of `ctx(t, σ)` with `b ∈ c.t`).

Generation rules (U is the least set closed under them; the prototype
computes it with a worklist and hash maps):

- **R1 root.** For every requested `a`: every branch of `{a}` is a node
  of `({a}, ∅, ∅)`.
- **R2 child.** For every node and pool spec `σ`: every branch of the
  seed of `ctx(t, σ)` is a node of that context.
- **R3 default specs.** The pool of `(κ, t)` contains `(up R, {b})` for
  every lower clause `(a, k, R, b)` firing at `t`, except when `k = 1`
  and the parent entry counts for `(R, b)` (skip-covered).
- **R4 back, through forced sets.** For node `(κ, t)` and each need
  `q > 0`, let `F q` be the intersection of the back sets of all
  candidate entries for `q` (if `q` has no candidate entry, R4 does
  nothing for this node now). Let `F = ⋃ F q`. If `F ⊄ t`: every branch
  of `t ∪ F` is a node of `κ`. Otherwise: for every candidate entry
  (of any need) with back set `X ⊄ t`, every branch of `t ∪ X` is a node
  of `κ`. New nodes copy the pool (inheritance).
- **R5 merge.** For node `(κ, t)` and upper clause `u = (a, n, S, e)`
  firing at `t`: a spec `σ` *may count* for `u` if `S ∈ σ.Lc` and some
  node of `ctx(t, σ)` holds `e`. Let `C` be these specs and
  `pot = [parent entry counts for (S, e)] + Σ k` over the lower clauses
  `(a', k, R, b)` firing at `t` for which some `σ ∈ C` has `R ∈ σ.Lc`
  and some node of `ctx(t, σ)` holds `b`. If `pot > n`:
  - if `n = 1`, let `D` be the default specs in `C` whose filler `e` is
    in the child seed or in every type (`⊤ ⊑ e`) ("definitely
    counted"), and `P` the other default specs in `C`; if `D` is
    nonempty and `|P| ≤ 8`, add `M ∪ ⋃P'` and `⋃P'` (nonempty) for
    every `P' ⊆ P`, where `M = ⋃ D` (union of specs is componentwise);
  - otherwise add `σ₁ ∪ σ₂` for every pair in `C`.
- **R6 parent witness.** In R5, if the parent entry counts for `u`, then
  for every added or listed spec `σ = (Lc, B)` the context `κ` records
  the request `(B, Lc)`. Every parent `μ` of `κ` (a node with a pool
  spec `σμ = (Lμ, Bμ)` whose child context is `κ`) then gets the grown
  spec `σμ' = (Lμ ∪ flip Lc, Bμ)`: added to `μ`'s own pool if
  `B ⊆ t_μ`, else in the pools of the new nodes `branches (t_μ ∪ B)` of
  `μ`'s context (which also copy `μ`'s pool).
- **R7 lazy alternatives (between rounds).** Generation runs in rounds.
  After each round, elimination runs on the current set; every dead
  node `(κ, t)` that holds a lazy default `w` whose clause may be
  violated (`w` has a lower clause, or `pot > n` as in R5 for its upper
  clause) gets the nodes `branches ((t \ {w}) ∪ {h})` of `κ` for every
  other head name `h` of `w`'s gci. Stop when a round adds no node.

Elimination. A node `(κ, t)` is *supported* in a set `A` if there is a
multiset `E` of entries (pool spec `σ`, node `c ∈ A` of `ctx(t, σ)`
with `back c ⊆ t`) such that, counting the parent entry, every lower
clause firing at `t` has count `≥ k` and every upper clause firing at
`t` has count `≤ n` (an entry `(σ, c)` counts for `(R, b)` if
`R ∈ σ.Lc` and `b ∈ c.t`). `alive` is the greatest subset of U in which
every node is supported (computed by deleting unsupported nodes until
stable, re-checking the parents of each deleted node's context). The
search for `E` is exact: entries are reduced to signatures (which needs
and which upper clauses they count for); a depth-first search adds an
entry that counts for the first unmet need, with memo on the remaining
needs and limits. It finds a multiset whenever one exists (take a
minimal solution `E*`: while the current multiset is below `E*`, the
first unmet need has a counting entry in `E* minus` the current one).

Answers. For requested `a`: `none` (unsatisfiable) if no alive root node
holds `a`; else the requested names in every alive root type holding `a`.

## 3. Differences from the design note, and why

1. **Contexts instead of parent summaries in the node.** The design keys
   a child on (seed, label, counting-relevant names of the parent). The
   prototype does exactly that with `κ = (K, L, π)`, and `π` is narrower
   than the design's "fillers of the child's counting clauses under roles
   in the label": lower fillers only enter when an upper clause has a
   role above the lower clause's role (otherwise the parent serving that
   demand never matters for an at-most clause; it only saves an entry).
   Measured: `KM_SRIQF_FULLREL=1` (all lower fillers) changes nothing on
   the 16 finished inputs; `KM_SRIQF_PIFULL=1` (key on the whole parent
   type, the case the design asks to compare with) loses 4 of the 16 (the four 2748/3087 inputs time out) and makes ore_ont_1603 and ore_ont_5707 create 5 to 6 times more contexts (4 411 against 830, 4 871 against 796). The sharing of section 4 is needed.
2. **Spec pools instead of a fixed spec list per node.** The design's
   node carries a list of child specs and merges produce node variants.
   Here a node carries a pool; elimination may use any multiset of pool
   specs. A merge adds a spec to the pool; the support search decides
   which specs to use. This avoids one node variant per merge choice.
3. **One head name per fired gci** in `branches` (SHI used every
   nonempty subset of the head). The `guided` property holds as stated.
4. **Back rule through forced sets (R4).** SHI's augment rule (and the
   design's back rule) adds a variant per child back set, and variants of
   variants give every union of back sets. R4 first adds the union of
   the back sets that every candidate for some need forces, and uses
   single back sets only once the forced part is present. Back sets of
   entries that count for no need are not used (a minimal star never uses
   such entries). Effect: ore_ont_16461 went from timeout to 0.1 s
   (41 234 nodes after 2 s to 270 nodes in total); without it 5 of the 16
   finished inputs time out.
5. **Merge for at-most 1 (R5, first case).** Pairwise closure produces
   every union of the counted specs. For `≤1`, every definitely counted
   default spec must be the same element, so they merge at once. Without
   it the four 2748/3087 inputs (all functional roles) time out
   (377 118 merges on ore_ont_11623).
6. **Lazy definer disjunctions (R7), new.** Not in the design. Negative
   occurrences of number restrictions and universals give top-level
   disjunctions `⊤ ⊑ X ⊔ W` in every type; with 11 to 215 of them the
   first `branches` call does not return (section 7). R7 takes the
   definer by default and adds the alternatives only for dead nodes. It
   removed the first-call blowup but not the later one (section 7), so
   on the corpus it gains nothing yet; it is kept because it is the only
   handle on that family and it agrees with the references.
7. **Skip covered demands (R3).** No default spec for an existential the
   parent entry already meets. Measured: no effect on the 16 finished
   inputs; it saves whole subtrees on inverse-role inputs.
8. **Elimination by search, not by fixed specs.** The design's support
   condition ("every spec has an alive child ... such that the star
   satisfies StarOK") is replaced by the multiset search over pool
   entries, which also lets the parent entry replace entries.

## 4. Argument per rule for the simulation invariant

Soundness first (no simulation needed). Map the alive set to C1 records:
a root node `(κ, t)` to `(t, none)`, and for an alive node `(κ, t)`, pool
spec `σ` and alive `c` of `ctx(t, σ)` with `back c ⊆ t`, the record
`(c.t, some (flip σ.Lc, t))`. This record set is self-supporting in the
sense of `Stars.lean`: the star found for `c` (parent entry plus
entries) is a C1 star of the record because (i) `fwd t σ.Lc ⊆ K ⊆ c.t`
and `back c ⊆ t` give `EdgeOK` across the parent edge, (ii) labels are
up-closed, (iii) the counts at `c` only read the parent type at names in
`Rel`, and `π = t ∩ Rel` is exact for every upper filler and for every
lower filler it contains (a lower filler outside `π` only makes `c`
count the parent less, so the star found has at least the counts the
real parent gives); every child of the star is again in the set. So
every alive root type is `Good`, and a non-subsumption read off it is
correct. This holds for any generator; all rules below matter only for
completeness.

Completeness: fix a model `I` of `O` and an element `x ∈ a \ b` (or `x ∈
a` for satisfiability). A node `(κ, t)` *simulates* `(z, y)` (`z` with
neighbour `y`) if `t ⊆ type z` up to lazy defaults (below), `L ⊆
label(z, y)` and `π ⊆ type y`. We need an alive root below `x`. The
claim is that the set S of nodes simulating some pair, chosen as below,
is self-supporting inside U; then S ⊆ alive. For a node `ν ∈ S`
simulating `(z, y)` choose distinct model witnesses for every lower
clause firing at `t` (they fire at `z`) and build the star block by
block: one entry per distinct witness `w ≠ y` (serving every demand
copy assigned to `w`), the parent entry for the copies assigned to `y`.

- **R1, R2, guided branches.** A branch below the model type exists for
  every seed below it (one head name per gci suffices). Sound for every
  rule below because each new node is a branch of a set below the model
  type.
- **R3 (and skip-covered).** The default entry of a demand copy simulates
  its witness. If the parent entry counts for an existential, choose `y`
  as the witness (valid in `I`: `R ∈ L ⊆ label(z, y)`, `b ∈ π ⊆ type y`).
  Argued, no gap.
- **R4 forced back sets.** Every star of the simulating node uses a
  candidate entry for each need, so the simulating type (which contains
  the back sets of its entries, by the edge condition in `I`) contains
  every `F q` and hence `F`; the branch of `t ∪ F` below the model type
  exists. When `F ⊆ t`, the single-set variants are those of the design.
  The restriction to entries counting for some need is the C1 pruning
  lemma (`starOK_filter`). Argued, no gap; the argument uses only the
  final U (it is a closure condition, so `closedB` can check it).
- **R5 merge.** If the simulating star (blocks as above, each entry an
  entry of a pool spec) violates `u = (a, n, S, e)` at `t`, then more
  than `n` entries count, each maps to an `S`-neighbour in `e` of `z`,
  and `I` has at most `n` of those, so two map to the same element: the
  block construction never does this, but the *default* star (one entry
  per demand copy) can. `pot` bounds the counting entries of a minimal
  star from above (each entry of a minimal star is critical for a need
  it counts for; at most `k` entries are critical for a clause with
  number `k`), so the trigger fires whenever such a violation is
  possible, and the pairwise closure contains the spec of every union of
  blocks. For `n = 1` (first case): all counted entries map to the single
  `S`-neighbour in `e`, so every block whose spec is definitely counted
  is that element's block, and the possibly counted ones join or not; the
  added specs are exactly these unions. Argued; gap: the case `|P| > 8`
  falls back to the pairwise rule (complete, only slower).
- **R6 parent witness.** If the default star counts the parent entry and
  an entry that maps to `y`, the block goes to the parent: the parent
  must hold `B` (true in `I` for `y`) and the edge label grows by the
  block's label (inside `label(y, z)` in `I`). The parent variant
  `branches (t_μ ∪ B)` has a branch below `type y`, and its grown spec
  has a child context whose nodes include a branch below `type z`; in
  that context the parent entry counts for the moved demands. **Gap
  (main proof obligation):** this rule changes the parent's node, which
  changes the child contexts of the parent and possibly its own parent
  entry counts, and so on up and down the tree. I argue convergence by a
  monotone measure (each step grows a type towards the model type, grows
  a label towards the model label, or removes an entry of a star), but I
  have not written a proof that the *final* U contains a simulating
  family for every model pair simultaneously. A proof needs a
  well-founded (or coinductive) construction of S over the whole model,
  with the guided branches chosen consistently.
- **R7 lazy definers.** Fix the model's interpretation of each definer
  `w` to be extremal (an at-most definer: all elements meeting its
  bound; a lower definer: exactly the elements with its witnesses);
  this keeps a model, because `w` occurs nowhere else. The guided node
  of `z` takes `w` when `z ∈ w` and the alternative otherwise. If the
  default node is alive, it can replace the guided alternative
  everywhere: it holds the same names except `w` and the alternative's
  extra consequences, `w` is no filler and has no universal clause, so
  its back set and its counts for any parent are no larger, and it is
  not requested, so the readout of requested names is unchanged. If it is
  dead, then its simulating star (which needs only the model) violates
  only `w`'s clause, so `pot > n` (or `w` is a lower definer) and R7
  adds the alternatives. Gap: the round structure makes U depend on
  intermediate elimination results; `closedB` must check "every dead
  node holding a default whose clause may be violated has its
  alternatives", which is a closure condition on (U, alive) and
  checkable, but the abstract theorem then has to be stated for the
  pair, not for U alone.
- **Pool inheritance.** Only adds specs. No effect on completeness; the
  measurement shows no effect on speed either (16/16, same time).

No rule is known to lose completeness: every rule that prunes (R4's
forced sets, R5's `n = 1` case, R3's skip, the narrower `Rel`, R7's
defaults) has an argument above. The open part is the global
convergence argument for R6 (and R7's dependence on elimination).

The brute force (`SRIQFast/Brute.lean`) is the C1 elimination over all
records with an exact search for a children multiset; it agreed with
`classifyQO` wherever both ran (every `KM_SRIQF_REF` run above also ran
the brute force). `classifyQO` itself runs out of memory once the
at-least numbers add up to about 3 (it enumerates every children list up
to that length), so most random checks use the brute force.

Over the 700 plain random inputs the rules fire: merges in 193, parent
witness requests in 161, back variants in 187, parent-witness variants
in 128; 402 have an unsatisfiable name.

Disagreements found during the work, all in my refinements, none in the
design:
1. v3: a lazy default was a requested name (the syntactic "pure definer"
   test matched a named class with one at-most clause), so its presence
   in every default type made it a false subsumer (random seed 5029).
   Fix: only names that are not requested can be defaults.
2. Harness: comparing definer names (not requested) is meaningless under
   lazy defaults; the `--sriq` format got a `req` line.
3. The SHI km comparison first reported 2 differences that were only
   km's `:X` prefix abbreviation (fixed in `cmp_km.py`).

The simple-role check: the probe uses `isSHIQFast` (one breadth-first
search per transitive role) instead of the proved `isSHIQB`, which takes
6 s on ore_ont_11623 and over 120 s on the three 23136 inputs. Both give
the same answer on all 113 of the 116 target inputs where `isSHIQB`
finishes in 120 s.

## 8. Open risks

1. **Proof of completeness for R6 (parent witness).** The local argument
   is clear, the global one (a simulating family for all model pairs in
   the final U) is not written. This is the step the C1c proof must do
   first; if it fails, R6 must become eager (generate grown labels for
   every child demand the parent could serve), which costs variants.
2. **R7 (lazy definers) makes U depend on elimination.** The abstract
   theorem then needs the closure condition on the pair (U, alive). R7
   gains nothing on the corpus yet, so it could be dropped from the
   proof without loss today.
3. **Over-approximate triggers.** R5's `pot` uses the union of all node
   types of a child context; it is safe (over-approximation) but makes
   the merge closure large (7877, 9012). A sharper bound is a proof
   obligation too.
4. **Top-level disjunctions** (negative number restrictions and
   universals) remain the main family that does not finish (7 of the 16).
   Laziness for existential definers needs a better trigger than "dead".
5. **Throughput.** The other 9 failures look like constant-factor and
   indexing problems (about 0.4 ms per event); the SHI fast procedure
   finishes EL-like inputs of 10⁵ lower clauses in 5 to 10 s. The proof does not
   depend on this, but the C1c target of 32 inputs does.
6. **Validation reach.** `classifyQO` itself only checks inputs with
   at-least numbers adding up to 2; the brute force is unproved (it
   agreed with `classifyQO` wherever both ran). Random inputs have at
   most 6 names (plus definers) and 2 roles, no transitivity.
7. **Front end.** The probe uses `isSHIQFast` instead of `isSHIQB` (same
   answers where `isSHIQB` finishes); `encTransQ` takes 10 s on the
   23136 inputs.
