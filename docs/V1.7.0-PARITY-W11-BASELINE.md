## Question classes that changed against W5A

Out of 1,508 method-ontology cells and 97,448 individual calls, running the unmodified W5A plugin against `km-badf3238` produces the exact same verdict on 1,507 of 1,508 cells and 97,447 of 97,448 calls:

1. **`getDifferentIndividuals` on `ore_ont_8948` (cell: `km_unsupported` -> `km_timeout`; call `getDifferentIndividuals(centi)`: `km_unsupported` -> `agree`)**:
   - In W5A (`km-5eea1411`), `getDifferentIndividuals(centi)` on `ore_ont_8948` failed at 16,585 ms with an interrupted subprocess (`ReasonerInternalException`, counted as `km_unsupported`), while the remaining 5 sampled calls timed out at 20,000 ms (`km_timeout`). Because `parity_report.py` ranks `km_unsupported` ahead of `km_timeout` when aggregating a cell, the `ore_ont_8948` cell appeared under `KM unsupported` in W5A.
   - In the W11 baseline (`km-badf3238`, where `--realize` and `--properties` workers respect `KM_THREADS=1`), `getDifferentIndividuals(centi)` completes in 19,798 ms and agrees with HermiT (`agree`), while the other 5 calls still hit the 20,000 ms cap because the unmodified plugin retains the obsolete per-pair `SameIndividual` refutation loop from W5A. The cell therefore moves from `KM unsupported` (176 -> 175) to `KM timeout` (8 -> 9).
2. **All other question classes (unchanged in verdict before plugin changes)**:
   - Data property hierarchy, domains, equivalents, and disjointness outside the syntactic fragment (`getTopDataPropertyNode`, `getBottomDataPropertyNode`, `getSubDataProperties`, `getSuperDataProperties`, `getEquivalentDataProperties`, `getDisjointDataProperties`, and `isEntailed` for data property axioms): still `km_unsupported` on the 11 ontologies outside `DataPropertyModel`'s syntactic fragment because the unmodified plugin has not yet wired `km classify --lines --data-properties`.
   - Anonymous class expression queries with fresh datatypes (`isSatisfiable`, `getSubClasses`, `getSuperClasses`, `getEquivalentClasses`, `getInstances` on `ore_ont_13759` and `ore_ont_1834`): still `km_unsupported` because the unmodified plugin has not yet passed `--unknown-datatypes=free`.
   - `getPrecomputableInferenceTypes`, `isPrecomputed`, and `isEntailmentCheckingSupported`: unchanged before plugin updates.
   - `Differ` cells (136 cells, 266 calls): byte-for-byte identical to W5A before plugin updates.
   - Per-call worst-case latencies improve on large ontologies (`getDisjointClasses` 3,262 ms -> 2,784 ms, `getInstances [expr]` 3,349 ms -> 2,875 ms, `isSatisfiable [expr]` 3,254 ms -> 2,805 ms on `ore_ont_7726`; `getObjectPropertyValues` 6,419 ms -> 5,449 ms on `food`) because `km-badf3238` honours `KM_THREADS=1` across all worker paths.
