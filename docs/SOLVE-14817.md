## Symptom and localization

The final 9724 binary timed out after 240 seconds on 14817. Saturation answered
48,642 of 58,364 active subjects and left 9,722 for completion. After the
cache-lifecycle and task-slicing ports described below, full job 48841110 still
timed out at subject 9,217 of 9,722. It used only 4,289,560 KB, so the residual
problem was a small high-cost tail rather than global memory exhaustion.

Two isolated tail subjects, 85031 and 84882, consumed most of the remaining
time. Subject 85031 maps to `UBERON_0014672` and completion concept tag 85041.
The old 45-second trace in job 48849853 deferred this one subject. It recorded
only nine saturation-successor expansions, for successor ids 1007 through
1015, followed by 72,670 disjunction replacement events before the budget
expired.

Queue and label diagnostics ruled out accidental requeueing. Job 48850830
watched concept tag 136767 through branch restoration. Every apparently
repeated insertion belonged to a newly restored branch state; reinsertion in
the same state reported the concept as already contained. KM was exploring a
real branch tree.

## Trusted Konclude comparison

The Konclude trace binary was built by relinking the exact native IBEX object
set and recompiling only the instrumented completion object. A native-object
control run, job 48849334, completed in 33.36 seconds. This separated trace
effects from compiler or dependency changes.

Target trace job 48849538 completed the entire Konclude classification in
50.34 seconds at 3,078,512 KB. Konclude dispatched the
`UBERON_0014672` satisfiability test at millisecond 1784070121114 and received
its callback at 1784070121239, a 125 ms completion interval.

The first structural difference was decisive:

- Konclude saturation-expanded the first six root successors as three
  cardinality-created pairs before installing their role links and processing
  their labels.
- KM created corresponding successors 1001 through 1006 but never called its
  saturation-expansion path for them. Its trace began at successor 1007.
- The repeated disjunction work occurred inside exactly those six unexpanded
  successors.

This was not a search heuristic difference. KM called a different successor
constructor.

## Exact missing port

Konclude's
`CCalculationTableauCompletionTaskHandleAlgorithm::applyATLEASTRule`, lines
16168–16252 in the retained source, performs this sequence for `≥ n R.C`:

1. Create an `ATLEAST` dependency track point.
2. Call `createDistinctSuccessorIndividuals` with the role's signed indirect
   super-role list, qualifier, dependency, and cardinality.
3. Mark low-level nominal successors for extended processing when needed.
4. Queue every completed successor.

`createDistinctSuccessorIndividuals`, lines 22322–22364, then performs this
order for each successor:

1. Allocate all `n` successors and make every pair distinct.
2. Resolve the generating restriction's saturation successor node.
3. Replay that saturation node with `tryExpansionFromSaturatedData`.
4. Create and reapply all signed indirect-super-role links.
5. Set the ancestor link, depth, and inherited cache flags.
6. Add the explicit qualifier concepts.
7. Attempt saturation-cache establishment.

Rust already had a close port of this full routine in
`completion/u35.rs::create_distinct_successor_individuals`. Production
`apply_atleast_rule` bypassed it and called the reduced
`ht_create_distinct_successors` helper instead. That helper created distinct
nodes, links, and qualifiers, but it did not resolve or replay the saturation
successor and did not establish saturation caching. This explains both the
missing expansion events and the location of the branch explosion.

## Implemented correction

`completion/u08.rs::apply_atleast_rule` now follows the Konclude call chain
directly:

- It creates the `ATLEAST` dependency and passes that dependency to every new
  successor.
- It passes the complete signed indirect-super-role list. A defensive
  reflexive insertion preserves Konclude's preprocessed role-list invariant for
  hand-built and strict-super-only inputs.
- It calls the full `create_distinct_successor_individuals` implementation, so
  saturation replay occurs before link installation and qualifier insertion.
- It propagates pending clash signals before queueing, marks low-level nominal
  successors for extended processing, and queues each completed successor.

The final subject trace has 19 successor expansions, including successors 1001
through 1006. Disjunction replacement events fall from 72,670 in the old
51-second trace to 300 over the complete successful run. Subject 85031 now
finishes in 14.66 seconds at about 1.65 GiB.

## Supporting Konclude ports retained from the investigation

Several exact ports were needed to make the tail measurable and to reproduce
Konclude's completion lifecycle. They improved time or memory but did not close
14817 until the cardinality constructor changed:

- A live ontology-wide `CSatisfiableExpanderCacheHandler` port now persists
  across per-subject completion contexts. It writes signature transitions and
  satisfiable entries, tracks deterministic and branched dependencies, reads
  cached suffixes, checks ancestor/cardinality compatibility, and propagates
  cached blocking flags.
- Per-node `CIndividualNodeSatisfiableExpandingCacheStoringData` records the
  last cached descriptor and signature. Label signatures now include the stable
  concept identity corresponding to Konclude's `CConcept*` contribution.
- The synchronous bridge reproduces Konclude's 80-rule task-yield boundary and
  commits both completion caches at each yield and branch return.
- Cache slot release drops the complete retired pool payload, matching
  Konclude's memory-pool lifetime instead of retaining ontology-wide signature
  maps through unreachable arena entries.
- KPSet saturation scheduling follows Konclude's touched-candidate queue before
  choosing another arbitrary cycle breaker.

These ports reduced the former approximately 16 GiB isolated-tail peak and let
the full run advance to its last subjects, but the pre-fix binary still timed
out. The direct `applyATLEASTRule` comparison identified the closing change.

## Permanent validation

The focused test
`at_least_replays_saturation_label_to_every_created_successor` drives the
production `apply_atleast_rule`. It constructs `≥2 R.C`, gives `C` a completed
saturation node containing an additional concept `D`, and checks that both
distinct successors contain the explicit qualifier and saturation-only `D`.
The former reduced helper fails this test.

The complete `ws` release suite passes 1,480 tests, ignores 7, and fails none.
IBEX full-sweep job 48853569 reports:

|---|---:|---:|
| completed | 574 | 575 |

| incomplete | 45 | 45 |

The change affects the Konclude-compatible completion implementation and its
cache lifecycle. It does not alter the CB calculus, its rule set, or its
fixpoint, so it does not require Lean re-certification.
