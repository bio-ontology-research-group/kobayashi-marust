# Certified inconsistency (v1.7.0, task inc1)

Branch `v170/inconsistency`. KM answers "inconsistent" on 46 pool inputs
(`scratch/h3/inconsistent_46.tsv`); Konclude or HermiT agree, but until now no
proved checker confirmed any of them. The hint route cannot (a hint is a
model), and the complete proved routes decline these inputs or run past
300 s. This note describes a refutation certificate, its proved checker and
its producer.

## 1. What is proved

`lean/ContextCalculus/SRIQN/Refute.lean` (checker) and
`lean/ContextCalculus/OWLFrontend/RefuteRoute.lean` (OWL route):

```
theorem refute_sound {Θ} {emp} (hne : ∀ V atom, Θ V atom → Nonempty V)
    (hemp : ∀ V atom, Θ V atom → ∀ L, emp L = true → ∀ v, ¬ ∀ l ∈ L, litSem atom l v)
    {O : DOntology (Fin n) (Fin m) (Fin p) (Fin q)} {pf : Proof}
    (h : refute O emp pf = true) : ¬ ConsistentDN Θ O

theorem refuteP_sound (pat : String → String → Prop) {O : Ontology} {pf : SRIQN.Refute.Proof}
    (h : refuteP O pf = true) : ¬ ConsistentAt (owl2MapP pat) O

theorem refutePR_sound (pat : String → String → Prop) {R : OntologyR} {pf : SRIQN.Refute.Proof}
    (h : refutePR R pf = true) (bi : BuiltIns (owl2MapP pat)) :
    ¬ ConsistentAtR (owl2MapP pat) bi R
```

`refuteP_sound` holds for every reading `pat` of `xsd:pattern`;
`refutePR_sound` (an ontology with DL-safe rules) also for every reading of
the built-ins. `refute_sound`, `refuteP_sound`, `refutePR_sound`,
`refuteChain_sound`, `empOWL_sound` and `model_refuteWeaken` print
`[propext, Classical.choice, Quot.sound]` under `#print axioms` (build logs
`scratch/inc1/build17.log`, `build4.log`). No `sorry`, no `native_decide`, no
new axiom.

The executable `km-owl-reference --procedure refute --cert FILE ONT` prints
`{"format":"owl-refute-v1","consistent":false,"certified":true}` only through
`publishRefuted` (which takes a proof of `refuteP O pf = true`) or
`publishRefutedR` (a proof of `refutePR R pf = true`; the line then also
carries `"rules":"dropped"`). Any other outcome is a decline with exit code
3 (`--explain` names the first failing step).

## 2. The route

`refuteP O pf`:

1. **Preparation** (`refuteStage`): datatype definitions unfolded, disjoint
   unions rewritten, keys dropped (`dropKeys`), anonymous individuals
   renamed. The renaming preserves consistency only without keys
   (`consistentAt_anonOff`), which is why the keys go first.
2. **Weakening** (`refuteWeaken`): keep the axioms of the chain-route
   fragment (`Axiom.isSROIQDKB`); drop the rest (`DisjointObjectProperties`,
   `AsymmetricObjectProperty`, reflexive and irreflexive properties, ...).
   Every model of an ontology is a model of the kept axioms
   (`model_refuteWeaken`, `model_dropKeys`), so a refutation of the kept
   axioms refutes the input (`consistentAt_refutePrep`, one direction). A
   refutation needs only this direction, which is why the route can drop
   axioms while the hint route has to strengthen them. Weakening happens
   after the renaming: before it, every assertion on an anonymous individual
   would fail the fragment test (ore_ont_1123 lost 43,892 class assertions
   that way in an intermediate version).
   An ontology with DL-safe rules (`OWL.parse` rejects it, `OWL.parseR`
   reads it) is read without its rules (`refutePR`): a model with rules
   satisfies the other axioms for every reading of the built-ins.
3. **Translation**: the chain-route translation `dosnC` of the SROIQ(D)
   knowledge base, an `SRIQN` data ontology (clauses `dbase`, nominal names
   `dnoms`), with `sroiq_consistent`: the input is consistent at the OWL 2
   datatype map iff `dosnC` is consistent in the OWL 2 data theory. Only the
   left-to-right direction is used. The route checks no regularity, chain
   elimination or C2a condition: role chains are used as clauses, not
   eliminated.
4. **Check**: `SRIQN.Refute.refute (dosnC …) emp pf` with the data oracle
   `empOWL` (section 4).

## 3. The certificate

A certificate names finitely many elements of a would-be model (object
elements and data values share one index space, fresh indices increase) and
derives facts about them, one ground rule instance per step. A step cites a
clause by its index in `dbase` and earlier facts by line number; the checker
computes the conclusion and appends it. Facts: `c x a`, `r x k y`, `eq x y`,
`ne x y`, `d x u w` (data property), `lit w j b` (data atom `j` holds at
value `w` iff `b`), `veq`, `vne`.

| step | rule |
|---|---|
| `nom X A` | `X` (fresh) is the element of the nominal `A` |
| `gci CI X REFS` | `⊓body ⊑ ⊔head` at `X`; the head is one line (a disjunction if it has several atoms) |
| `ex CI X REF Y` | `A ⊑ ∃R.B` at `X`, fresh successor `Y` |
| `exnom CI X Y REF REFY` | `A ⊑ ∃R.{b}`: the successor is the element `Y` of the nominal |
| `all CI X Y REF REFR` | `A ⊑ ∀R.B` |
| `chain CI K X0..XK R1..RK` | `R1 ∘ … ∘ RK ⊑ S` along a cited path |
| `atmost CI X REF T (Y RR RC)*T` | `A ⊑ ≤k R.B` with `k+1` cited successors: a disjunction of equalities |
| `nomeq A X Y REF1 REF2` | two elements of one nominal are equal |
| `eqsym`, `eqrw REFEQ REF` | equality: symmetry, rewriting a fact |
| `dex CI X REF W` | `A ⊑ ∃u.(pos, neg)`, fresh value `W` with its literals |
| `dall CI X W REF REFD` | `A ⊑ ∀u.(head)` at value `W` |
| `datmost CI X REF T (W RD NL L*)*T` | data at-most: a disjunction of value equalities |
| `dsub CI X W REFD` | `u ⊑ v` |
| `veqsym`, `veqrw` | value equality |
| `dlit W J B REFS` | the cited literals of `W` entail `(J, B)`: the oracle declares them empty together with `(J, ¬B)` |
| `litem W J` | excluded middle on one atom |

A proof is a tree in prefix order: steps, then `close …` or `split REF` with
a left and a right subproof. `split` on a disjunction line `f ∨ rest` adds
`f` on the left and the line `rest` on the right. Leaves: `close empty REF`
(an empty disjunction), `close ne X Y R1 R2`, `close vne W W' R1 R2`,
`close lits W REFS` (the oracle declares the cited literals of `W` empty).
Lines starting with `c` are comments. The checker does no search.

Soundness (`check_sound`): the invariant `Good` says that every line holds
under assignments `e`, `ev` of the indices to a model and that every index
is below the bound `next`. Each step extends the assignments only at fresh
indices (`stepOut_sound`), so the old lines keep holding; a split keeps the
invariant on the branch whose fact holds; every leaf contradicts it.

## 4. The data oracle

`empOWL spec L` is true when every atom of the translation is supported
(`drSupported`) and no cell of `cellsOf (allBases spec)` satisfies all
literals of `L` under any reading of the free datatypes. `empOWL_sound`
derives this from `owlTheory_iff`, the cell characterisation of the OWL 2
data theory that the hint and C2a routes already use; no new datatype
reasoning was added. A literal set that needs reasoning outside the
supported sub-theory gets no `close lits`; such an input stays open.

The route computes the cells once per run (`empWith` with the cells bound
before the check). Before this change the cells were recomputed at every
oracle call.

## 5. Choice of design

* The brief prefers a resolution-style derivation over the frontend
  clauses. This is that derivation, specialised to the clause shapes of
  `SRIQD.Clause` (ground hyper-resolution and unit propagation instances
  over named and fresh elements, with equality and data values), so each
  step is checked by one clause match and table lookups.
* No existing proved replay checker fitted: the EL and CB certificate
  checkers prove subsumptions in their own calculi, and the hint checkers
  check models. The new checker reuses the frontend translation, its
  correctness theorem `sroiq_consistent` and the datatype cell theory.
* The producer is a separate untrusted Python tool (`tools/refute/produce.py`)
  rather than a KM engine change: KM's tableau trace does not name frontend
  clause indices, and deriving certificates from it would need engine work
  with no checked benefit. No engine code changed.

## 6. Producer

`tools/refute/produce.py DUMP --out CERT --oracle BIN --ofn ONT [--focus IRI]`
reads the clause dump of `--procedure refute --print-clauses` and writes a
certificate. Its own verdicts are unchecked; only the checker's acceptance
counts. Phases, each with oracle rounds:

1. Horn rounds over all named individuals (no anonymous successors, no
   splits) with a growing budget of agenda steps (20,000, 200,000), so a
   local clash in a large ABox shows up early.
2. Local mode: one individual at a time (first the individuals of KM's
   justification, `--focus`; then one per group of told classes), with
   anonymous successors up to depth 3, the definitional splits `⊤ ⊑ A ⊔ B`
   of the translation at that element, and case splits chosen by a
   one-level lookahead (the disjunction with the most alternatives that
   close by saturation alone).
3. Horn saturation without a budget, then the global search (iterative
   deepening of successors, case splits).

Data: the producer keeps one oracle process,
`km-owl-reference --procedure refute --emp - ONT`, which parses and
translates the ontology once and answers literal sets (`J B J B ...`, one
per line) with the checker's own `empWith`. It asks the literal sets of
values (possible `close lits` leaves) before entailment queries (`dlit`
steps), larger sets first, in growing batches, and stops at the first
empty set. The producer never decides a data clash itself.
