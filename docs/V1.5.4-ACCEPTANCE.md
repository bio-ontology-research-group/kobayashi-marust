# v1.5.4 acceptance contract: general routing

Status: thresholds approved by the maintainer on 2026-10-26: no held-out
coverage loss, at most 10 % slowdown, 0.5 % admission floor.

## Goal

Replace the v1.5.3 automatic router with a policy in which every decision
follows from the logic of the input or from a stated resource model, and
which, by construction and by test, is not fitted to known ontologies.

## Why

The v1.5.3 router (`engine/src/routing.rs`, 6,413 lines) makes its real
decisions with hand-written predicates over source counts. Many thresholds
were measured on the ORE 592 sample. Some are two-sided bands that admit a
single benchmark ontology:

| Predicate (`compact_normalized_ht_bridge_candidate`) | ORE-592 ontologies admitted |
|---|---|
| `narrow_existential_hierarchy` (1,500-1,800 axioms, 600-750 classes, ...) | 1 (5940) |
| `role_dense_existentials` | 1 (5404) |
| `broad_named_hierarchy` | 1 (13444) |
| `compact_functional_universal` | 1 (541) |
| `compact_role_schema_shif` | 1 (3231) |
| `compact_horn_shi` | 3 |
| `compact_qualified` | 2 |

Computed from `results/benchmarks/2026-07-15-routing/profile-table.csv`.
These predicates contain no identifier, but they act as fingerprints. The
existing identity tests only search predicate bodies for the string
`ore_ont_`, so they cannot detect such a band.

Two further defects make some conditions meaningless:

- The routing flags `expressivity.inverse` and `expressivity.transitivity`
  reproduce Konclude's post-preprocessing defaults. Inverse is always true,
  and transitivity is true unless complex role inclusions occur.
- `profile.clauses.*` is zero at routing time, so every clause-count
  conjunct holds vacuously, while `km profile` reports a different route.

Finally, the "learned tree" `routing_tree_generated.rs` is a constant, and
`km routes` mislabels it.

## Requirements

### G1. Admissible routing evidence

A routing condition may test only:

1. **Semantic fragment membership.** This includes the existing fragment
   gate (rules, native bridge ABox, certified positive ABox,
   ABox/nominal, core), exact syntactic screens (pure EL, Horn), and the
   source-level certificates (positive-ABox separation, role separation for
   cardinality). Each must state the theorem or argument that makes it a
   fragment test.
2. **Construct presence**, as Boolean facts read from the source: for
   example, inverse roles, number restrictions, nominals, transitivity,
   complex role inclusions, datatypes, disjunction, and negation.
3. **Size, only for resource decisions.** Examples are in-process versus
   worker execution, thread counts, memory caps, and whether a quotient or
   scanner pays off. Each threshold must:
   - be one-sided and monotone;
   - be derived from a stated resource model;
   - be the only threshold for that resource;
   - never be what chooses which reasoning procedure answers.

Forbidden:

- two-sided intervals on counts;
- conjunctions of numeric thresholds that select a procedure;
- equality tests on counts;
- thresholds introduced to make a named input pass;
- ontology identifiers;
- any condition that reads clause statistics before they exist.

### G2. Uncertainty goes to the portfolio

Sometimes construct and fragment facts cannot tell which complete procedure
will be fastest. In that case the router selects a portfolio that races
complete procedures. It does not guess.

### G3. Correct inputs to the router

- Routing uses source-derived inverse and transitivity flags. Konclude's
  preprocessing defaults remain only for the reported expressivity code.
- `km profile` and `km classify` select the same route for the same file.
  A test enforces this.

### G4. Admission floor

On the 1,708 admitted inputs of the ORE 2015 pool, every rule that selects a
non-default procedure on grounds other than semantic necessity must admit at
least **0.5 %, i.e. 9 inputs**. Otherwise the rule is merged into a
broader rule or removed. The release records the admission count of every
rule.

**Amendment of 2026-10-27, approved by the maintainer.** Rules whose
condition is a proved source certificate are exempt from the floor, like the
semantic gates. Count bands remain forbidden. This keeps the two cardinality
role-separation certificates, which admit two pool inputs each; without them
the design input ore_ont_7499 times out.

**Amendment of 2026-10-28, approved by the maintainer.** An input counts as
solved by v1.5.3 only if v1.5.3's answer was justified. v1.5.3 published
`DROPPED 0` for inputs whose positive data-property assertions it silently
discarded; v1.5.4 carries such assertions exactly where it can (the
conversion under the literal cap, and the profile abstraction of
`docs/DATA-ASSERTION-PROFILES.md` above it) and otherwise reports the
uncarried ones in `DROPPED`. An input that v1.5.4 answers with the same
taxonomy as gold while reporting `DROPPED > 0`, and that v1.5.3 answered by
discarding those assertions, is not a coverage loss under G1 or G8. The
release notes list each such input with its dropped count. On the design
half these are ore_ont_10425, 15655, 4410, 4572 and 5368: each combines data
counting (`FunctionalDataProperty` or a data maximum) with constructs that
can identify individuals, so the profile abstraction is inexact for them, and
an exact encoding with one ground individual per value (measured with a
bit-code prototype) does not classify them within 900 s. Native data-value
reasoning in the nominal CB is scheduled for v1.5.5.

### G5. Metamorphic stability tests

Unit and corpus tests must show the route is unchanged under:

- IRI renaming;
- adding or removing annotations and declarations;
- reordering axioms;
- duplicating an axiom;
- adding an unrelated tautology.

Under the disjoint union of an ontology with a renamed copy of itself, only
a G1.3 resource decision may change.

### G6. Held-out evaluation

The pool is split by a stable content hash (SHA-256 of the file, even/odd)
into two halves:

- **Design half:** the ORE 592 sample plus the even-hash pool inputs.
- **Held-out half:** the odd-hash pool inputs not in the 592 sample.

Rules:

- Every measured choice (portfolio composition, resource thresholds) is made
  on the design half only.
- The held-out half is run once, on the frozen release candidate.
- The report gives both halves, and acceptance is judged on the held-out
  half.

### G7. Correctness

- Zero wrong answers against the four references on both halves.
- Every specialist remains complete-answer-or-defer.
- Every fallback is counted.

### G8. Performance

Compared with v1.5.3 on the held-out half, on the same Ibex node type and
under the v1.5.3 protocol (one core, 240 s, 20 GiB, PGO build, scoped
watchdog):

- verified inputs ≥ v1.5.3 (no loss);
- mean and median time on common inputs ≤ v1.5.3 × 1.10;
- still more verified inputs than Konclude, and faster than Konclude in mean
  and median time on common inputs.

### G9. Release gates

- Full Rust and Java test suites pass.
- All four Lean gates pass from the exact tag, as for every full release.
- Routing is part of the Lean publication boundary, so a change to the
  routing publication relation requires that relation to be re-certified.

### G10. Documentation

- The route glossary and the paper's routing tables are regenerated from
  the new code.
- `km routes` describes the policy accurately.
- The release notes list every removed predicate together with the input
  whose time changed most because of it.

## Plan

1. **Inventory.** Classify every `select` predicate, conductor probe, and
   schedule override in v1.5.3 as semantic, construct, resource, or
   fitted, and record its 592 and pool admission counts. Add a
   `km profile --explain` mode that lists all matching rules.
2. **Router.** Replace the predicate cascade with a declarative rule table:
   - the fragment gate;
   - construct and certificate rules;
   - resource rules;
   - the portfolio as the default.

   Remove the fitted predicates. Fix the routing flags and the
   clause-statistics vacuity.
3. **Tests.** G3, G5, and the admission audit as CI tests.
4. **Design-half evaluation** on Ibex. Tune only portfolio composition and
   resource thresholds.
5. **Freeze; held-out evaluation once; release gates; documentation.**
