### 2.4 Model existence from a clash-free ground set (equality, nominals, counting, chains)

Source language `Eqv.OClause` (`CompletenessEq.lean:91-102`):

```lean

  | gci (body head : List CN) | exR (a : CN) (r : RN) (b : CN) | allR (a : CN) (r : RN) (b : CN)
  | exL (r : RN) (d c : CN) | subR (r s : RN) | inv (r s : RN) | func (r : RN)
  | nom (a : CN) (o : T) | atMost (n : ℕ) (r : RN) (c : CN)
```

plus (`CBRoleChainEncoding.lean:17-48`) `RoleChain` (arbitrary body list, no regularity), `RoleAxiom`
(`symmetric`, `asymmetric`, `reflexive`, `irreflexive`, `inverseFunctional`, `disjoint`), and
`SourceOntology` bundling `clauses`, `chains`, `roleAxioms`.

The central theorems:


Context: `[Fintype T] [Fintype CN] [Fintype RN]`, `T` is a finite carrier supplied by the caller, `wit`
and `minWit` are the supplied Skolem witness maps. The proof builds the congruence quotient of the
propositional model (`congruenceModel_models` :269, `respectsEq_of_grounds` :466). It handles number

`atMostHead`. The file header (:39-41) still says that step is "not unfolded here"; that text is stale
(section 8).

Direction: these theorems say "clash-free finite ground set implies a model". They are about an
abstract closure (`PropRes.Derivable`) and say nothing about how `T` and `wit` are chosen. The converse
needed for a total procedure (a satisfiable source has some finite `T`, `wit` whose grounding is
clash-free) is not in the tree. It also cannot hold for arbitrary `(T, wit)` (section 7.1).

`CBEqEncoding.lean` and `CBRoleChainEncoding.lean` prove the source-to-nested-term encoding exact:
`CBRoleChainEncoding.lean:314` `entailsSub_iff_source`, `:348` `satisfiable_iff_source`,
`CBEqEncoding.lean:1016` `entailsSub_iff_source` and `:1051` `satisfiable_iff_source`.

### 2.5 Production-calculus completeness (the CB engine's own rules)

All of these take a *decoded document* (the Rust engine's terminal state, serialised, then checked in
Lean). None is an executable saturation.

- `CBSourceEqualityFreeCompleteness.lean:132` `SourceProductionClosed.ordered_candidate_source_instance_eqFree`,
  `:174` `context_source_instances_eqFree`, `:203` `DecodedSourceCanonicalClosureDocument.all_context_source_instances_eqFree`.
  Hypotheses: `closed : SourceProductionClosed decoded` (an accepted production-closure document), a
  retained context `context` with `PropRes.PClause.bot ∉ rawSet context.retained`, `EqFree` for every
  source clause and every retained clause, a computed linear extension of the literal order. Conclusion:
  `ContextCalculus.sat (OrdRes.Itrue (rawSet context.retained)) (substCl substitution sourceClause)`
  for every source clause and every substitution in `CBHyperClosure.substitutions orderedTerms`. So the
  ordered candidate valuation satisfies every source instance over the finite ordered term set.
  Language: equality-free (`EqFree`: no `eq`/`ineq` literal in source or retained clauses), nested
  Skolem terms allowed, no nominals, no counting. It does not conclude that a model of the source
  exists and does not conclude any `Entails` equivalence (the valuation covers the finite term set only).
- `CBSourceEqualityCanonicalModel.lean` (1,532 lines). Last theorem `:1453`
  `productiveGroundValuation_of_Itrue_positive`. It proves well-founded, directly joinable productive
  rewriting (`productiveEqualityRewrite_wellFounded` :304, `productiveClassRewrite_directlyJoinable` :386),
  unique class normal forms (:475, :542), builds `productiveQuotientModel`, and shows the congruence
  closure keeps every positive atom of the candidate valuation true. It contains no theorem that the
  quotient satisfies every source instance (the equality analogue of `all_context_source_instances_eqFree`)
  and no theorem that links to a model of the source. Only `ContextCalculus.lean` imports it.
- `CBSourceGroundResolutionBridge.lean:517`
  `SourceProductionClosed.ordered_candidate_source_instance_or_tautology`: each source instance is
  satisfied or its raw Hyper conclusion is a rejected equality tautology (the dichotomy used by the
  equality-free theorem).
- `CBCertificationSurface.lean:87` `certifiedCBClashFreeGlobalProductionModel`: for an accepted
  `WireCBGlobalModelDocument`, the global closure holds and, if `PropRes.PClause.bot ∉
  decoded.blocked.certificate.terminal`, there is a nonempty `TModel D` satisfying every clause of the
  production source. The finite blocked carrier, the witness table and the terminal saturation are
  *supplied by the document* and checked (`CBBlockedCarrierWire.lean`, `CBBlockedGroundSaturationWire.lean`).

- `CBCertificationSurface.lean:112,:340,:361,:382` `certifiedCB*ExactTaxonomyPublication`: an accepted

### 2.6 Termination and finiteness

- `Termination.lean`: `branch_depth_bound` (:51), `no_infinite_branch` (:57), `reachable_finite` (:63),
  instance `Fintype (blockedUniverse CN)` (:86), `context_branch_bound` (:91):
  `BlockedBranch br → br.length ≤ 2 ^ Fintype.card CN`. The header (:6-9, :30-34) says explicitly that it
  does not prove that blocking preserves models, that production contexts are branches of this universe,
  or that production saturation terminates.
- `CBTerminalStateWire.lean`: checks operational terminal conditions of a run (empty queues, watermarks);
  it "does not infer closure merely from process termination".
- `CompletenessStrategy.exists_fixed` (:210) and `SRI.Proc.saturate`/`eliminate` (`SRI/Procedure.lean:139`,
  `:166`) terminate by a finite-universe counting measure (`(Finset.univ \ G).card`, `G.card`). These

- `HypertableauTermination.lean` and `HypertableauRoleBlocking.lean`: finiteness of the blocked node
  universe, of equality and role-sensitive blocking signatures, branch-update finiteness. They do not
  bound a concrete executable search.

Answer to "is there any termination or finiteness proof for a CB saturation": no, for the production
FCL calculus on any fragment. There are finiteness proofs for the abstract core-branch universe, for
type elimination, and for the seed-keyed SRI saturation.

## 3. Clause languages: CB formalisation versus `SRI.Clause`

| Feature | `Eqv.OClause` + `RoleChain` + `RoleAxiom` (source-level CB) | `CheckerTerm.FCL` (production CB) | `SRI.Clause` (`SRI/NormalForm.lean:43`) |
|---|---|---|---|
| Atom/term type | concept names `CN`, role names `RN`, individual type `T` | `FTerm` = `var Int | const Nat | app Nat FTerm` (`CheckerTerm.lean:44`), `FLit` = `P (concept/role) | eq | ineq` (:57) | concept names `Fin n`, `RoleT` = `pos r | inv r` (`NormalForm.lean:29`) |
| Disjunctive GCI | `gci body head` | `Clause FLit` (body, head lists) | `gci body head` |
| `a ⊑ ∃R.b` | `exR a r b` | Skolem terms `app f x` | `exRight a R b` (R a role term) |
| `a ⊑ ∀R.b` | `allR a r b` | clause | `allRight a R b` |
| `∃R.d ⊑ c` | `exL r d c` | clause | no constructor; written `d ⊑ ∀R⁻.c` (`allRight d R.flip c`) |
| Role inclusion | `subR r s` (names only) | clause | `chain [R] S` with role terms |
| Inverse roles | axiom `inv r s` between role *names*; not usable inside `exR`/`allR` | bridge clauses | `RoleT.inv` inside every role position |
| Role chains | `RoleChain {body, sup}` of any length, names only | `encodeChain` (`CBRoleChainEncoding.lean:78`) | `chain body S`, any length in the type; the procedure needs `IsALCHI` (length 1) after `encTrans` |
| Transitivity | the chain `R ∘ R ⊑ R` (`satChain_transitiveChain_iff`) | clause | chain `[R,R] R`; removed by `encTrans` (`SRI/Transitivity.lean:52`) |
| Equality / functionality | `func r`, `nom`, quotient model; `eq` atoms in ground set | `eq`/`ineq` literals | none |
| Nominals | `nom a o` (`a ≡ {o}`) | constants `const` | none |
| Counting | `atMost n r c`, `guardedAtMost a n r c`, `guardedAtLeast a n r c` | clauses over `eq`/`ineq` | none |
| Role axioms | `symmetric`, `asymmetric`, `reflexive`, `irreflexive`, `inverseFunctional`, `disjoint`; `func` | clauses | symmetry as `chain [R] R.flip`; none of the others |
| Self restriction | none | none | none |
| ABox | none directly; expressible as nominal clauses | none | none |
| Datatypes, keys, rules | none | none | none |

Net: source-level CB covers SROIQ minus Self, minus datatypes, with ABox only via nominals. The inverse
role is weaker there than in `SRI` (an axiom between names, not a term constructor). `SRI.Clause` covers
ALCHI plus transitivity (and symmetry), with arbitrary chains representable in the type but declined by
the procedure.

  Parallel theorems exist for the equality (:805, :1771), cardinality (:1131) and native-ABox (:1525)
  families (`CheckedRegularControlAttempt`-style producers).
- No `def` or `instance` of any of these producer or family types exists; the search functions are
  `noncomputable` (classical choice over finite data). `frontierAddress`, the proof that a concrete
  blocker never exhausts the node universe in a way the checked rooted address cannot describe, is a
  hypothesis; nothing in `lean/` proves it for a concrete blocker. Equality-aware and cardinality-aware
  blockers have the same status.
- HT-to-CB bridges: `CBRegularALCCountermodel`, `CBRegularRoleCountermodel`,
  `CBRegularNominalCountermodel`, `CBRegularCardinalityCountermodel`,

  `SafeSource`, arbitrary chains via a binary decomposition, `CBRoleChainCanonicalBinary.lean`) turn a

## 7. Assessment (my judgment, not a fact from the files)

### 7.1 One finding that changes how route (a) reads

The existing ground theorems (`herbrand_complete_ground`, `source_complete_ground*`) prove "clash-free
grounding over a given finite `(T, wit)` implies a model". They give completeness of a ground procedure
only if the grounding is sound, that is, only if `Derivable (ground ...) ⊥` implies the source is
unsatisfiable. That soundness holds for the nested-term Herbrand universe, but not for an arbitrary
finite carrier with a cyclic `wit`. Example: `A ⊑ ∃r.A`, `⊤ ⊑ ≤1 r⁻.⊤`, a nominal `o ∈ A` with no
`r`-predecessor. It is satisfiable only in an infinite model (a chain from `o`). Any finite `T` with
`wit` forces a cycle, the functionality of `r⁻` merges nodes, and the grounding derives `⊥`. The repo
says the same thing about full SROIQ lacking the finite-model property
(`CBLiveExactTaxonomyPublication.lean:22`). So a finite-carrier ground procedure cannot be both sound
and total for SROIQ. The CB route needs a proof at the level of *contexts with unravelling* (the
Sequoia-style model construction), not of a flat finite grounding. This is why the repo's CB publication
uses derivations for positive cells and countermodels for negative cells: the finite ground set is used
only on the model-existence side. This finding rests on my reading and on the counterexample above; the
survey `docs/history/SURVEY-HT-CB-COMPLETENESS-2026-11-09.md` (B1, last paragraph) reaches the same point.

### 7.2 Route (a): finish CB completeness for the full clause language plus termination

Reusable: propositional, ordered and exchange completeness (section 2.2); rule soundness including Nom
(`Basic`, `Nominals`); the exact source encodings (`CBEqEncoding`, `CBRoleChainEncoding`); the finite
quotient model construction for equality, nominals, counting, chains and all role axioms but Self
(`CompletenessEq`, `CBRoleChainGroundCompleteness`, 1,941 lines), which becomes the model-side step once a
finite carrier is justified; the equality-free per-context candidate model and 1,532 lines of
equality-orientation and normal-form infrastructure.

Not reusable as is: the `CB*Wire` stack (39 `CB*Wire.lean` files among 94 `CB*.lean` files). It checks a *Rust-produced document*; an
executable Lean saturation would need its own state, and the repurposable parts are the one-step
enumerators (`CBHyperClosure.substitutions`, `CBLocalEqEnumeration`, `CBPredEnumeration`).

Three hardest missing lemmas:
1. The context-structure canonical model: a saturated finite context structure (cores, Succ/Pred/r-Pred
   exchange with context-specific orders, ground nominal context) yields a model of the whole source by
   unravelling, with equality quotient. Today the equality-free case stops at "candidate valuation
   satisfies instances over the finite ordered term set", and the equality case stops before the
   instances (section 2.5).
2. Termination of an executable saturation with the Nom rule, paramodulation and counting (fresh nominal
   allocation, Eq and Factor growth). `Termination.lean` supplies only a depth bound on an abstract
   duplicate-free core list.
3. Completeness for non-finite-model-property inputs: blocking (or unravelling) that preserves
   satisfiability when inverse roles, nominals and counting force infinite models, plus the OWL 2
   regularity condition and automaton encoding (absent from Lean) for general chains, Self, and the
   simple-role side conditions.

Note: the V1.7.0 plan (section 4.1) calls the CB calculus "complete for SROIQ in the literature". The
repo's own files cite it for ALCHOIQ (`Nominals.lean:4`, `CompletenessEL.lean:26`), so Self, regular
chains and the other role axioms would be extensions of the published result, not citations of it. I
could not check the paper from the tree; confirm against the paper before relying on the claim.

### 7.3 Route (b): extend the SRI type-based procedure with counting and nominals

Reusable (the only end-to-end Lean chain from OWL text to a proved complete answer, for SHI): the OWL
parser, semantics, names and fragment predicates; the structural-transformation translator with polarity
and its correctness framework (`SRITranslate*`, 2,123 lines; new constructors add cases to induction
proofs); `SRI.Clause`/`models`/`EntailsSub`; `GoodTypes` (types, `Compat`, canonical model); `Abstract`
(rule-closed/elimination interface that lets any faster computation inherit exactness); the unravelling
completeness proof (`Completeness.lean`); the executable fast procedure and its indexes (`Fast.lean`);
`encTrans` for transitivity; the reference-answer plumbing (`SRIReference`, `ReferenceSHI`,
`km-owl-reference`); and a measured production rate for proofs of this shape (section 6). Termination is
already settled by a finite record universe. The procedure is a CB-style seed-keyed saturation, so it
also shares vocabulary with the CB engine.

Three hardest missing lemmas:
1. Counting-aware good types and the elimination/unravelling argument. `Compat` is edge-local today.
   `≤n R.C` with inverse roles constrains the number of neighbours from both sides, so a type needs
   multiplicities (a mosaic or a bounded-multiplicity abstraction, or an arithmetic side condition) and
   the "model gives good types / good types give a model" pair must be redone. `SHIQ` lacks the finite
   model property (background knowledge, not checked in the tree), so the canonical model of the good
   types is not finite in general.
2. Nominals: the tree-shaped unravelling of `Completeness.lean` (`Dm` paths from one root) breaks. The
   model is a finite named part plus trees, and nominal individuals interact with counting through the
   "new nominal" guess (the Nom rule or the SHOIQ tableau's NN-rule). The statement of `Good` needs a
   named-individual component.
3. The regular role chain automaton encoding and the other role axioms (irreflexive, asymmetric,
   disjoint, inverse-functional, reflexive, Self): `encTrans_correct` is the only reduction of this kind
   in Lean, and it covers `[R,R] ⊑ R`. General regular chains need the automaton construction with a
   closure-induction lemma (the V1.6.2 plan section 5 sketches it).

### 7.4 Route (c): a tableau with blocking

Reusable: `Hypertableau.lean` (state, canonical model, `Refutes` soundness, 514 lines);
`HypertableauUnravelling.lean` (1,347 lines: regular unravelling with role rules for subroles, inverses,
chains, reflexive roles and cardinality definitions, `redirect`-based witness completeness);
role-sensitive and equality-aware blocking signatures with finiteness bounds; the finite search totality
theorems (`finite_guarded_fact_ht_complete`); the HT-to-CB countermodel bridges for nominals,
cardinalities and chains; equality, cardinality and native-ABox variants. It is the largest body of
material (about 71k lines) and the only one that states blocking and unravelling for inverses, chains
and counting together.

Not reusable as is: it is organised around checking supplied certificates. The search is
`noncomputable`, the producer families are never constructed, the soundness of a concrete blocker
(`frontierAddress`, and the equality-aware "sound fold refinement") is hypothesised, and the clause
language is guarded hypertableau clauses rather than OWL.

Three hardest missing lemmas:
1. Soundness of a concrete pairwise (and equality-aware) blocker: any complete clash-free blocked graph
   unravels to a model, with the fold satisfying `FoldPreservesLocalFacts` and the cover conditions for
   inverses, counting and nominals. Today these are hypotheses.
2. An executable search with a termination proof: build the producer, prove `frontierAddress` for it,
   and handle the new-nominal rule and merge/choose rules with counting. The survey estimates about 2,000
   new lines for the equality-free regular case alone.
3. Completeness of the search: every satisfiable input has some branch that reaches a clash-free
   terminal (the "model implies a run exists" direction, including nondeterministic choice and the
   number of new nominals), and the same regularity/automaton reduction for general chains.

### 7.5 Which has the most reusable material

By pipeline and proof method: route (b) (everything from OWL text to a proved answer already exists for
SHI, and the SHI chapter took roughly a day with agents). By volume of semantic material on the hard
features (inverses, chains, counting, nominals, unravelling): route (c). By the closeness of the clause
language to the target: route (a) (`OClause` + `RoleChain` + `RoleAxiom` is SROIQ minus Self already, with
exact encodings and a proved model-existence theorem), but its missing core (lemma 1 above) is the least
supported, because the existing completeness theorems are model-existence for a supplied carrier and
equality-free per-context statements.

My ranking for a Lean-executable total reference procedure on SROIQ: (b) first for reuse, with its model
side borrowing the unravelling statements of (c); (a) third, because its reusable half is the ground
quotient model, which on its own cannot certify completeness of any finite-carrier procedure (7.1).
All three share the same unproved hardest step: a finite abstraction (types with multiplicities, a
context structure, or a blocked completion graph) that is satisfiable exactly when the input is, in the
presence of inverse roles, nominals and counting. The OWL 2 regularity/automaton reduction and the Self,
irreflexive, asymmetric and disjoint role axioms are missing from Lean for every route and can be done
once, as a pre-reduction to a normal form, independent of the route.

   "the full NExpTime feature set". The theorem is model-existence from clash-freedom of a supplied

4. `docs/V1.7.0-PLAN.md` section 4.1 describes the CB calculus as "complete for SROIQ in the literature".
   Repo files say ALCHOIQ (7.2).
5. `docs/V1.6.3-HT-PLAN.md` section 2a says `CBSourceEqualityFreeCompleteness` concludes only that each
