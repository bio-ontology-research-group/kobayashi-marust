# ORE 16303: a vacuous universal-role inclusion kept a typed object ABox on eager nominal CB

Date: 2026-09-02. Status: proposed patch on branch `agent/v14-16303`,
written without building or measuring (see "Tests to run"). Nothing in this
change touches a calculus, a worker, or the clause output; it changes which
already-validated exact route the automatic selector chooses for one source
feature.

## Symptom

| Measurement | Value |

| Wall, 2026-08-14 sweep | 4.0688 s |

## The ontology, as features

The source is a QL approximation of OBI. Its profile (schema-1 table
`results/benchmarks/2026-07-15-routing/profile-table.csv`) is:

- 8,622 logical axioms: 8,248 `SubClassOf`, 42 `InverseObjectProperties`,
  147 `SubObjectPropertyOf`, 185 ABox axioms (163 `ClassAssertion` on named
  classes, 20 `ObjectPropertyAssertion`, 2 `DifferentIndividuals`);
- 4,218 classes, 156 object properties, 151 individuals, 20,028 concept
  expressions, maximum concept depth 2;
- constructors: 3,325 existentials, 44 complements (the pairwise disjointness
  idiom `X ⊑ ¬Y`), no unions, universals, cardinalities, nominals, or data;
- 13,404 normalized clauses, 24 binary disjunctions, no equality;
- expressivity `SHOI`, `universal_role = true`.

The ABox role assertions use two vocabularies. Ten edges use `IAO_0000136`
(is about), which occurs in 256 TBox axioms as `∃is-about.C` on both sides
of subsumptions. Ten edges use `doap:*` properties that the TBox never
mentions. The class assertions cover 20 distinct named classes.

There is exactly one occurrence of the universal role in the whole document:

```
SubObjectPropertyOf(<http://purl.obolibrary.org/obo/RO_0001000> owl:topObjectProperty)
```

That axiom is a tautology: `(owl:topObjectProperty)^I = ΔI × ΔI` in every
OWL 2 DL interpretation, so every role is a sub-property of it.

## Why every existing certificate declined

| Certificate / predicate | Verdict on 16303 | Reason |
|---|---|---|
| `positive_abox_tbox_separable` | declined, correctly | 44 complements: an asserted individual could be inconsistent |
| `positive_el_abox_materializable` | declined, correctly | complements and inverse roles are outside the positive-EL fragment |
| `atomic_class_abox_candidate` | declined | requires positive-EL materialisation |
| `inert_role_abox_probe_candidate` | declined, correctly | `is about` is read by TBox existentials (this is the rejection named in the task) |
| `existential_witness_abox_candidate` | declined | the ABox is not existential-only |
| `disjoint_union_abox_candidate` | declined | `expressivity.universal_role` |
| `typed_object_abox_bridge_candidate` | declined | `expressivity.universal_role` |

With the last two gone, `routing::select` reaches the final
`SemanticFragment::Nominal => Route::Nominals` arm. That bundle is the only
nominal route that never consults the typed bridge, the general HT probe, or
the certified production probe: it runs plain (`KM_ABSORB=0`) nominal-aware
CB with 16 threads over the whole 4,218-class terminology. The 2.1 GiB is
mostly plain CB on this terminology (`cb_plain16` alone is 2.0 GiB in the
matrix); the nominal calculus adds the rest.

## Root cause

`SourceProfileBuilder::object_role` sets `expr.universal_role` for every
mention of the builtin, including the super-role position of
`SubObjectPropertyOf(R owl:topObjectProperty)`. The builder separately tracks
`universal_role_beyond_subrole_super`, which the inverse/cardinality
certificates already use, and the frontend's `top_role` pass (v1.1.0, the
ORE 541 fix) already removes the vacuous inclusion and its RBox row when the
builtin occurs nowhere else. But the profile handed to `routing::select` and
to the orchestrator kept `universal_role = true`, so the routing fences saw a
universal role that no longer existed in the terminology KM classified.

## The change

- `SourceProfileBuilder::elide_vacuous_universal_role` clears the occurrence
  flag. The frontend calls it exactly when `TopRoleScan::eliminable()` holds
  and the elision ran (never under `KM_NO_TOP_ROLE_ELISION`), before the
  profile is finished. The ABox certificates computed in `finish`
  (`positive_abox_tbox_separable`, `disjoint_union_abox_candidate`) and every
  routing predicate keyed on `expressivity.universal_role` therefore describe
  the retained ontology.
- `km profile` runs the same frontend, so the emitted profile and the route
  trace stay consistent.
- No routing predicate, worker, calculus, clause, or RBox output changes.

Files: `engine/src/frontend/profile.rs` (method and unit test),
`engine/src/frontend/mod.rs` (one call and two end-to-end tests),
`engine/src/frontend/top_role.rs` (module doc and one test),
`engine/src/routing.rs` (doc comment and one routing test),
`docs/ROUTING.md`, `docs/SOLVE-16303.md`.

## Soundness

1. Tautology. `R ⊑ U` and `R1 ∘ … ∘ Rn ⊑ U` hold in every interpretation
   when `U` is the universal role, so removing them yields a logically
   equivalent ontology `O'`. This is already the basis of the `top_role`
   pass; the change adds no new elision.
2. `O'` has no universal role. `eliminable()` requires that the builtin
   occurs nowhere except as such a super-role, and the pass removes every
   `RoleInclusion`/`RoleChain` with the builtin as super together with every
   `Subrole`/`Chain`/`ChainN` RBox row. Every statement of the form "for an
   ontology without the universal role …" therefore applies to `O'`:
   closure under disjoint unions (the `disjoint_union_abox_candidate`
   theorem), the one-object-model plus disjoint-union proof of
   `positive_abox_tbox_separable`, and every worker fence that exists only
   because KM has no universal-role object (the bridge's
   `has_builtin_top_role`, general HT, SHOQ).
3. Routing consequence. For 16303 the selector now reaches
   `typed_object_abox_bridge_candidate` and returns `CertifiedNominals`. That
   bundle is the validated complete-answer-or-defer typed bridge
   (`KM_HT_ONLY=certified`) racing the unchanged exact nominal-aware CB
   fallback (`KM_NOMINALS=1`), the route already used for the SHOIN
   object-ABox family (ORE 15672). No answer can be published except by one
   of those two unchanged exact mechanisms. Relative to today, only
   scheduling differs.
4. Fail-closed boundaries are untouched. A document with any other occurrence
   of the builtin is never elided; `KM_NO_TOP_ROLE_ELISION` keeps the
   conservative flag; the bridge still rejects a role table containing the
   builtin on its own.

## Expected performance mechanism

Orchestrator path for this shape under `CertifiedNominals`:

1. `compact_typed_bridge_first_candidate`: no (more than 1,000 axioms).
2. `certified_nominal_general_ht_probe_candidate`: no.
3. `certified_nominal_production_probe_candidate`: yes. It reruns the
   frontend under `production_all` with `KM_EL_ABOX_CHECK=1`; the positive-EL
   ABox completion declines because the inverse bridges are not EL. Expected
   cost: one extra frontend pass over a 1.4 MB document.
4. `race_cb_vs_ht` with `typed_nominal_exclusive`: the bridge worker carries
   the complete typed ABox, its answer is harvested at a 0 s acceptance
   budget (trigger absorption plus bridge exclusivity), and the nominal CB
   fallback runs with one thread while the bridge works.

Expected result: wall of roughly frontend + probe pass + bridge (the frozen
matrix measured the bridge at 2.0 s; the current bridge is faster) instead
of 4.3 s, and peak memory of roughly the bridge (about 120 MB) plus whatever
one CB thread allocates during that window instead of 2.1 GiB. The strict
targets are not reached by routing alone; the remaining gap is the bridge's
own classification time on a 44-complement, 42-inverse terminology and the
probe pass.

## Blast radius

Only sources whose sole universal-role occurrences are vacuous supers change.
The 2026-07-15 table lists 25 ORE ontologies with `universal_role = true`;
which are vacuous-only can be read directly from a fresh `km profile` sweep
(their flag becomes false). Candidates whose route can change:

- `nominals` today with an ABox the typed bridge represents: 13762, 16303,
  16462, 2632, 6589, 7409, 8480. Each moves to `certified_nominals` or, for
  positive sources, to the positive-separation path, always with the exact
  nominal fallback or the certified consistency proof.
- Ontologies already on `elc`/`production_all` through
  `positive_el_abox_materializable` (1579, 3377, 6722, 7455, 15846, 9654,
  15803) keep the `PositiveAbox` fragment; some may now satisfy
  `positive_abox_tbox_separable` and skip the EL materialisation check.
- TBox-only sources, the learned SRIQ tree, the cardinality certificates
  (already keyed on the beyond-super notion), and rule ontologies are
  unaffected.

## Follow-ups kept out of this patch

These are measured decisions, not correctness items.

1. The certified production probe costs one frontend pass on this shape and
   cannot accept (inverse bridges are not EL). A source-level pre-screen
   would need a normalized argument, because inert inverse bridges are
   pruned before the EL screen.
2. A sequential bridge-first schedule for compact typed ABoxes whose plain
   nominal-CB fallback is disjunction-heavy (`complements > 0`) would remove
   the one-thread CB's memory share during the bridge run. It trades a
   possible defer latency for that memory; measure before widening
   `sequential_typed_bridge_candidate`.
3. Disjoint-union projection with TBox re-routing: with the candidate flag
   now true, the opt-in `KM_ABOX_DISJOINT_UNION_CHECK` path can prove
   consistency through the bounded HT global check, but it then continues on
   the nominal-selected route; re-selecting the TBox route (`production_all`
   was 1.18 s / 864 MB in the matrix) would improve wall and worsen memory
   under the strict objective.
4. The rest of the gap to Konclude is inside the bridge's classification of
   this terminology. The 2026-08-27 IBEX experiments (`route_screen`,
   `phase_profile`, `tbox_elc`, `inverse_elc`, `cert_el_production`,
   `dirty_cb`) hold the per-phase numbers; their sbatch scripts are under
   `.work/inputs/`. The local `ore_ont_16303-inverse-cert1.json` artifact has
   310 extra subsumption pairs over the automatic output, which confirms
   that the inverse-closure ELC variant is not a sound lever for this family.
