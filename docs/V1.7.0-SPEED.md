This document records the correctness arguments, unit tests, threshold justifications, and test-suite updates for the classification speed and memory work on `v170/speed` (merged with `development/v1.7.0` at `d322add6`).

## 1. Correctness Arguments for Inference-Altering Optimizations (S4)

Five optimizations on `v170/speed` alter which inferences run rather than how an unchanged inference set is indexed. For each optimization, this section gives the soundness and completeness argument and names the unit test that fails if the invariant is violated.

### (a) `c4da4cf3`: Absorption of `CCEQ` Definitions and Trigger Truncation

- **Location**: `engine/src/konclude_ht/bridge.rs` (`extract_partial_def_triggers_into_component`, `truncate_absorption_triggers_after_failed_conjunct`).
- **Mechanism**:
  1. For an equivalence definition `N ≡ D₁ ⊓ ... ⊓ Dₖ` (`CCEQ`), the left-to-right implication `N ⊑ D₁ ⊓ ... ⊓ Dₖ` is compiled into deterministic concept unfolding on `N`, while the right-to-left implication `D₁ ⊓ ... ⊓ Dₖ ⊑ N` is a conjunctive GCI candidate for Horn trigger absorption.
  2. In `truncate_absorption_triggers_after_failed_conjunct`, each conjunct `Dⱼ` (`1 <= j <= k`) is inspected in order for single-conjunct absorbability into Konclude-style `AbsorptionTrigger`s (atomic concept `A`, existential role `∃R.A`, or self-restriction `∃R.Self`).
  3. When a prefix `D₁, ..., Dₘ` (`1 <= m < k`) absorbs into triggers `T₁, ..., Tₘ` and conjunct `Dₘ₊₁` is not absorbable (for example, `∀R.B` or `≤n R.B`), `extract_partial_def_triggers_into_component` allocates a fresh internal concept `C_partial` (`C_partial >= n_concepts`) with definition:
     `C_partial ⊑ D₁ ⊓ ... ⊓ Dₘ ⊓ (¬Dₘ₊₁ ⊔ ... ⊔ ¬Dₖ ⊔ N)`
     and attaches the trigger rule `T₁ ⊓ ... ⊓ Tₘ ⊑ C_partial`.
- **Correctness Argument**:
  - **Soundness**: In any model `I` of the original ontology `O`, define the interpretation of the fresh symbol `C_partial` as `C_partial^I = (D₁ ⊓ ... ⊓ Dₘ)^I`. Because `O ⊨ D₁ ⊓ ... ⊓ Dₖ ⊑ N`, every element `x ∈ C_partial^I` satisfies `D₁, ..., Dₘ` and also satisfies `(¬Dₘ₊₁ ⊔ ... ⊔ ¬Dₖ ⊔ N)`. Conversely, every element `x` satisfying the trigger conjunction `T₁ ⊓ ... ⊓ Tₘ` satisfies `D₁ ⊓ ... ⊓ Dₘ`, so `x ∈ C_partial^I`. The rewritten ontology `O'` is a conservative extension of `O` over the named signature: every model of `O` extends to a model of `O'`, and every model of `O'` restricts to a model of `O` because `C_partial ⊑ (¬Dₘ₊₁ ⊔ ... ⊔ ¬Dₖ ⊔ N)` together with `T₁ ⊓ ... ⊓ Tₘ ⊑ C_partial` entails `D₁ ⊓ ... ⊓ Dₖ ⊑ N`.
  - **Completeness**: On any completion node `x` where `D₁(x), ..., Dₖ(x)` hold, the absorbed triggers `T₁, ..., Tₘ` fire and derive `C_partial(x)`. Unfolding `C_partial(x)` adds the disjunction `(¬Dₘ₊₁ ⊔ ... ⊔ ¬Dₖ ⊔ N)(x)`. Since `Dₘ₊₁(x), ..., Dₖ(x)` hold on `x`, all negative disjuncts clash and `N(x)` is derived. Nodes that do not satisfy `D₁ ⊓ ... ⊓ Dₘ` cannot falsify `D₁ ⊓ ... ⊓ Dₖ ⊑ N` because at least one `Dᵢ` (`1 <= i <= m`) is false on them; omitting the disjunction on those nodes preserves model existence.
- **Unit Test**:
  `konclude_ht::bridge::tests::cceq_absorption_truncates_failed_conjunct_triggers_and_extracts_partial_triggers` (`engine/src/konclude_ht/bridge.rs`).

### (b) `83f66f41`: Pruning Phase-2 Pairs from All Root Concepts of a Completion Model and the Transitive Closure

- **Location**: `engine/src/hypertableau.rs` (`classify`).
- **Mechanism**:
  1. Phase 2 of the hypertableau classifier maintains a candidate set `possible[C]` of potential named subsumers for each satisfiable named concept `C`, along with confirmed subsumers `subsumers[C]` and reverse index `subs_of[C]`.
  2. When testing a candidate pair `(A, B)` via `is_subsumed(A, B)` (which tests satisfiability of `O ∪ {A(x₀), ¬B(x₀)}` at root individual `x₀`):
     - If `is_subsumed(A, B)` returns `None` (satisfiable) with root node concept set `root_concepts = L(x₀) ∩ Named`, the classifier removes every `D ∉ root_concepts` from `possible[C]` for **every** `C ∈ root_concepts` (not only for `C = A`).
     - If `is_subsumed(A, B)` returns `Some(())` (unsatisfiable, so `O ⊨ A ⊑ B`), the classifier computes the transitive closure step: for every `X ∈ subs_of[A]` (where `O ⊨ X ⊑ A` is already confirmed) and every `Y ∈ subsumers[B]` (where `O ⊨ B ⊑ Y` is already confirmed), it records `Y ∈ subsumers[X]`, `X ∈ subs_of[Y]`, and removes `Y` from `possible[X]`.
- **Correctness Argument**:
  - **Root-Model Pruning (`is_subsumed` returns `None`)**: When the hypertableau saturation of `O ∪ {A(x₀), ¬B(x₀)}` terminates without a clash, the resulting completion graph `G` induces a canonical model `I_G` of `O` in which `x₀ ∈ C^{I_G}` for every `C ∈ L(x₀)` and `x₀ ∉ D^{I_G}` for every named concept `D ∉ L(x₀)`. For any pair `(C, D)` with `C ∈ L(x₀) ∩ Named` and `D ∈ Named \ L(x₀)`, the element `x₀` in `I_G` witnesses `x₀ ∈ C^{I_G} \ D^{I_G}`, proving `O ⊭ C ⊑ D`. Pruning `D` from `possible[C]` removes only non-subsumptions for which an explicit countermodel has already been constructed.
  - **Transitive Closure Pruning (`is_subsumed` returns `Some(())`)**: Subsumption `⊑` in `O` is a preorder (reflexive and transitive). When `O ⊨ X ⊑ A`, `O ⊨ A ⊑ B`, and `O ⊨ B ⊑ Y` have all been established by sound hypertableau refutations, `O ⊨ X ⊑ Y` holds in every model of `O`. Recording `(X, Y)` directly and removing `Y` from `possible[X]` skips a refutation test `O ∪ {X(x₀), ¬Y(x₀)}` whose outcome is already determined to be unsatisfiable.
- **Unit Test**:
  `hypertableau::tests::phase2_root_model_and_transitive_closure_pruning_matches_naive_classify` (`engine/src/hypertableau.rs`).

### (c) `ef0dc1ea`: Consuming Nominal-Free Saturation Outcomes on Native-Nominal Routes (`unguarded_top_gcis == 0`)

- **Location**: `engine/src/konclude_ht/bridge.rs` (`run_konclude_bridge_component`).
- **Mechanism**:
  During Phase 2 concept saturation (`s04` / `s07`), each named concept `A` is saturated starting from a fresh root node `{A}` using deterministic rules. When `has_native_nominals` is true, the bridge consumes the saturation outcome `concept_sat_outcomes[A]` directly (avoiding a full completion test on the retained nominal ABox base) under two paths:
  1. If `concept_sat_outcomes[A] == Some(false)` (saturation clashed), `A` is immediately classified as unsatisfiable (`⊥`).
  2. If `concept_sat_outcomes[A] == Some(true)` and `concept_sat_complete[A]` is true, `A` is marked satisfiable and its saturation label set `L(x₀)` is used as its complete named subsumer set **only when** `consistency_retained_base_deterministic && unguarded_top_gcis == 0`.
- **Correctness Argument**:
  - **Unsatisfiable Case (`Some(false)`)**: Every rule in concept saturation (`s04` / `s07`) is a sound consequence of the TBox/RBox axioms of `O`. If starting from `{A(x₀)}` alone derives a clash (`⊥`), then `O ⊨ A ⊑ ⊥` in every model of `O`, regardless of any ABox nominals or global `⊤` axioms.
  - **Satisfiable and Complete Case (`Some(true)` with `concept_sat_complete[A] && consistency_retained_base_deterministic && unguarded_top_gcis == 0`)**:
    Let `G_nom` be the clash-free, deterministic completion graph obtained from the ontology's consistency check over the nominal ABox (`consistency_retained_base_deterministic == true`), and let `T_A` be the clash-free, deterministic saturation tree for `A` (`concept_sat_complete[A] == true`, meaning `T_A` never encountered a nominal `CCOIRS`, a disjunction `CCOR`, or a non-deterministic cardinality/inverse construct).
    Consider the disjoint union `M = G_nom ⊎ T_A`, where `x₀` is the root of `T_A`:
    1. Because `T_A` is nominal-free (`concept_sat_complete[A]` becomes `false` whenever any nominal concept or nominal role link is touched), `T_A` and `G_nom` share no named individuals or nominals, so no nominal-merging rule applies between `G_nom` and `T_A`.
    2. Because there are no role edges connecting `G_nom` and `T_A`, no universal restriction `∀R.C`, existential restriction `∃R.C`, role chain, or at-most restriction `≤n R.C` can propagate across the boundary between `G_nom` and `T_A`.
    3. The only axioms that apply to nodes of `T_A` without requiring a trigger concept in `L(x)` are global unguarded GCIs `⊤ ⊑ C`. When `unguarded_top_gcis == 0`, no such axioms exist; every TBox axiom is guarded by a positive concept or role trigger that is already saturated to fixpoint inside `T_A` and inside `G_nom` independently.
    Therefore, `M = G_nom ⊎ T_A` is a complete, clash-free pre-model of `O ∪ {A(x₀)}` in which the named concepts holding at `x₀` are functionality-identical to `L_{T_A}(x₀)`. Conversely, if `unguarded_top_gcis > 0` (for example, `⊤ ⊑ {o}` forcing every element to merge into nominal `o`), `T_A` is not closed under `⊤ ⊑ {o}` and the bridge must run the completion prover on `G_nom`.
- **Unit Test**:
  `konclude_ht::bridge::tests::native_nominal_saturation_outcome_requires_zero_unguarded_top_gcis` (`engine/src/konclude_ht/bridge.rs`).

### (d) `f6131f0e`: Binary-Digit Value Markers vs. Pairwise Disjointness

- **Location**: `engine/src/frontend/datatypes.rs` (`encode_value_disjointness`, `PAIRWISE_VALUE_LIMIT = 128`) and `engine/src/frontend/bottom_prepass.rs`.
- **Mechanism**:
  When a datatype or functional data property induces `k` distinct canonical literal value markers `M_0, M_1, ..., M_{k-1}` within a mutual-exclusion group:
  - For `k <= 128`, the frontend emits the `k(k-1)/2` pairwise disjointness clauses `M_i ⊓ M_j ⊑ ⊥` (`0 <= i < j < k`).
  - For `k > 128`, let `b = ⌈log₂ k⌉`. The frontend introduces `2b` fresh auxiliary concepts `Bit_{d,0}` and `Bit_{d,1}` (`0 <= d < b`), emits `b` disjointness clauses `Bit_{d,0} ⊓ Bit_{d,1} ⊑ ⊥`, and for each `0 <= i < k` and `0 <= d < b` emits the binary implication `M_i ⊑ Bit_{d, (i >> d) & 1}`.
- **Correctness Argument**:
  Let `Σ` be the signature of the ontology (including `M_0, ..., M_{k-1}` but excluding the fresh symbols `Bit_{d,0}, Bit_{d,1}`).
  1. **Soundness (Entails All Pairwise Disjointnesses)**: For any `0 <= i < j < k`, since `i != j`, their `b`-bit binary representations differ at some bit position `d ∈ {0, ..., b-1}`. Suppose `(i >> d) & 1 = 0` and `(j >> d) & 1 = 1`. In any interpretation `I` satisfying the binary-digit axioms, `M_i^I ⊆ Bit_{d,0}^I`, `M_j^I ⊆ Bit_{d,1}^I`, and `Bit_{d,0}^I ∩ Bit_{d,1}^I = ∅`, which implies `M_i^I ∩ M_j^I = ∅`. Every model of the binary-digit encoding satisfies `M_i ⊓ M_j ⊑ ⊥` for all `i != j`.
  2. **Completeness / Conservative Extension**: Given any `Σ`-interpretation `I` that satisfies `M_i^I ∩ M_j^I = ∅` for all `0 <= i < j < k`, every domain element `x ∈ Δ^I` belongs to at most one `M_i^I`. Define the extension `I'` to `Σ ∪ {Bit_{d,0}, Bit_{d,1}}` by:
     `Bit_{d,0}^{I'} = ⋃ { M_i^I | 0 <= i < k, (i >> d) & 1 == 0 }`
     `Bit_{d,1}^{I'} = ⋃ { M_j^I | 0 <= j < k, (j >> d) & 1 == 1 }`
     By construction, `M_i^{I'} ⊆ Bit_{d, (i >> d) & 1}^{I'}` for every `i` and `d`. And if `x ∈ Bit_{d,0}^{I'} ∩ Bit_{d,1}^{I'}`, then `x ∈ M_i^I` for some `i` with bit `d` equal to `0` and `x ∈ M_j^I` for some `j` with bit `d` equal to `1`; since `i != j`, this contradicts `M_i^I ∩ M_j^I = ∅`. Hence `Bit_{d,0}^{I'} ∩ Bit_{d,1}^{I'} = ∅`. Every model of the pairwise disjointness axioms extends to a model of the binary-digit axioms, so the two encodings have identical `Σ`-consequences while reducing clause count from `O(k²)` to `O(k log k)`.
- **Unit Test**:
  `frontend::bottom_prepass::tests::binary_digit_value_markers_above_pairwise_limit_match_pairwise_disjointness` (`engine/src/frontend/bottom_prepass.rs`).

### (e) `a4cddac7`: Coalescing of Branch Epochs and Backtracking Restoration

- **Location**: `engine/src/konclude_ht/model/substrate.rs` (`Arena::coalesce_epochs_to`) and `engine/src/konclude_ht/process/context.rs` (`ProcessContext::coalesce_branch_epochs_to`).
- **Mechanism**:
  In `Arena<T>`, `begin_epoch()` records the current undo-trail length `L` in `epochs` and sets `alloc_watermark = slots.len()`. During an active epoch, `get_mut(id)` pushes `(id, old_value)` onto `saves` if and only if `id.index() < alloc_watermark`. When nested epochs `d_1, d_2, ..., d_m` (`target_depth = d_1`) are coalesced via `coalesce_epochs_to(target_depth, target_slot_watermark)`:
  1. `epochs` is truncated to `target_depth` (with trail start `L_1 = epochs[target_depth - 1]`).
  2. `alloc_watermark` is restored to `target_slot_watermark` (`W_1`, the slot count when epoch `d_1` began).
  3. The trail slice `saves[L_1..]` is compacted in forward chronological order: any save with `id.index() >= W_1` is discarded, and for each slot `id.index() < W_1`, only the **first** save `(id, v_0)` recorded at or after `L_1` is kept (deduplicated via `coalesce_seen`).
- **Correctness Argument**:
  Let `S_0` be the arena state immediately before epoch `d_1` began (when `slots.len() == W_1` and `saves.len() == L_1`).
  1. **Pre-`d_1` Slots (`id.index() < W_1`)**: Because `W_1 <= W_2 <= ... <= W_m`, every epoch `d_k` (`1 <= k <= m`) has `alloc_watermark >= W_1`. Consequently, the very first time any slot `id` with `id.index() < W_1` is mutated during `d_1 ..= d_m`, `get_mut(id)` is guaranteed to push `(id, S_0[id])` onto `saves[L_1..]`. Later mutations to the same slot `id` in epochs `d_2 ..= d_m` may push additional entries `(id, S_k[id])`. By scanning `saves[L_1..]` forward and keeping only the first entry for each `id.index() < W_1`, `coalesce_epochs_to` retains `(id, S_0[id])` and removes all subsequent overwrites.
  2. **Post-`d_1` Mutations in the Coalesced Epoch**: Restoring `alloc_watermark = W_1` ensures that any subsequent mutation to a slot `id.index() < W_1` within the coalesced epoch saves `(id, S_0[id])` if not yet mutated, and any mutation to a slot `id.index() >= W_1` does not pollute `saves`.
  3. **Rollback Equivalence**: When `rollback_epoch()` later pops epoch `d_1`, it iterates `saves` down to `L_1`. Because each modified slot `id.index() < W_1` appears at most once in `saves[L_1..]` with its exact pre-`d_1` value `S_0[id]`, every slot `< W_1` is restored to `S_0[id]`, matching the state produced by rolling back `d_m, ..., d_1` individually.
- **Unit Test**:
  `konclude_ht::model::substrate::tests::coalesce_epochs_to_preserves_earliest_pre_target_saves_and_watermark` (`engine/src/konclude_ht/model/substrate.rs`).

### (f) Additional S6 Optimizations and Their Invariants

1. **Epoch-DFS Reachability in `source_named_subsumer_closure_seeded_rows` (`engine/src/konclude_ht/bridge.rs`)**:
   - Replaced the `FxHashSet<(usize, usize)>` closure table and `Vec<FxHashSet<usize>>` upper-concept table with sorted `Vec<u32>` adjacency lists and an epoch-stamped `seen: Vec<u32>` array.
   - **Invariant**: Within each fixpoint iteration, `u` iterates `0..n_named` in ascending order. When DFS from `u` visits a neighbor `vi < u`, `supers[vi]` has already been computed to full transitive reachability in the current `adj` graph, so all nodes reachable from `vi` are added directly from `supers[vi]` in `O(|supers[vi]|)` without re-traversing `adj` edges inside `vi`'s subgraph. When `vi >= u`, DFS expands `adj[vi]` on `stack`. By strong induction on `u`, `supers[u]` and `subs[vi]` contain the exact reflexive-free transitive closure of `adj`, producing the exact same fixpoint as the hash-set implementation.
2. **Retained Blocking Base Unmodified Fast Path (`engine/src/konclude_ht/completion/u20.rs`, `process/context.rs`, `model/substrate.rs`)**:
   - In `get_blocking_individual_node_candidate_iterator` (`u20.rs`), `run_saturation_loop` does not populate `node_switch_history`, which previously left `min_test_indi_node_id = 1` and caused `BlockingBaseIndex` to fall back to scanning all `1..=base_hi` retained consistency-base nodes on every subject (`9,285` nodes on `ore_ont_9899`).
   - Added `retained_blocking_base_unmodified` on `ProcessContext`: when `max_valid_indi_id > index.base_hi` and no base individual node (`<= base_node_count`) has changed its `label_set`, `merged_to`, or `blockable` state and no base label set (`<= base_label_set_count`) has changed its `hash` since `base_epoch_depth`, every base node's label set is already indexed in `BlockingBaseIndex::by_hash`. Advancing `min_test_indi_node_id` to `index.base_hi + 1` scans only fresh nodes created during the current concept test while querying base nodes in `O(1)` via `by_hash`.
3. **Precomputed Ancestor and Disjointness Tables in `BottomPrepass` (`engine/src/frontend/bottom_prepass.rs`)**:
   - Precomputes `ancestors[c]`, `ancestor_disjoint[c]`, and `self_disjoint[c]` once per `BottomPrepass::certify` call and deduplicates `role` per `owner` in `viable_context_common_types`, replacing repeated per-node BFS allocations (`BTreeSet`/`VecDeque`) with bitset/mark lookups over identical closure relations.
4. **Single-Pass `TInput` Deserialization and Streaming Writer (`engine/src/tableau.rs`, `engine/src/orchestrate/race.rs`)**:
   - `run_bridge_json_owned_compact` parses `producer_input: TInput` from `&input` once, drops the raw JSON string before allocating bridge structures, and validates `u32` ID bounds and `native_abox` directly on `&producer_input`. `PreparedHt::launch` streams `serde_json::to_writer` inside the background stdin thread via a `1 MiB` `BufWriter`.
5. **Subprocess `km ofn` Pass-1 Uncarried-Data Short-Circuit (`engine/src/cli.rs`)**:
   - Wired `abort_on_uncarried` into `ofn_to_clauses_for_classifier_pass` when `KM_CLASSIFIER_EXTENDED_ATOMIC_ABOX=1` in subprocess `km ofn`, matching the in-process frontend path so Pass 1 immediately hands off to Pass 2 (`KM_KEEP_DATA_ASSERTIONS=1`) when uncarried data assertions are present.

## 2. Justification of Speed Thresholds and Rule-Ontology Handling (S5)

Three numeric thresholds in the classification pipeline act purely as performance routing choices where both branches of the threshold are sound and complete for the ontology being classified.

### (a) `blocks > 64` Sandwich Decline (`engine/src/orchestrate/mod.rs:3449`)

- **Threshold**: `const MAX_SANDWICH_BLOCKS: usize = 64;` in `try_cb_horni_atomic_abox_sandwich`.
- **Role**: The CB-Horn-I atomic-ABox sandwich is an optional fast path that tests whether an ALCHIF ontology with a ground atomic ABox has identical lower (TBox-only) and upper (role-assertion-projected) CB taxonomy bounds.
  - When `blocks <= 64`, `try_cb_horni_atomic_abox_sandwich` runs the lower and upper CB passes; if their taxonomies coincide (`lower == upper`), the sandwich returns that exact taxonomy; if they differ (`lower != upper`), it returns `None` and falls through to the complete Konclude-HT / hypertableau classifier.
  - When `blocks > 64`, `try_cb_horni_atomic_abox_sandwich` immediately returns `None` and routes directly to the complete Konclude-HT / hypertableau classifier without spending time on two CB passes whose upper bound rarely matches when more than 64 connected role-assertion blocks exist.
- **Why Both Sides Give the Same Answer**: Returning `None` when `blocks > 64` simply skips an optional sufficient-condition check and delegates to the full exact reasoner. Both sides compute the exact same classification taxonomy.

### (b) `<= 4,096` Data Assertions and `<= 8 MB` Ground-Rule Compilation (`engine/src/orchestrate/data_source.rs`)

- **Thresholds**:
  1. `DENSE_DATA_ASSERTION_DIRECT_PASS_THRESHOLD: usize = 4_096` (`engine/src/orchestrate/data_source.rs:4128`):
     On rule-free ontologies (`!has_rules`) with more than 4,096 `DataPropertyAssertion`s, `classifier_pass1_skips_to_keep_data_assertions` skips Pass 1 (which would scan the ontology only to discover uncarried data assertions and abort) and starts directly in Pass 2 (`keep_data_assertions = true`). Skipping the doomed Pass 1 probe does not alter the Pass 2 clause set or classification result.
  2. `AUTOMATIC_DATA_SOURCE_MAX_BYTES: usize = 8 * 1024 * 1024` (`8 MiB`) and `MAX_GROUNDED_RULE_AXIOMS: usize = 100_000` (`engine/src/orchestrate/data_source.rs:20-25, 3816-3996`):
     In `data_source::automatic_candidate`, the orchestrator optionally pre-grounds SWRL `DLSafeRule` axioms over named ABox individuals into materialised OWL functional axioms before invoking the main frontend.
- **What Happens to a Rule Ontology Above the Bound**:
  A rule ontology above the `8 MiB` grounded size limit or `100,000` grounded rule-instance limit is **never** answered without its rules:
  1. In `data_source::automatic_candidate` (`engine/src/orchestrate/data_source.rs:3947-3996`), if `ground_dl_safe_rules` returns `None` (because the grounded rule instances exceed `MAX_GROUNDED_RULE_AXIOMS = 100_000` or contain unsupported rule atoms) or if the rewritten source exceeds `AUTOMATIC_DATA_SOURCE_MAX_BYTES = 8 MiB` (`rewritten.len() > AUTOMATIC_DATA_SOURCE_MAX_BYTES`), `automatic_candidate` discards the rewritten text (`rewritten = None`) when no data-property rewrites were needed, or returns the original `DLSafeRule(...)` lines untouched inside `rewritten` when data-property rewrites were applied (`ground_dl_safe_rules` only strips `DLSafeRule` lines when it returns `Some(grounded)`).
  2. The original `DLSafeRule(...)` axioms remain in the OWL Functional Syntax input passed to the main frontend (`engine/src/frontend/`).
  3. The frontend parser (`engine/src/frontend/parse.rs`) parses every `DLSafeRule` into `Axiom::DLSafeRule`, records `profile.source.rule_axioms > 0` (`engine/src/orchestrate/mod.rs:3212`), and clausifies the rules into multi-variable horn/disjunctive DL clauses (`engine/src/frontend/normalise.rs`).
  4. In the orchestrator (`engine/src/orchestrate/mod.rs:2410, 4436-4550`), `profile.source.rule_axioms > 0` activates the dedicated rule-reasoning pipeline:
     - First, `run_rules_consistency_check` checks ABox + rule consistency via the rule engine (`rules-consistency`), detecting inconsistency on rule-clashing ontologies (such as `ore_ont_11367`, `1558`, `1967`, `6434`).
     - Second, `complete_rule_taxonomy` (`engine/src/orchestrate/mod.rs:2547`) grounds and saturates the rules over the ABox and TBox taxonomy.
     - Third, if a rule axiom cannot be soundly represented or grounded within the complete rule fragment, the frontend/orchestrator marks `uncarried_constructs` / `OutOfFragment` (`exit 2`), failing closed rather than silently dropping rules.

### (d) `PAIRWISE_VALUE_LIMIT = 128` (`engine/src/frontend/datatypes.rs:2887`)

- **Threshold**: `const PAIRWISE_VALUE_LIMIT: usize = 128;` in `encode_value_disjointness`.
- **Role**: Selects between `k(k-1)/2` pairwise disjointness clauses (`k <= 128`, up to 8,128 clauses) and `k · ⌈log₂ k⌉ + ⌈log₂ k⌉` binary-digit marker clauses (`k > 128`). As shown in Section 1(d) and tested by `binary_digit_value_markers_above_pairwise_limit_match_pairwise_disjointness`, both encodings are logically equivalent over the ontology signature (`(M_i ⊓ M_j)^I = ∅` for all `i != j`), so `128` is strictly a crossover threshold between clause-table size and auxiliary-symbol count.

## 3. Documentation of Changed Unit Test Assertions in `sat1` and `s07` (S3)

In commit `0772464a` (`Cut saturation node/linker allocations on 7361`), two unit-test assertions in `konclude_ht` were updated to reflect memory-representation changes that do not alter reasoning semantics:

1. **`konclude_ht::process::sat1::tests::sat1_coping_node_copies_role_backward_hash_and_successor_nominals` (`engine/src/konclude_ht/process/sat1.rs:1328-1335`)**:
   - **Previous Assertion**:
     ```rust
     let copied_other = ctx.saturation_arenas.role_back_prop_data_hash
         .get(*ctx.saturation_arenas.nodes.get(target).role_back_prop_hash.get(&other_role).unwrap());
     assert!(copied_other.link_linker.is_none());
     assert!(!copied_other.self_connected);
     ```
   - **Updated Assertion**:
     ```rust
     if let Some(&other_id) = ctx.saturation_arenas.nodes.get(target).role_back_prop_hash.get(&other_role) {
         let copied_other = ctx.saturation_arenas.role_back_prop_data_hash.get(other_id);
         assert!(copied_other.link_linker.is_none());
         assert!(!copied_other.self_connected);
     }
     ```
   - **Reason for Change and Why the Old Expectation Was Not a Correctness Property**:
     In `sat1_coping_node`, `other_role` in the test fixture was configured with `reapply_linker: OptionId::NONE`, `link_linker: OptionId::NONE`, and `self_connected: false`. Commit `0772464a` changed `sat1_coping_node` to skip copying dead entries in `role_back_prop_hash` when `reapply_linker.is_none()` and no self-connection holds, eliminating 613 MB of empty `RoleBackwardSaturationPropagationHashData` allocations on `ore_ont_7361`. In the saturation engine, looking up a role in `role_back_prop_hash` that is absent has the exact same behavior as looking up a role whose entry has `reapply_linker == NONE`, `link_linker == NONE`, and `self_connected == false` (zero backward reapplications and zero link traversals). Requiring an all-empty entry to be materialised in `role_back_prop_hash` was an internal hash-map allocation detail, not a reasoning correctness property.

2. **`konclude_ht::saturation::s07::tests::s07_process_successor_functional_drains_qualified_atmost_and_fans_out` (`engine/src/konclude_ht/saturation/s07.rs:3006`)**:
   - **Previous Assertion**:
     ```rust
     assert!(released.contains(&qual_linker.raw));
     assert_eq!(concept_process_chain_descriptor_count(&ctx, dep_head, descriptor), 1);
     ```
   - **Updated Assertion**:
     ```rust
     assert!(released.contains(&qual_linker.raw) || dep_head == qual_linker);
     assert_eq!(concept_process_chain_descriptor_count(&ctx, dep_head, descriptor), 1);
     ```
   - **Reason for Change and Why the Old Expectation Was Not a Correctness Property**:
     During `process_successor_functional_concepts_extensions`, the drained linker `qual_linker` on `node` is released to the free list `remaining_concept_saturation_process_linker`, and immediately afterward `s07_create_concept_process_linker` allocates a linker `dep_head` for `dep`'s `qual_func_atmost_con_process_linker` chain. Before `0772464a`, `s07_create_concept_process_linker` always pushed a fresh slot onto the arena even when `remaining_concept_saturation_process_linker` was non-empty, leaving `qual_linker` sitting unused in the free list (`released.contains(&qual_linker.raw)`). Commit `0772464a` made `s07_create_concept_process_linker` pop and reuse freed linkers from `remaining_concept_saturation_process_linker` first, so `qual_linker` is immediately recycled as `dep_head` (`dep_head == qual_linker`). Which arena slot ID backs `dep_head` is an allocator freelist reuse detail, not a correctness property; the semantic property is that `node`'s queue was drained (`qual_func_atmost_con_process_linker.is_none()`) and `dep` received the descriptor (`concept_process_chain_descriptor_count(&ctx, dep_head, descriptor) == 1`).
