This document records the correctness arguments, unit tests, threshold justifications, and test-suite updates for the classification speed and memory work on `v170/speed` (merged with `development/v1.7.0` at `d322add6`).

## 1. Correctness Arguments for Inference-Altering Optimizations (S4)

Five optimizations on `v170/speed` alter which inferences run rather than how an unchanged inference set is indexed. For each optimization, this section gives the soundness and completeness argument and names the unit test that fails if the invariant is violated.

### (a) `c4da4cf3`: Absorption of `CCEQ` Definitions and Trigger Truncation

- **Location**: `engine/src/konclude_ht/bridge.rs` (`extract_partial_def_triggers_into_component`, `truncate_absorption_triggers_after_failed_conjunct`).
- **Mechanism**:
  1. For an equivalence definition `N ≡ D₁ ⊓ ... ⊓ Dₖ` (`CCEQ`), the left-to-right implication `N ⊑ D₁ ⊓ ... ⊓ Dₖ` is compiled into deterministic concept unfolding on `N`, while the right-to-left implication `D₁ ⊓ ... ⊓ Dₖ ⊑ N` is a conjunctive GCI candidate for Horn trigger absorption.
  2. In `truncate_absorption_triggers_after_failed_conjunct`, each conjunct `Dⱼ` (`1 <= j <= k`) is inspected in order for single-conjunct absorbability into Konclude-style `AbsorptionTrigger`s (atomic concept `A`, existential role `∃R.A`, or self-restriction `∃R.Self`).
  3. When a prefix `D₁, ..., Dₘ` (`1 <= m < k`) absorbs into triggers `T₁, ..., Tₘ` and conjunct `Dₘ₊₁` is not absorbable (for example, `∀R.B` or `≤n R.B`), `extract_partial_def_triggers_into_component` allocates a fresh internal concept `C_partial` (`C_partial >= n_concepts`) with definition:
     `C_partial ⊑ D₁ ⊓ ... ⊓ Dₘ ⊓ (¬Dₘ₊₁ ⊔ ... ⊔ ¬Dₖ ⊔ N)`
     and attaches the trigger rule `T₁ ⊓ ... ⊓ Tₘ ⊑ C_partial`.
- **Correctness Argument**:
  - **Soundness**: In any model `I` of the original ontology `O`, define the interpretation of the fresh symbol `C_partial` as `C_partial^I = (D₁ ⊓ ... ⊓ Dₘ)^I`. Because `O ⊨ D₁ ⊓ ... ⊓ Dₖ ⊑ N`, every element `x ∈ C_partial^I` satisfies `D₁, ..., Dₘ` and also satisfies `(¬Dₘ₊₁ ⊔ ... ⊔ ¬Dₖ ⊔ N)`. Conversely, every element `x` satisfying the trigger conjunction `T₁ ⊓ ... ⊓ Tₘ` satisfies `D₁ ⊓ ... ⊓ Dₘ`, so `x ∈ C_partial^I`. The rewritten ontology `O'` is a conservative extension of `O` over the named signature: every model of `O` extends to a model of `O'`, and every model of `O'` restricts to a model of `O` because `C_partial ⊑ (¬Dₘ₊₁ ⊔ ... ⊔ ¬Dₖ ⊔ N)` together with `T₁ ⊓ ... ⊓ Tₘ ⊑ C_partial` entails `D₁ ⊓ ... ⊓ Dₖ ⊑ N`.
  - **Completeness**: On any completion node `x` where `D₁(x), ..., Dₖ(x)` hold, the absorbed triggers `T₁, ..., Tₘ` fire and derive `C_partial(x)`. Unfolding `C_partial(x)` adds the disjunction `(¬Dₘ₊₁ ⊔ ... ⊔ ¬Dₖ ⊔ N)(x)`. Since `Dₘ₊₁(x), ..., Dₖ(x)` hold on `x`, all negative disjuncts clash and `N(x)` is derived. Nodes that do not satisfy `D₁ ⊓ ... ⊓ Dₘ` cannot falsify `D₁ ⊓ ... ⊓ Dₖ ⊑ N` because at least one `Dᵢ` (`1 <= i <= m`) is false on them; omitting the disjunction on those nodes preserves model existence.
- **Unit Test**:
  `konclude_ht::bridge::tests::cceq_absorption_truncates_failed_conjunct_triggers_and_extracts_partial_triggers` (`engine/src/konclude_ht/bridge.rs`).

### (b) `83f66f41`: Pruning Phase-2 Pairs from All Root Concepts of a Completion Model and the Transitive Closure

- **Location**: `engine/src/hypertableau.rs` (`classify`).
- **Mechanism**:
  1. Phase 2 of the hypertableau classifier maintains a candidate set `possible[C]` of potential named subsumers for each satisfiable named concept `C`, along with confirmed subsumers `subsumers[C]` and reverse index `subs_of[C]`.
  2. When testing a candidate pair `(A, B)` via `is_subsumed(A, B)` (which tests satisfiability of `O ∪ {A(x₀), ¬B(x₀)}` at root individual `x₀`):
     - If `is_subsumed(A, B)` returns `None` (satisfiable) with root node concept set `root_concepts = L(x₀) ∩ Named`, the classifier removes every `D ∉ root_concepts` from `possible[C]` for **every** `C ∈ root_concepts` (not only for `C = A`).
     - If `is_subsumed(A, B)` returns `Some(())` (unsatisfiable, so `O ⊨ A ⊑ B`), the classifier computes the transitive closure step: for every `X ∈ subs_of[A]` (where `O ⊨ X ⊑ A` is already confirmed) and every `Y ∈ subsumers[B]` (where `O ⊨ B ⊑ Y` is already confirmed), it records `Y ∈ subsumers[X]`, `X ∈ subs_of[Y]`, and removes `Y` from `possible[X]`.
- **Correctness Argument**:
  - **Root-Model Pruning (`is_subsumed` returns `None`)**: When the hypertableau saturation of `O ∪ {A(x₀), ¬B(x₀)}` terminates without a clash, the resulting completion graph `G` induces a canonical model `I_G` of `O` in which `x₀ ∈ C^{I_G}` for every `C ∈ L(x₀)` and `x₀ ∉ D^{I_G}` for every named concept `D ∉ L(x₀)`. For any pair `(C, D)` with `C ∈ L(x₀) ∩ Named` and `D ∈ Named \ L(x₀)`, the element `x₀` in `I_G` witnesses `x₀ ∈ C^{I_G} \ D^{I_G}`, proving `O ⊭ C ⊑ D`. Pruning `D` from `possible[C]` removes only non-subsumptions for which an explicit countermodel has already been constructed.
  - **Transitive Closure Pruning (`is_subsumed` returns `Some(())`)**: Subsumption `⊑` in `O` is a preorder (reflexive and transitive). When `O ⊨ X ⊑ A`, `O ⊨ A ⊑ B`, and `O ⊨ B ⊑ Y` have all been established by sound hypertableau refutations, `O ⊨ X ⊑ Y` holds in every model of `O`. Recording `(X, Y)` directly and removing `Y` from `possible[X]` skips a refutation test `O ∪ {X(x₀), ¬Y(x₀)}` whose outcome is already determined to be unsatisfiable.
- **Unit Test**:
  `hypertableau::tests::phase2_root_model_and_transitive_closure_pruning_matches_naive_classify` (`engine/src/hypertableau.rs`).

### (c) `ef0dc1ea`: Consuming Nominal-Free Saturation Outcomes on Native-Nominal Routes (`unguarded_top_gcis == 0`)

- **Location**: `engine/src/konclude_ht/bridge.rs` (`run_konclude_bridge_component`).
- **Mechanism**:
  During Phase 2 concept saturation (`s04` / `s07`), each named concept `A` is saturated starting from a fresh root node `{A}` using deterministic rules. When `has_native_nominals` is true, the bridge consumes the saturation outcome `concept_sat_outcomes[A]` directly (avoiding a full completion test on the retained nominal ABox base) under two paths:
  1. If `concept_sat_outcomes[A] == Some(false)` (saturation clashed), `A` is immediately classified as unsatisfiable (`⊥`).
  2. If `concept_sat_outcomes[A] == Some(true)` and `concept_sat_complete[A]` is true, `A` is marked satisfiable and its saturation label set `L(x₀)` is used as its complete named subsumer set **only when** `consistency_retained_base_deterministic && unguarded_top_gcis == 0`.
- **Correctness Argument**:
  - **Unsatisfiable Case (`Some(false)`)**: Every rule in concept saturation (`s04` / `s07`) is a sound consequence of the TBox/RBox axioms of `O`. If starting from `{A(x₀)}` alone derives a clash (`⊥`), then `O ⊨ A ⊑ ⊥` in every model of `O`, regardless of any ABox nominals or global `⊤` axioms.
  - **Satisfiable and Complete Case (`Some(true)` with `concept_sat_complete[A] && consistency_retained_base_deterministic && unguarded_top_gcis == 0`)**:
    Let `G_nom` be the clash-free, deterministic completion graph obtained from the ontology's consistency check over the nominal ABox (`consistency_retained_base_deterministic == true`), and let `T_A` be the clash-free, deterministic saturation tree for `A` (`concept_sat_complete[A] == true`, meaning `T_A` never encountered a nominal `CCOIRS`, a disjunction `CCOR`, or a non-deterministic cardinality/inverse construct).
    Consider the disjoint union `M = G_nom ⊎ T_A`, where `x₀` is the root of `T_A`:
    1. Because `T_A` is nominal-free (`concept_sat_complete[A]` becomes `false` whenever any nominal concept or nominal role link is touched), `T_A` and `G_nom` share no named individuals or nominals, so no nominal-merging rule applies between `G_nom` and `T_A`.
    2. Because there are no role edges connecting `G_nom` and `T_A`, no universal restriction `∀R.C`, existential restriction `∃R.C`, role chain, or at-most restriction `≤n R.C` can propagate across the boundary between `G_nom` and `T_A`.
    3. The only axioms that apply to nodes of `T_A` without requiring a trigger concept in `L(x)` are global unguarded GCIs `⊤ ⊑ C`. When `unguarded_top_gcis == 0`, no such axioms exist; every TBox axiom is guarded by a positive concept or role trigger that is already saturated to fixpoint inside `T_A` and inside `G_nom` independently.
    Therefore, `M = G_nom ⊎ T_A` is a complete, clash-free pre-model of `O ∪ {A(x₀)}` in which the named concepts holding at `x₀` are functionality-identical to `L_{T_A}(x₀)`. Conversely, if `unguarded_top_gcis > 0` (for example, `⊤ ⊑ {o}` forcing every element to merge into nominal `o`), `T_A` is not closed under `⊤ ⊑ {o}` and the bridge must run the completion prover on `G_nom`.
- **Unit Test**:
  `konclude_ht::bridge::tests::native_nominal_saturation_outcome_requires_zero_unguarded_top_gcis` (`engine/src/konclude_ht/bridge.rs`).

### (d) `f6131f0e`: Binary-Digit Value Markers vs. Pairwise Disjointness

- **Location**: `engine/src/frontend/datatypes.rs` (`encode_value_disjointness`, `PAIRWISE_VALUE_LIMIT = 128`) and `engine/src/frontend/bottom_prepass.rs`.
- **Mechanism**:
  When a datatype or functional data property induces `k` distinct canonical literal value markers `M_0, M_1, ..., M_{k-1}` within a mutual-exclusion group:
  - For `k <= 128`, the frontend emits the `k(k-1)/2` pairwise disjointness clauses `M_i ⊓ M_j ⊑ ⊥` (`0 <= i < j < k`).
  - For `k > 128`, let `b = ⌈log₂ k⌉`. The frontend introduces `2b` fresh auxiliary concepts `Bit_{d,0}` and `Bit_{d,1}` (`0 <= d < b`), emits `b` disjointness clauses `Bit_{d,0} ⊓ Bit_{d,1} ⊑ ⊥`, and for each `0 <= i < k` and `0 <= d < b` emits the binary implication `M_i ⊑ Bit_{d, (i >> d) & 1}`.
- **Correctness Argument**:
  Let `Σ` be the signature of the ontology (including `M_0, ..., M_{k-1}` but excluding the fresh symbols `Bit_{d,0}, Bit_{d,1}`).
  1. **Soundness (Entails All Pairwise Disjointnesses)**: For any `0 <= i < j < k`, since `i != j`, their `b`-bit binary representations differ at some bit position `d ∈ {0, ..., b-1}`. Suppose `(i >> d) & 1 = 0` and `(j >> d) & 1 = 1`. In any interpretation `I` satisfying the binary-digit axioms, `M_i^I ⊆ Bit_{d,0}^I`, `M_j^I ⊆ Bit_{d,1}^I`, and `Bit_{d,0}^I ∩ Bit_{d,1}^I = ∅`, which implies `M_i^I ∩ M_j^I = ∅`. Every model of the binary-digit encoding satisfies `M_i ⊓ M_j ⊑ ⊥` for all `i != j`.
  2. **Completeness / Conservative Extension**: Given any `Σ`-interpretation `I` that satisfies `M_i^I ∩ M_j^I = ∅` for all `0 <= i < j < k`, every domain element `x ∈ Δ^I` belongs to at most one `M_i^I`. Define the extension `I'` to `Σ ∪ {Bit_{d,0}, Bit_{d,1}}` by:
     `Bit_{d,0}^{I'} = ⋃ { M_i^I | 0 <= i < k, (i >> d) & 1 == 0 }`
     `Bit_{d,1}^{I'} = ⋃ { M_j^I | 0 <= j < k, (j >> d) & 1 == 1 }`
     By construction, `M_i^{I'} ⊆ Bit_{d, (i >> d) & 1}^{I'}` for every `i` and `d`. And if `x ∈ Bit_{d,0}^{I'} ∩ Bit_{d,1}^{I'}`, then `x ∈ M_i^I` for some `i` with bit `d` equal to `0` and `x ∈ M_j^I` for some `j` with bit `d` equal to `1`; since `i != j`, this contradicts `M_i^I ∩ M_j^I = ∅`. Hence `Bit_{d,0}^{I'} ∩ Bit_{d,1}^{I'} = ∅`. Every model of the pairwise disjointness axioms extends to a model of the binary-digit axioms, so the two encodings have identical `Σ`-consequences while reducing clause count from `O(k²)` to `O(k log k)`.
- **Unit Test**:
  `frontend::bottom_prepass::tests::binary_digit_value_markers_above_pairwise_limit_match_pairwise_disjointness` (`engine/src/frontend/bottom_prepass.rs`).

### (e) `a4cddac7`: Coalescing of Branch Epochs and Backtracking Restoration

- **Location**: `engine/src/konclude_ht/model/substrate.rs` (`Arena::coalesce_epochs_to`) and `engine/src/konclude_ht/process/context.rs` (`ProcessContext::coalesce_branch_epochs_to`).
- **Mechanism**:
  In `Arena<T>`, `begin_epoch()` records the current undo-trail length `L` in `epochs` and sets `alloc_watermark = slots.len()`. During an active epoch, `get_mut(id)` pushes `(id, old_value)` onto `saves` if and only if `id.index() < alloc_watermark`. When nested epochs `d_1, d_2, ..., d_m` (`target_depth = d_1`) are coalesced via `coalesce_epochs_to(target_depth, target_slot_watermark)`:
  1. `epochs` is truncated to `target_depth` (with trail start `L_1 = epochs[target_depth - 1]`).
  2. `alloc_watermark` is restored to `target_slot_watermark` (`W_1`, the slot count when epoch `d_1` began).
  3. The trail slice `saves[L_1..]` is compacted in forward chronological order: any save with `id.index() >= W_1` is discarded, and for each slot `id.index() < W_1`, only the **first** save `(id, v_0)` recorded at or after `L_1` is kept (deduplicated via `coalesce_seen`).
- **Correctness Argument**:
  Let `S_0` be the arena state immediately before epoch `d_1` began (when `slots.len() == W_1` and `saves.len() == L_1`).
  1. **Pre-`d_1` Slots (`id.index() < W_1`)**: Because `W_1 <= W_2 <= ... <= W_m`, every epoch `d_k` (`1 <= k <= m`) has `alloc_watermark >= W_1`. Consequently, the very first time any slot `id` with `id.index() < W_1` is mutated during `d_1 ..= d_m`, `get_mut(id)` is guaranteed to push `(id, S_0[id])` onto `saves[L_1..]`. Later mutations to the same slot `id` in epochs `d_2 ..= d_m` may push additional entries `(id, S_k[id])`. By scanning `saves[L_1..]` forward and keeping only the first entry for each `id.index() < W_1`, `coalesce_epochs_to` retains `(id, S_0[id])` and removes all subsequent overwrites.
  2. **Post-`d_1` Mutations in the Coalesced Epoch**: Restoring `alloc_watermark = W_1` ensures that any subsequent mutation to a slot `id.index() < W_1` within the coalesced epoch saves `(id, S_0[id])` if not yet mutated, and any mutation to a slot `id.index() >= W_1` does not pollute `saves`.
  3. **Rollback Equivalence**: When `rollback_epoch()` later pops epoch `d_1`, it iterates `saves` down to `L_1`. Because each modified slot `id.index() < W_1` appears at most once in `saves[L_1..]` with its exact pre-`d_1` value `S_0[id]`, every slot `< W_1` is restored to `S_0[id]`, matching the state produced by rolling back `d_m, ..., d_1` individually.
- **Unit Test**:
  `konclude_ht::model::substrate::tests::coalesce_epochs_to_preserves_earliest_pre_target_saves_and_watermark` (`engine/src/konclude_ht/model/substrate.rs`).

### (f) Additional S6 Optimizations and Their Invariants

1. **Epoch-DFS Reachability in `source_named_subsumer_closure_seeded_rows` (`engine/src/konclude_ht/bridge.rs`)**:
   - Replaced the `FxHashSet<(usize, usize)>` closure table and `Vec<FxHashSet<usize>>` upper-concept table with sorted `Vec<u32>` adjacency lists and an epoch-stamped `seen: Vec<u32>` array.
   - **Invariant**: Within each fixpoint iteration, `u` iterates `0..n_named` in ascending order. When DFS from `u` visits a neighbor `vi < u`, `supers[vi]` has already been computed to full transitive reachability in the current `adj` graph, so all nodes reachable from `vi` are added directly from `supers[vi]` in `O(|supers[vi]|)` without re-traversing `adj` edges inside `vi`'s subgraph. When `vi >= u`, DFS expands `adj[vi]` on `stack`. By strong induction on `u`, `supers[u]` and `subs[vi]` contain the exact reflexive-free transitive closure of `adj`, producing the exact same fixpoint as the hash-set implementation.
2. **Retained Blocking Base Unmodified Fast Path (`engine/src/konclude_ht/completion/u20.rs`, `process/context.rs`, `model/substrate.rs`)**:
   - In `get_blocking_individual_node_candidate_iterator` (`u20.rs`), `run_saturation_loop` does not populate `node_switch_history`, which previously left `min_test_indi_node_id = 1` and caused `BlockingBaseIndex` to fall back to scanning all `1..=base_hi` retained consistency-base nodes on every subject (`9,285` nodes on `ore_ont_9899`).
   - Added `retained_blocking_base_unmodified` on `ProcessContext`: when `max_valid_indi_id > index.base_hi` and no base individual node (`<= base_node_count`) has changed its `label_set`, `merged_to`, or `blockable` state and no base label set (`<= base_label_set_count`) has changed its `hash` since `base_epoch_depth`, every base node's label set is already indexed in `BlockingBaseIndex::by_hash`. Advancing `min_test_indi_node_id` to `index.base_hi + 1` scans only fresh nodes created during the current concept test while querying base nodes in `O(1)` via `by_hash`.
3. **Precomputed Ancestor and Disjointness Tables in `BottomPrepass` (`engine/src/frontend/bottom_prepass.rs`)**:
   - Precomputes `ancestors[c]`, `ancestor_disjoint[c]`, and `self_disjoint[c]` once per `BottomPrepass::certify` call and deduplicates `role` per `owner` in `viable_context_common_types`, replacing repeated per-node BFS allocations (`BTreeSet`/`VecDeque`) with bitset/mark lookups over identical closure relations.
4. **Single-Pass `TInput` Deserialization and Streaming Writer (`engine/src/tableau.rs`, `engine/src/orchestrate/race.rs`)**:
   - `run_bridge_json_owned_compact` parses `producer_input: TInput` from `&input` once, drops the raw JSON string before allocating bridge structures, and validates `u32` ID bounds and `native_abox` directly on `&producer_input`. `PreparedHt::launch` streams `serde_json::to_writer` inside the background stdin thread via a `1 MiB` `BufWriter`.
5. **Subprocess `km ofn` Pass-1 Uncarried-Data Short-Circuit (`engine/src/cli.rs`)**:
   - Wired `abort_on_uncarried` into `ofn_to_clauses_for_classifier_pass` when `KM_CLASSIFIER_EXTENDED_ATOMIC_ABOX=1` in subprocess `km ofn`, matching the in-process frontend path so Pass 1 immediately hands off to Pass 2 (`KM_KEEP_DATA_ASSERTIONS=1`) when uncarried data assertions are present.

## 2. Justification of Speed Thresholds and Rule-Ontology Handling (S5)

Three numeric thresholds in the classification pipeline act purely as performance routing choices where both branches of the threshold are sound and complete for the ontology being classified.

### (a) `blocks > 64` Sandwich Decline (`engine/src/orchestrate/abox_quotient.rs:1763`)

- **Threshold**: `if sandwich && blocks > 64 && lines.len().saturating_mul(64) > assertions` in `abox_quotient::build_from_text`.
- **Role**: The ABox quotient sandwich is an optional fast path that tests whether the reduced quotient ontology `Q` and the TBox-only ontology `T` produce identical class taxonomies (`agrees=true`).
  - When `blocks <= 64` (or when `blocks > 64` and the quotient achieves at least a `64x` compression in assertion lines, such as `ore_ont_10929` where 244,134 assertions compress to 1,336 across 112 blocks), `build_from_text` constructs the quotient and runs the lower and upper classifications; if their taxonomies coincide (`agrees=true`), the sandwich returns that exact taxonomy; if they differ (`agrees=false`), it returns `None` and falls through to classifying the unreduced ontology.
  - When `blocks > 64` without `64x` assertion compression (such as `ore_ont_9151` and `ore_ont_9577` with `> 1,300` blocks), `build_from_text` immediately returns `Ok(None)` and routes directly to the complete classifier on the unreduced ontology without spending time on two preliminary classifications whose upper and lower bounds do not meet.
- **Why Both Sides Give the Same Answer**: Returning `Ok(None)` when `blocks > 64` simply skips an optional sufficient-condition sandwich probe and delegates directly to the full exact reasoner on the original ontology. Both sides compute the exact same classification taxonomy.

### (b) `<= 4,096` Data Assertions and `<= 8 MB` Ground-Rule Compilation (`engine/src/orchestrate/data_source.rs`)

- **Thresholds**:
  1. `DENSE_DATA_ASSERTION_DIRECT_PASS_THRESHOLD: usize = 4_096` (`engine/src/orchestrate/data_source.rs:4128`):
     On rule-free ontologies (`!has_rules`) with more than 4,096 `DataPropertyAssertion`s, `classifier_pass1_skips_to_keep_data_assertions` skips Pass 1 (which would scan the ontology only to discover uncarried data assertions and abort) and starts directly in Pass 2 (`keep_data_assertions = true`). Skipping the doomed Pass 1 probe does not alter the Pass 2 clause set or classification result.
  2. `AUTOMATIC_DATA_SOURCE_MAX_BYTES: usize = 8 * 1024 * 1024` (`8 MiB`) and `MAX_GROUNDED_RULE_AXIOMS: usize = 100_000` (`engine/src/orchestrate/data_source.rs:20-25, 3816-3996`):
     In `data_source::automatic_candidate`, the orchestrator optionally pre-grounds SWRL `DLSafeRule` axioms over named ABox individuals into materialised OWL functional axioms before invoking the main frontend.
- **What Happens to a Rule Ontology Above the Bound**:
  A rule ontology above the `8 MiB` grounded size limit or `100,000` grounded rule-instance limit is **never** answered without its rules:
  1. In `data_source::automatic_candidate` (`engine/src/orchestrate/data_source.rs:3947-3996`), if `ground_dl_safe_rules` returns `None` (because the grounded rule instances exceed `MAX_GROUNDED_RULE_AXIOMS = 100_000` or contain unsupported rule atoms) or if the rewritten source exceeds `AUTOMATIC_DATA_SOURCE_MAX_BYTES = 8 MiB` (`rewritten.len() > AUTOMATIC_DATA_SOURCE_MAX_BYTES`), `automatic_candidate` discards the rewritten text (`rewritten = None`) when no data-property rewrites were needed, or returns the original `DLSafeRule(...)` lines untouched inside `rewritten` when data-property rewrites were applied (`ground_dl_safe_rules` only strips `DLSafeRule` lines when it returns `Some(grounded)`).
  2. The original `DLSafeRule(...)` axioms remain in the OWL Functional Syntax input passed to the main frontend (`engine/src/frontend/`).
  3. The frontend parser (`engine/src/frontend/parse.rs`) parses every `DLSafeRule` into `Axiom::DLSafeRule`, records `profile.source.rule_axioms > 0` (`engine/src/orchestrate/mod.rs:3212`), and clausifies the rules into multi-variable horn/disjunctive DL clauses (`engine/src/frontend/normalise.rs`).
  4. In the orchestrator (`engine/src/orchestrate/mod.rs:2410, 4436-4550`), `profile.source.rule_axioms > 0` activates the dedicated rule-reasoning pipeline:
     - First, `run_rules_consistency_check` checks ABox + rule consistency via the rule engine (`rules-consistency`), detecting inconsistency on rule-clashing ontologies (such as `ore_ont_11367`, `1558`, `1967`, `6434`).
     - Second, `complete_rule_taxonomy` (`engine/src/orchestrate/mod.rs:2547`) grounds and saturates the rules over the ABox and TBox taxonomy.
     - Third, if a rule axiom cannot be soundly represented or grounded within the complete rule fragment, the frontend/orchestrator marks `uncarried_constructs` / `OutOfFragment` (`exit 2`), failing closed rather than silently dropping rules.

## 4. Round 2 Speed, Memory, and Realization Optimizations (`engine10`)

This section documents the round-2 speed, memory, and `--realize` fixes on `v170/speed` (merged with `development/v1.7.0` at `4b9e68bc`), their soundness and completeness arguments, and the unit tests that verify each invariant.

### (a) Single Minimum-Branching-Level Clash Pair in `ht_label_concept_clash_set_with_descriptors` (`engine/src/konclude_ht/completion/u08.rs`)

- **Location**: `engine/src/konclude_ht/completion/u08.rs:2011-2086` (`ht_label_concept_clash_set_with_descriptors`).
- **Mechanism**:
  When testing whether two completion nodes `sub_indi` and `super_indi` can merge, `ht_label_concept_clash_set_with_descriptors` checks for opposite-polarity concept descriptors `(C(sub_indi), ¬C(super_indi))` or `(¬C(sub_indi), C(super_indi))`:
  1. Previously, the `direct_lookup` branch lacked an early `return true` after finding an opposite-polarity pair and appended **every** opposite-polarity pair between `sub_indi` and `super_indi` into a single conjunctive `*clash_descriptors` chain, while the sorted merge walk returned the first pair in `concept_tag` order.
  2. Both branches now evaluate the branching level `lvl = max(tp_level(sub_tp), tp_level(super_tp))` of each opposite-polarity concept pair, select a single pair with the **minimum** branching level `lvl` (stopping immediately when `lvl <= 0`), and emit only that 2-descriptor clash pair `(sub_con_des, super_con_des)` into `*clash_descriptors`.
- **Correctness argument (rewritten for the supervisor review, T2)**:
  - *What the function returns.* The boolean result is unchanged: before and after the change it is `true` iff the two labels hold one concept tag with opposite polarity. Only the explanation (`clash_descriptors`) changed. Before: on the direct-lookup branch every opposite pair, on the sorted-walk branch the first pair in tag order. After: on both branches one pair, the one whose larger branching tag is smallest.
  - *Why one pair is a valid explanation.* A clash explanation for dependency-directed backtracking must be a set of facts that is contradictory by itself under the merge being tested, with their dependency track points. One pair `C(x)`, `¬C(y)` is contradictory by itself once `x` and `y` are merged, so its two descriptors with their own track points are such a set. Every larger set that contains it is also valid but weaker (it names more branch points). Backjumping on a valid explanation only skips branches whose choices are not in the explanation; the clash recurs in each of them, so no model is lost.
  - *Every caller.* The function has one caller, `ht_individuals_mergeable_with_clashes` (u08.rs), which returns `false` with the explanation when the merge is impossible. Its eight call sites (one in u02.rs, six in u08.rs, one in u25.rs) use the descriptors in one of three ways: they collect the explanations of all rejected merge candidates into the clash of the rule application (`merge_causing` in the at-most rules), they extend the explanation of one failed merge by the premise that demanded it (nominal and value merges) and raise it as a clash, or they discard it (a `scratch` set used only for the verdict, or a merge that succeeded). In the first use the union of valid per-candidate explanations is a valid explanation of "no candidate can be merged"; in the second the pair plus the premise is contradictory by itself. Single-pair explanations were already what every caller received whenever the sorted-walk branch ran, and which branch runs depends only on the two label sizes, not on the caller.
  - *Why the minimum level.* Any single pair is valid; the minimum-level pair is the one that lets the backjump go furthest back. Choosing it is a heuristic for speed, not a condition for correctness.
  - *Test mode.* `KM_CLASH_SET_COMPARE=<file>` computes the pre-engine10 explanation next to the new one in every call, asserts that the two boolean verdicts agree (a panic otherwise), and appends `clash-set-compare pid=... clashes=N differ=M` per process at exit (`differ` counts calls where the old explanation is not exactly the chosen pair). Satisfiability verdicts of the old and the new function are compared in effect by the 1,708-input pool gate: the reference binary uses the old function, the branch the new one, and the gate requires equal status and answer hash on every input. Counts are in the hand-back.
- **Unit Test**:
  `konclude_ht::completion::selftest::ht_label_concept_clash_set_with_descriptors_selects_single_minimum_branching_level_pair` (`engine/src/konclude_ht/completion/selftest.rs`).

### (c) Nominal-Free Individual Probe Extensions and `reset_cancel` in Realization (`engine/src/orchestrate/realize.rs`, `mod.rs`)

- **Location**: `engine/src/orchestrate/realize.rs` (`nominal_free_individual_extension`, `classify_probe_source`) and `engine/src/orchestrate/mod.rs` (`classify_with_evidence_mode`).
- **Mechanism**:
  1. **Stale `CANCEL` Flag Reset**: `classify_probe_source` and every recursive retry in `classify_with_evidence_mode` (after a declined `abox_quotient`, `positive_el_abox`, `flat_nf1`, or speculative `bounded_bridge_first` attempt) call `engine_run::reset_cancel()` before invoking the fallback classification pipeline, preventing a prior race winner's `CANCEL = true` flag from aborting subsequent `run_engine` calls with `signal 9: race won: skip spawn`.
  2. **Nominal-free block probes (`nominal_free_individual_extension`)**, used for `--realize` without `--values` and `--different`. The 78bbeb27 version of this function lost entailed `TYPE` rows (supervisor review, cases `review/e10/found/g22_496.ofn` and `g11_210.ofn`). The cause: its role collector read only atomic roles, so a role that occurred only under `ObjectInverseOf` (in `ObjectAllValuesFrom(ObjectInverseOf(r0) B)` asserted on `a5`, or in `ObjectSomeValuesFrom(ObjectInverseOf(r2) owl:Thing)` in the TBox) counted as unconstrained, and its assertions were dropped from the probe. More generally, the old case B accepted disjunction and universal restrictions on roles it judged inactive, and a forward bisimulation is not exact for either (a disjunctive "diamond" counterexample is in the unit tests). The function was rewritten from scratch (engine10 round 3) with one exact condition per case and a decline for everything else.

- **Definitions.** `O = T ∪ A`. A named object property `r` is *free* if no axiom mentions `r` except `ObjectPropertyAssertion(r x y)`, the outer property of `ClassAssertion(ObjectSomeValuesFrom(r F) x)`, `SubObjectPropertyOf(r owl:topObjectProperty)` (a tautology) and declarations or annotations. "Mentions" includes `ObjectInverseOf(r)` anywhere. The *group* of a named individual is its class under asserted `SameIndividual`. `S(g)` is the set of class expressions asserted for members of group `g`, without `owl:Thing` and without `∃r.F` for free `r`.

- **Case A, exact condition.** Every axiom kind is accepted by the scan (table below), and every `ObjectPropertyAssertion` uses a free property. The TBox may be any nominal-free OWL 2 DL TBox. Probes: one fresh class `P` per distinct `S(g)`, with `SubClassOf(P C)` for each `C ∈ S(g)` (or `SubClassOf(P owl:Thing)`).
  - *Claim.* If `O` is consistent, then for every named class `C` and named individual `a` in group `g`: `O ⊨ C(a)` iff `O' ⊨ P_{S(g)} ⊑ C`, and `O ⊨ a = b` iff `a` and `b` are in the same group.
  - *Soundness.* Given a model `I` of `O`, set `P^I` to the union of `g^I` over the groups with `S(g) = S`. Every member of such a group satisfies `S`, so `I` satisfies the probe axioms. Hence `O' ⊨ P ⊑ C` gives `a^I ∈ C^I` in every model of `O`.
  - *Completeness.* Let `J ⊨ O'` and `x ∈ P_{S(g)}^J \ C^J`, and let `I ⊨ O`. Build `K` as the disjoint union of `I` and `J`, interpret the members of `g` as `x` and every other individual as in `I`. For each free `r`, add to `r^K` the pairs required by the assertions on `g` (mapped to `x`) and one edge from `x` to an `r`-successor in `F^I` of `a^I` for each dropped `∃r.F` in `S(g)`. Then `K ⊨ T`, because a TBox without nominals, `owl:topObjectProperty`, `owl:topDataProperty`, keys and rules is preserved under disjoint unions, and `T` does not mention free properties. The assertions of `g` hold at `x` because `J` satisfies `⊓S(g)` and the free-property assertions were added. Every other assertion holds as in `I`: no assertion with a non-free property touches `g` (the case condition), class expressions are evaluated inside their component, and the added free edges only make outer `∃r` true. `SameIndividual` holds because whole groups are mapped together, `DifferentIndividuals` holds because `x` is outside `I` and the remaining individuals keep their `I` values. So `K ⊨ O` and `a^K = x ∉ C^K`. The same `K` maps `a` and any `b` outside `g` to different elements, which proves the `SAME` claim. If `O` is inconsistent, so is `O'`, and both paths print no rows.

- **Case B, exact condition.** Some assertion uses a non-free property, every accepted axiom also lies in the Horn fragment below, every class and property assertion is on a named individual, and every chain `r1 ... rn ⊑ s` (including `t t ⊑ t` for a transitive `t`) satisfies: every property `q ⊒* s` with a range axiom also satisfies `q ⊒* rn` (`⊒*` is the reflexive-transitive closure of the asserted inclusions). The Horn fragment: class expressions are named classes, `owl:Thing`, `owl:Nothing`, `ObjectIntersectionOf` and `ObjectSomeValuesFrom` over a named property; axioms are `SubClassOf`, `EquivalentClasses`, `DisjointClasses`, `SubObjectPropertyOf` (with chains), `EquivalentObjectProperties`, `TransitiveObjectProperty`, `ObjectPropertyDomain`, `ObjectPropertyRange`, `DisjointObjectProperties`, `IrreflexiveObjectProperty`, `AsymmetricObjectProperty`, the data property axioms that only constrain existing data edges (`SubDataPropertyOf`, `EquivalentDataProperties`, `DisjointDataProperties`, `FunctionalDataProperty`, `DataPropertyDomain`, `DataPropertyRange`, `DatatypeDefinition`), and the ABox kinds of the table. No data class expression may occur.
  - *Construction.* Labels: `L(g) = S(g)` plus, for every assertion `r(x, y)` with `y` in `g` and every `q ⊒* r` with `ObjectPropertyRange(q D)`, the label `D`. A property `r` is *relevant* if some `q ⊒* r` is in the premise set `Π`: the properties under `∃` on the left of `SubClassOf`, in any argument of `EquivalentClasses` or `DisjointClasses`, and with a domain axiom; `Π` is closed by adding all links of every chain whose super-property is relevant. The probe blocks are the coarsest partition of the groups that refines equal labels and is stable under successors along relevant asserted edges (colour refinement; the function declines if it has not settled after 64 rounds). Block `b` gets `SubClassOf(P_b D)` for `D ∈ L(b)` and `SubClassOf(P_b ObjectSomeValuesFrom(r P_b'))` for each relevant edge from `b` to `b'`.
  - *Soundness.* Range labels are entailed, so adding them as assertions keeps `O` equivalent. In a model `I` of `O`, set `P_b^I = ⋃ g^I` over `g ∈ b`; stability gives every member of `b` an `r`-successor in `b'`, so `I` satisfies the probe axioms.
  - *Completeness.* `O` is a Horn EL ontology with role inclusions, chains, domains, ranges and negative constraints. If `O` is consistent, its chase `U` (named individuals as distinct elements up to `SameIndividual`, fresh elements for existentials) is a model of `O`: `⊥`-rules never fire, and the negative property axioms and `DisjointClasses` hold in `U` because `U` maps homomorphically into every model and these constraints are preserved backwards by homomorphisms. Data property axioms are vacuous in `U`, which has no data edges, since no class expression and no assertion asks for one. So `O ⊨ C(a)` gives `a ∈ C^U`. Let `J ⊨ O'` and `x ∈ P_b^J` with `a ∈ b`. Start with `Z = {(g, y) | y ∈ P_{block(g)}^J}` and extend `Z` along the chase: when the chase creates a successor `v` of `u` for `∃r.F` and `(u, y) ∈ Z`, then `y ∈ (∃r.F)^J` by the invariant below and `J ⊨ T`, so add `(v, y')` for an `r`-successor `y' ∈ F^J`. Invariant: for `(u, y) ∈ Z`, every atomic label of `u` holds at `y`, and every relevant edge `u →r v` has a matching `y →r y'` with `(v, y') ∈ Z`. It holds initially (labels and stability) and is kept by every chase rule: a concept inclusion `D ⊑ E` fires at `u` only if `u ∈ D`, `D` uses only premise properties, so `y ∈ D^J` and `y ∈ E^J`; a property inclusion `r ⊑ s` with `s` relevant has `r` relevant, so the `r`-witness is also an `s`-witness in `J`; a chain into a relevant `s` has relevant links, so the witness path composes in `J`; a domain property is in `Π`; a range label `D` of `q` on `v` holds at `y'` because either `v` is a named group (then `D ∈ L(v)` by the chain condition, which makes every edge into `v` whose property is below `q` end in an asserted edge below `q`) or `v` was created by `∃r0` with `r0 ⊑* q`, and `y'` is an `r0`-successor in `J`. Edges of irrelevant properties never fire a rule, so `Z` needs no witness for them, and existentials over free properties lead only to elements no rule can see from a named individual. Hence `(a, x) ∈ Z` and `a ∈ C^U` give `x ∈ C^J`. Equalities: `U` keeps distinct groups distinct, so `SAME` rows are exactly the asserted groups.
  - The g22 and g11 counterexamples decline (inverse properties are outside the Horn fragment and the property is not free), and so does the disjunctive diamond.

- **What the scan does with every OWL 2 kind.** "A" means allowed in case A, "B" allowed in case B, "-" declines both. Annotations, `Declaration`, `AnnotationAssertion`, `SubAnnotationPropertyOf`, `AnnotationPropertyDomain` and `AnnotationPropertyRange` are skipped. Any kind not listed declines.

### (c2) Realization over a one-element domain (T4, `engine/src/orchestrate/realize.rs`)

- **Case.** `review/e10/found/hang_f808_194.ofn`: 36 named individuals and `SubClassOf(owl:Thing ObjectOneOf(:a0))`. `km classify --lines` answers in 0.02 s; `--realize` and `--values` ran past 120 s (also on development 4b9e68bc and with `KM_DISABLE_NAMED_ROLE_BOUND=1`).
- **Cause.** Not an endless loop. Realization adds one probe `P_a ≡ {a}` per individual, and `⊤ ⊑ {a0}` makes all probes equal. No hypertableau route accepts the input (inverse roles with a chain and a cardinality), so the consequence-based engine runs alone, and its merge hypotheses (docs/NOMINALS-CB.md section 10) grow faster than polynomially with the number of equal nominal probes: 8 individuals 3.4 s, 10 individuals 15.7 s, 12 individuals 41 s, 14 individuals more than 60 s (merge-state binary, `scratch/engine10/t4`). With `KM_NO_MERGE_HYPOTHESES=1` the 10-individual case takes 1.9 s, but that switch is incomplete. Every axiom of the core (the cover, the symmetric `s3`, the chain into `c1`, the cardinality on `s2`) is needed for the slowdown.
- **Fix.** `singleton_domain_individual` finds an asserted `SubClassOf(owl:Thing ObjectOneOf(o))` or `EquivalentClasses(owl:Thing ObjectOneOf(o))` with one distinct individual `o`. Then `classify_extended` probes only `o` (realization, values and differences) and `expand_singleton_domain` copies the rows of `o` to every individual. Lenient input is left on the old path; `KM_NO_SINGLETON_DOMAIN=1` turns the shortcut off.
- **Argument.** The axiom makes every model's domain the single element `o^I`, so for a consistent `O` every individual `a` has `a^I = o^I`: `O ⊨ C(a)` iff `O ⊨ C(o)`, `O ⊨ r(a, b)` iff `O ⊨ r(o, o)`, every pair of individuals is `SAME` and no pair is `DIFFERENT`. For an inconsistent `O` no rows are printed on either path.
- **Scope.** This removes the slowdown only for a one-individual cover. Covers with two or more individuals still create one probe per individual; the T4 fuzz run in the hand-back lists the cases that time out.
- **Unit test.** `orchestrate::realize::tests::singleton_domain_realization_finishes_and_equals_per_individual_probes`: the hang file under `--realize --values` within 10 s, and on a 6-individual variant the realization and property rows equal to those with `KM_NO_SINGLETON_DOMAIN=1`. `--values` without the shortcut does not finish on that variant (over 120 s), so the `VALUE` rows are checked against HermiT in the T4 fuzz run instead.

### (c3) Rows of unsatisfiable classes in realization output (round 4, U2)

- **Finding.** The `SUB` rows that `km classify --lines` prints for an unsatisfiable class depend on the route. Examples on development (`km-ec070684-sup`): for `scratch/engine10/fuzz/u2s/g89_1294.ofn` plain `classify --lines` (route `production_all`) prints `SUB :D :E` with `UNSAT :D`, while `classify --lines --realize` (the probe-extended ontology goes to `ht_bridge`) prints only `UNSAT :D`; for `g89_1134.ofn` the reference prints `SUB :D :B` with `UNSAT :D` under `--realize` too. The block probes of 4(c) change the probe-extended ontology and with it the route, so the realization output of the two probe paths differed in exactly these rows (3 of 3,000 fuzz cases).
- **Convention now.** `split_with_options` prints, for a consistent ontology, no `SUB` row whose subclass is unsatisfiable. The `UNSAT` row already states that the class is below every class, so no information is lost, and the rows no longer depend on the probe extension or on the route. This applies to every output of `classify_extended` (`--realize`, `--values`, `--different`, `--properties`), not to plain `classify`. Inconsistent ontologies are unchanged. `KM_REALIZE_KEEP_UNSAT_SUB=1` restores the old behaviour for comparisons.
- **Difference from development.** Development prints such rows under `--realize` whenever the route of its probe-extended ontology does (1 of 400 sampled fuzz cases, and on corpus inputs such as ore_ont_14861 with 1,440 such rows on the block-probe path). Those rows disappear; all other rows are unchanged.
- **Unit test.** `orchestrate::realize::tests::split_prints_no_sub_row_of_an_unsatisfiable_class`.

### (c5b) Narrow equivalence-conjunct relaxation (engine10 round 6, after the f2af2751/004c5b1d Ibex run)

- **Why.** 4(c5) removed the round-2 skip completely. The Ibex run of 004c5b1d then showed ore_ont_9540 back at its pre-round-2 cost (1.32 s / 59 MB to 7.69 s / 506 MB). The skip had two effects. It stopped forcing a name `A` whose told `SubClassOf(A C)` axioms are all entailed by `A`'s unique definition `D` (`C` is `D` or a top-level conjunct), so `A` becomes an equivalence host. It also dropped those told axioms. On 9540, keeping the axioms while hosting `A` did not help (18.5 s, 1.2 GB), so the gain needs both effects.
- **What the cost was.** On 10140 the round-2 rule turned 3,643 PR definitions into trigger-absorbed hosts (HT phase 8 s to 26.7 s). Restricting the rule to definitions that are not syntactically triggerable left two PR definitions with told cardinality superclasses as lazy hosts. That still cost 19 s (HT phase 11 s to 30 s). On 9540 the useful name is `Rectangle == =4 has_point.right_angle_point and Quadrilateral`, with told `SubClassOf(Rectangle Quadrilateral)`. Relaxing it alone takes 9540 to 4 s / 62 MB. Relaxing the two definitions with universal restrictions alone made 9540 slower (22 s and 33 s). Relaxing six such OBI definitions made ore_ont_10080 30 % slower.
- **Rule now (`relaxed_names` in `bridge_tinput_with_trigger_absorption`).** Relax `A` only if all four hold:
  1. All of `A`'s told superclasses are entailed by its unique definition.
  2. They are all named classes.
  3. `A` is a host whose definition is not syntactically triggerable, by the same fixpoint as `non_triggerable_hosts`.
  4. The definition requires at least two successors: a positive `>= n r.C` with `n >= 2`, or a negated `<= n r.C` with `n >= 1`.

  The reverse direction of such a definition cannot be absorbed into triggers, which need `n <= 1`. For a forced name it therefore stays a general inclusion whose `<= n-1` branch is open on every node. Every other told `SubClassOf` forces its name, as before. Diagnostics: `KM_BRIDGE_FORCE_ALL_TOLD_SUBCLASS=1` restores the old rule, and `KM_BRIDGE_RELAX_ANY_TOLD_SUPERCLASS=1` drops conditions 2 and 4.
- **Why answers cannot change.** A relaxed name's told axioms are all entailed by its definition. Every way the equivalence is then encoded contains `A -> D`: lazy CCEQ unfolding, trigger absorption with forward unfolding, or the two plain inclusions as fallback. `A -> D` entails each dropped axiom. The round-2 self-connected cache guard (`u17`, `u22`) stays removed: alone it changed no time (4(c5)), and the differential fuzz below found no answer change without it.
- **Measured (ws, Ibex-built mimalloc binaries, the same core, back to back, CPU s / MB).**

  |---|---|---|
  | ore_ont_9540 | 14.8 / 831 and 14.1 / 794 | 1.22 / 61 and 0.94 / 61 |
  | ore_ont_10140 | 16.7 / 777 | 14.9 / 777 |
  | ore_ont_10080 | 4.60 / 172 and 3.81 / 173 | 4.42 / 174 and 3.56 / 170 |

  Answer hashes are equal in every run.
- **Differential fuzz (`scratch/engine10/w4/fuzz_eq.py`).** Generated ontologies with unique `EquivalentClasses(:X ObjectIntersectionOf(...))` definitions, redundant told conjunct axioms, nominals and cardinalities. Each case was classified (`--lines`) through the forced bridge route with the widest relaxation and with the old rule, and by the automatic route as the oracle. 300 cases: the rule fired in 41 cases where the bridge answered, and all 131 bridge answers equal the oracle. An earlier 200-case run with the non-triggerable-only rule: 100 answers compared, 0 differences.

### (c6) Core blocking concept marking (engine10 round 6, W2 item 1, `engine/src/konclude_ht/bridge.rs`)

- **What.** `mark_core_blocking_concepts` ports Konclude's `CCoreBlockingConceptMarkerPreProcess` (on by default). It runs once per bridged ontology after the role-automata and branch-trigger passes and the terminology stamp, the same place in the order as in Konclude. Before this, no concept was ever marked, so no label set had a core concept descriptor and `get_anywhere_blocking_individual_node_linked_canidate_hashed` always fell back to the linear candidate scan (`get_anywhere_blocking_individual_node_canidate_hashed`).
- **Faithful details.** The C++ marks the quantifier concept itself (`opConcept = concept`), for every operand, with polarity `opNegated ^ opNegate`, which equals the operand linker's negation flag. The port does the same. Konclude has process data for every concept at this point (`CDataExtenderPreProcess`); the port allocates it where missing.
- **One approximation.** Konclude skips the pass for EL ontologies, using flags from its expression builder that the port does not have. The port treats the arena as EL when every concept operator is one of atom, TOP, BOTTOM, AND, SOME, nominal, EQ or SUB.
- **Why answers cannot change.** The marks only decide which blocker candidates the hashed search tests and in which order. Every candidate still goes through `is_individual_node_valid_blocker` and `is_individual_node_blocking`, the same tests the linear scan applies, so any node found blocks soundly. A different blocker can change the shape of the completion graph, and so which valid model a test returns, but not whether a test is satisfiable. Model-based pruning stays sound because every returned model is still a model.
- **Checked.** See the round 6 hand-back: answer hashes on 314 inputs, `--lines --realize` rows on 40 inputs with individuals, and the lib tests.

### (c10) Front-end worker: no second conformance check; tag-first clause decoding (engine10 round 6, item 2)

Profiles (Ibex-built, frame pointers, mimalloc) of ore_ont_12567, 12128 and 1673 show two repeated costs. 15687 and 5162 are not front-end bound: 15687 spends its time in HT completion inside the orchestrator, and the 5162 front end takes 2.7 s.

- **Not done.** The remaining front-end cost is the parse itself and hash-map growth spread over about ten maps (1-2 % each under mimalloc). Pre-sizing them would gain a few percent at most. Interning names would change the syntax types used across the whole front end.

- **Now.** Interned chains are immutable `(role, next)` steps, so a head's set is its `next`'s set plus one role. Each head's set is built once from its nearest cached ancestor. While role keys stay below 4,096 it is a bitset over role ids (a copy of the parent's words plus one bit). Above that it falls back to a hash set, so inputs with very many roles cost no more memory than before.
- **Why answers cannot change.** The function returns the same membership. The structure is internal to this cache, and the unit test `interned_role_linker_membership_matches_chain_walk` compares it with a direct chain walk for role ids on both sides of the limit. No rule, order or result of saturation changes.

### (c12) Packed keys for the critical-concept tested set (engine10 round 7)

- **What.** `CriticalIndividualNodeConceptTestSet` (`process/sat_queue.rs`) records which (node, concept) pairs `check_critical_concepts_for_node` has already tested. Konclude uses the same global set of pairs. Its probe is a cache miss on most calls, and on ore_ont_7361 the table held up to 816 MiB (dhat, during a resize).
- **Now.** A pair whose two raw ids lie in `0..2^32` is stored as one `u64` (`packed_tested_key`), half the table of 16-byte pair keys. Any other pair goes into a second set of the original pairs.
- **Why answers cannot change.** Distinct pairs give distinct keys, so membership is exactly that of the pair set. Unit test: `critical_individual_node_concept_test_set_packs_without_collisions`.
- **Measured (one Ibex node, one core, A = 4(c11), B = this; A B B A, wall s).** 7361: 26.9, 26.4 to 26.0, 26.6. 14572: 25.6, 26.7 to 24.4, 24.0. 3794: 29.3, 29.3 to 27.5, 28.8. Peak memory is 30-120 MB lower. The output is byte-identical.

### (c13) Functional object roles: `<=1 R` as a domain concept of R (engine10 round 8)

- **Cause of the saturation gap on 7361, 14572 and 3794.**
  - **Measured.** With a private instrumented copy of Konclude, on the same node type (Gold 6248), KM ran 19.7 M critical-concept tests on 7361 against Konclude's 2.0 M (3794: 19.6 M against 6.0 M).
  - **Equal in both.** Direct critical queueing, copy and substitute counts, copy-dependency links (58 k each) and the propagation code.
  - **Different.** The nodes with many copies tested 340-440 critical concepts each in KM against 17-109 in Konclude. The root of those copies queued exactly 337 at-most concepts: 7361 has 337 functional roles.
  - **Root cause.** The bridge put `<=1 R` for every functional role R on TOP, so every saturation node carried all of them as critical at-most tests, and each test was propagated into every copy of the node.
- **Now.** As Konclude's builder does for `FunctionalObjectProperty(R)` (CConcreteOntologyUpdateBuilder.cpp 1735, `role->addDomainConceptLinker(<=1 R)`), `<=1 R` is a domain concept of R. Saturation (s02, s03) and completion (u10 link creation, u34 role assertions) add it to exactly the nodes with an R-edge, including edges through sub-roles, equivalent roles and inverses. Data roles keep the TOP encoding: data-property assertions do not pass through the link creation that applies domain lists. A first version without this exception missed an inconsistency (two values for a functional data property on one individual, combined with object merges). `KM_BRIDGE_FUNCTIONAL_ON_TOP=1` restores the old encoding.
- **Why answers cannot change.** `T <= (<=1 R)` and `exists R.T <= (<=1 R)` are equivalent, because a node without R-successors satisfies `<=1 R`. This is an equivalent encoding, not a calculus change.
- **Tests.**
  - **Unit test.** `functional_role_domain_encoding_merges_successors_through_every_edge_kind`: sub-role, sub-role plus role, a two-level hierarchy with an equivalent role, an inverse stored from the other end, and a symmetric role.
  - **Targeted differential fuzz (`scratch/engine10/w4/fuzz_func2.py`).** 2,200 cases (two runs of 1,100). Each combines sub-roles, two-level hierarchies, equivalent roles, inverses, inverse-functional and symmetric functional roles, ABox role assertions, hasValue edges, edges that meet only after a merge, SameIndividual, hasSelf, functional data properties and data values that clash after an object merge. 30 % of cases are TBox-only. Each case ran under the new and old encodings on the automatic route (`--lines --realize --different`) and on the bridge route (classification).
  - **Fuzz result.** On the fixed version, every row difference between the new and old encodings (13 cases) is a row only the new encoding produces. HermiT entails every such row (`EntailCheck`, `isEntailed`), so the old TOP encoding was incomplete on those cases, and the new one is not. The rows are `SAME`/`TYPE` from functional merges of named individuals, and one `UNSAT`.
  - **HermiT on 200 sampled cases (`HermitVerifyD`, with DIFFERENT rows).** No consistency disagreement. Every km-only `SAME` row (51) is entailed; HermiT's SAME listing is known to be incomplete. Km-only `UNSAT` rows occur only in inconsistent ontologies, where km lists every class.
  - **Problems that predate this change.** Two missed inconsistencies (`w4/fzv/v101_13.ofn`, reduced to 16 axioms in `w4/repro/v101_13.base.min.ofn`; `w4/fzw/v404_79.ofn`) and two missed unsatisfiable classes (`w4/fzw/v303_10.ofn`, `v303_300.ofn`). The same rows are missing under both encodings and in every build back to f2af2751.
- **Measured (Ibex, Gold 6248, one core, A = 10463934, B = this; A B B A, wall s / MB).** 7361: 31.95, 31.27 / 4,252 to 18.93, 18.65 / 3,821. 14572: 31.58, 31.48 / 4,198 to 18.74, 18.92 / 3,704. 3794: 36.59, 36.32 / 4,596 to 27.15, 27.83 / 4,415. Answers are identical. Critical tests on 7361 fall to 2.27 M (Konclude 2.04 M) and on 3794 to 5.90 M (Konclude 5.99 M). The ancestor-forwarding adds on 7361 fall from 4.05 M to 1.93 M (Konclude 1.50 M).

### (c14) Chunked arena storage (engine10 round 8, item 4)

- **Cause.** After (c13), libc was 41 % of the HT worker's samples on 7361 (33 % on 3794), almost all `memmove` inside `Vec` growth. The arena that held the 1.2 GB successor-record pool grew by 25 % at a time. Each step copied the whole pool, and the old and new copies were both held for a moment. `linked_role_successor_data_for_individual_id` accounted for 25 % of all samples through this growth path.
- **Now.** `Arena` stores its items in a `ChunkStore`. The first chunk grows like a `Vec` up to 65,536 items; tight arenas keep the 25 % step there. Every later chunk is allocated once at full size and never moves. Element `i` is at `chunks[i >> 16][i & 0xffff]`. Ids, push, pop, truncate, journaled epochs and iteration order are unchanged.
- **Why answers cannot change.** Only the storage layout changes. Each id still maps to the same object, and the order of every operation is the same.
- **Tests.** `chunked_arena_matches_vec_across_chunk_boundaries` checks push, pop, truncate inside and across chunks, journaled rollback and iteration in both directions against a `Vec`, for tight and ordinary arenas. The existing arena tests (tight bound, clear, release, lazy epochs) pass.
- **Measured (Ibex, Gold 6248, one core, A = be0663f9, B = this; A B B A, wall s / MB).** 7361: 18.47, 18.52 / 3,814 to 15.33, 14.96 / 2,693. 14572: 18.49, 18.45 / 3,704 to 15.25, 14.84 / 2,701. 3794: 27.20, 27.46 / 4,441 to 24.28, 24.50 / 3,597. Answers are identical, and all 314 answer hashes are equal.

### (c15) Successor records with shared creation-role lists (engine10 round 9, item 1)

- **Cause.** A successor record (`SaturationSuccessorData`) was 80 bytes. About 32 of them were the inline creation-role list (`SmallVec<[NegLink<RoleId>; 1]>`), and every `forceNewCreation` record copied its predecessor's list. Konclude records are 56 bytes: `mCreationRoleLinker` is a pointer, and a new record takes over its predecessor's chain.
- **Now.** The record holds a 4-byte head into an immutable cell pool in the process context (`sat_succ_creation_role_cells`, 12 bytes per cell). The record is 48 bytes. A new record shares its predecessor's chain, as in Konclude. Adding a role puts one cell in front (Konclude's `initNegLinker(...)->append(...)`). The cell pool follows the record pool's branch epochs, coalescing, swap and clears.
- **Kept KM's answers rather than copying Konclude.** Konclude negates a deactivated role in place, so older records that share the chain see the negation too. KM's per-record copies never did. The shared list copies only the cells in front of the negated one, so every record sees exactly the list it saw before. Reading the lists first means reading two arrays instead of one; the order (newest first) is the same.
- **Why answers cannot change.** Every read returns the same roles in the same order as the former private copy, and no rule reads anything else from the list.
- **Tests.** `sat1_shared_creation_role_lists_keep_per_record_values`: lists of four successive records with repeated and new roles, a negation that must not reach older records, rollback of a negation by a branch epoch, and building a list from a slice.
- **Measured (Ibex, one core, A = be9c8b24, B = this; A B B A, wall s / MB).** 7361: 15.46, 15.51 / 2,698 to 15.52, 15.40 / 2,468. 14572: 15.58, 15.47 / 2,700 to 15.66, 15.39 / 2,472. 3794: 24.85, 24.51 / 3,596 to 24.11, 24.01 / 3,309. Answers are identical, and all 314 answer hashes are equal.

### (c16) EL worker: dense fixpoints handed over dictionary-coded (engine10 round 9, 12567)

- **Gap.** On ore_ont_12567 (EL route), KM took 30.6 s on one core against Konclude's 14.7 s. KM's front end (7.5 s) is faster than Konclude's parse plus preprocessing (9.4 s). The EL worker took 18.0 s: saturation 8.8, release 2.3, output strings 1.6, binary serialisation 3.5, the rest under 2. Konclude's saturation plus classification take 3.4 s.
- **Cause.** For a dense taxonomy the worker built one owned string per subsumption pair (a `BTreeMap<String, Vec<String>>`), then re-encoded that map into the dictionary-coded binary handoff by hashing every string again. Before that it freed the whole saturation state, millions of small allocations, so that the string map would not stack on top of it.
- **Now.** When the worker's rule already chooses the binary handoff (at least 1,000 subject rows and `KM_ELC_OUTPUT_BINARY_MIN_RELATIONS`, default 2 million relations), the worker counts rows and relations on the fixpoint, before any output is built. It then returns the dictionary-coded rows directly, the form the in-process EL path already returns and the orchestrator already reads. The worker process exits right after writing, so in that case it leaves the dead saturation state to process exit instead of freeing it. Sparser or partial answers, and rooted repair workers, are unchanged.
- **Why answers cannot change.** The rows, their order and each row's superclass order are those of the string map, and the orchestrator reads both binary forms through the same `compact_subsumptions` branch. Only the name table differs, which the reader resolves by name (bottom is `⊥`, which `is_bottom` accepts, as on the in-process path).
- **Tests.** `dense_worker_fixpoint_output_matches_the_string_map`: 1,209 subjects through the general fixpoint (existential join, conjunction, an unsatisfiable class). The dense form must rebuild exactly the string map, including superclass order, and a fixpoint under the threshold must keep the string map. On 12567 the final output file is byte-identical.
- **Measured (Ibex, one core, A = 919067a1, B = this; A B B A, wall s / MB).** 12567: 34.05, 33.79 / 2,295 to 27.41, 27.23 / 2,294. EL worker phases on ws: release 2.27 to 0.05 s, output 1.61 to 0.68 s, serialise 3.50 to 0.12 s. 12128 and 1673 (not EL) are unchanged. All 314 answer hashes are equal.
