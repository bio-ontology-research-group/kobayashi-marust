# KM v1.6.1 acceptance

v1.6.1 makes the v1.6.0 reference stage scale and makes its failures
legible. It changes no theorem of v1.6.0. The release is accepted when every
clause below holds on the tagged commit, with the evidence recorded here.

## Q1. The stage publishes a sparse answer that the v1.6.0 theorems cover

`lean/ContextCalculus/SparseTaxonomy.lean` defines the sparse publication
(`SparseTaxonomy`, one row per requested name: an unsatisfiability flag and
the named subsumers) and its dense denotation `SparseTaxonomy.dense`. The
routing gate's `#print axioms` log reports at most `propext`,
`Classical.choice`, `Quot.sound` for

- `SparseTaxonomy.sparseReferenceAnswer_dense` (the sparse EL answer denotes
  exactly v1.6.0's `referenceAnswer`),
- `SparseTaxonomy.sparseElReference_agrees` and
  `SparseTaxonomy.sparseAlcReference_agrees` (what the binary prints is what
  `elReferenceExecution` and `alcReferenceExecution` publish, so
  `kmSupervisor_sound` and `kmSupervisor_complete_on_EL_or_ALC` cover it),
- `SparseTaxonomy.sparseElReference_correct`,
  `SparseTaxonomy.sparseAlcReference_correct` and
  `SparseTaxonomy.sparseElReference_complete`.

`km-el-reference` prints only the sparse form and never materialises the
`named × named` list; the Rust stage parses it without building an N × N
structure, checks its shape (rows in request order, every superclass a
requested name) and declines otherwise.

## Q2. The stage publishes more, and never disagrees

The forced suite run (`KM_REFERENCE_FORCE=1`, all 1,781 checkers-on inputs,
on Ibex) publishes strictly more of the 592 recognised inputs than v1.6.0's
378, loses none of those 378, and every forced answer equals the unforced
answer under the v1.6.0 digest normalisation. The remaining misses are
listed by cause (time budget, memory, guard, other) with sizes, and the
release notes state the new practical limit.

## Q3. Failures report their cause

The 14 inputs that v1.6.0 recorded as "exit 2 after printing the matrix"
are explained. A checker that fails after starting to write reports its own
error, not its output: the Rust stage takes the decline reason from stderr
first, and `km-el-reference` reports write errors as `io error` with exit 4,
never as `failed to read`. A test covers each.

## Q4. Nothing else changes

As P4 of v1.6.0: C1 (no wrong answer on the held-out half and the pool),
S1 against the same-day v1.5.3 and Konclude on Ibex, and L1/R1 (five Lean
gates, checkers-on suite, Java, full Rust suite from the tag) with receipts.
The reference stage runs only after every production route declines, so S1
is expected to be unchanged.
