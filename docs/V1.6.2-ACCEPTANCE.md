# KM v1.6.2 acceptance

v1.6.2 proves the frontend for the reference procedures: from the OWL 2
functional syntax text to an answer that is exact under the OWL 2 direct
semantics, for OWL EL and OWL ALC. It certifies km's own answers on those
inputs by comparison with that procedure. It changes no theorem of v1.6.0
or v1.6.1. The plan is `docs/V1.6.2-FRONTEND-PLAN.md`, section 7 (phase A).
The release is accepted when every clause below holds on the tagged commit,
with the evidence recorded here.

## F1. The OWL reference procedure is exact under the direct semantics

`lean/ContextCalculus/OWL/Semantics.lean` defines OWL 2 class expressions,
axioms and the direct semantics (`OWL.EntailsSub`); `OWL/Parse.lean` parses
the functional syntax (prefix expansion by FSS 2.4 and 3.7, the standard
prefixes `owl rdf rdfs xsd`). `OWLFrontend/Reference.lean` proves

```lean
theorem owlReference_sound (h : owlReference O requested = some a) :
    a.named = requested.eraseDups ∧
      ∀ i j (hi : i < a.named.length) (hj : j < a.named.length),
        (a.bit i j = true ↔ OWL.EntailsSub O a.named[i] a.named[j])

theorem owlReference_complete (requested : List OWL.IRI)
    (h : O.isEL = true ∨ O.isALC = true) :
    (owlReference O requested).isSome = true
```

with the translation theorems `translateEL_correct`, `translateALC_correct`
(polarity definers, one per occurrence), `translateEL_isSome`,
`translateALC_isSome`, the probe lemmas
`OWL.unsatisfiable_iff_entailsSub_fresh` and
`OWL.inconsistent_iff_entailsSub_fresh`, and `owlReadout_exact` (what
`km-owl-reference` prints, the inconsistency verdict, the unsatisfiable
classes and the subsumers of the satisfiable ones, is what these theorems
describe). The routing gate builds these modules and their tests and
requires each theorem in its axiom audit with at most `propext`,
`Classical.choice`, `Quot.sound` and no `sorryAx`.

The executable declines ALC inputs whose translation has more than 16
concept names (`KM_ALC_REFERENCE_MAX_CONCEPTS`, as the v1.6.0 ALC stage):
type elimination is exponential in that number. `owlReference_complete`
is about the procedure; the budget is a decline of the executable, never a
wrong answer.

## F2. km's answers agree with the OWL reference on the suite

With `KM_FRONTEND_CHECK=1`, `km classify` runs `km-owl-reference` on the
input text after it has its answer and compares the inconsistency verdict,
the unsatisfiable classes and the subsumptions between satisfiable named
classes. Agreement makes km's answer exact by F1; disagreement fails closed
(exit 6); a decline changes nothing. On the 1,781-input checkers-on suite
on Ibex: no disagreement, every decline listed by cause (outside `F`, in
`F` but neither EL nor ALC, ALC budget with the concept count, time budget),
and the inputs where km itself fails are the same as in v1.6.1.

## F3. The Rust parser follows the specification on IRI identity

Two spellings of one IRI (an abbreviated `p:x` and its expansion) denote
one entity, builtins are recognised by their expanded IRI, and malformed
input gives a parse error, never a panic. The deviations found by the
differential test (`results/agents/2026-11-12/v162-parse/README.md`) are
each fixed or listed as open; on suite inputs that spell each entity one
way, km's printed answers are unchanged.

## F4. Nothing else changes

As P4 of v1.6.0: C1 (no wrong answer on the held-out half and the pool),
S1 against the same-day v1.5.3 on Ibex (mean and median wall-time ratio at
most 1.10), and L1/R1 (five Lean gates, checkers-on suite, Java, full Rust
suite from the tag) with receipts. `KM_FRONTEND_CHECK` is off by default,
so S1 measures the production routes.

## Not in v1.6.2

- Phase B of the plan (checking the Rust clause stream, the role encoding
  and the coverage condition) moves to v1.6.3, which needs the same role
  reasoning for ALCHI, SHI and regular chains (`docs/V1.6.3-HT-PLAN.md`).
- Inputs in `F` with inverses, symmetry, or role axioms together with ALC
  constructors have no reference procedure yet (v1.6.3).
- No theorem about the parser itself (for example that a printed ontology
  parses back); the differential test against the Rust parser is the
  evidence.
