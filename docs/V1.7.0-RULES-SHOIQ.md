# Deciding DL-safe rules with nominals, inverse roles and number restrictions (SHOIQ)

Status 2026-11-17 (task `engine6`, branch `v170/rules-shoiq`).

## 1. Problem

When an ontology contains DL-safe SWRL rules (`DLSafeRule` or `HasKey`, which `frontend::has_key` rewrites into a DL-safe rule) and no object nominal (`ObjectOneOf`, `ObjectHasValue`) or universal role (`owl:topObjectProperty`) occurs, rule conclusions constrain named individuals only. A consistent model of the ABox and rules can be combined by disjoint union with any countermodel of a non-entailed TBox subsumption, so checking consistency with the rule worker and classifying the rule-free TBox is exact.

When an object nominal or `owl:topObjectProperty` occurs (`orchestrate::rules_reach_class_queries`), a rule conclusion about a named individual can reach class queries and entail new class subsumptions. The clausal rule worker (`KM_RULES_CLASSIFY=1`, `Tableau::classify` in `engine/src/tableau.rs`) decides `O`-guarded rule clauses over nominal roots for `SHOI` and `SHOQ`, but it cannot decide `SHOIQ`:
- `Tableau` has no `NN`-rule for the interaction of nominals, inverse roles, and number restrictions;
- `cb_to_ht` fences qualified or $>1$ cardinalities alongside inverse roles as `inverse+number(SHIQ)`;
- `cb_to_ht::build_rule_clause` defers `DifferentIndividualsAtom` in rule bodies because `HAtom` has no node-inequality atom.

This caused KM to refuse:
- `ore_ont_8250` on all queries (`classify`, `--realize`, `--properties`, `--values`, and `km incremental-source`);
- `ore_ont_2526`, `ore_ont_16630`, `ore_ont_6615`, and `rules_shoiq_properties.ofn` on `km classify --properties` (where the property probes `P_r ≡ ∃r.B` and `P_⊤ ≡ ∃owl:topObjectProperty.B` introduce inverse roles and the universal hub nominal `⊤ ⊑ ∃S.{g}`).

## 2. Method: Exact Finite Grounding into `SHOIQ`

Under the OWL 2 Direct Semantics with DL-safe rules (`DLSafeModel` in `lean/ContextCalculus/RulesRouteSemantics.lean`), every object variable $x$ of a rule ranges over the named-individual domain
$$D_N^\mathcal{I} = \{a^\mathcal{I} \mid a \in N\}$$
where $N = \{a_1, \dots, a_m\}$ is the finite set of named individuals occurring in the ontology. No unique-name assumption is made: distinct names $a, b \in N$ may denote the same domain element $a^\mathcal{I} = b^\mathcal{I}$, and universal quantification over $D_N^\mathcal{I}$ is equivalent to quantification over the syntax names $a \in N$.

Define a fresh guard class $G$ (`__ground_path_domain_*`) by the equivalence:
$$G \equiv \{a_1\} \sqcup \dots \sqcup \{a_m\} \quad (\text{or } G \equiv \bot \text{ when } N = \emptyset).$$
In every interpretation $\mathcal{I}$ satisfying this definition, $G^\mathcal{I} = D_N^\mathcal{I}$.

### 2.1 Pre-normalisation of Keys and Data Atoms

Before object-rule compilation:
1. `frontend::has_key` rewrites every `HasKey` axiom into its equivalent DL-safe rule.
2. `frontend::rule_data_atoms` rewrites any data variable occurring in the body in a single `DataPropertyAtom(p, t, ?v)` and in zero or more `DataRangeAtom(D_i, ?v)` atoms into a fresh class atom over $C \equiv \text{DataSomeValuesFrom}(p, \bigcap_i D_i)$.
3. `frontend::ground_rule_source` replaces constant data atoms `DataPropertyAtom(p, t, l)` in rules and `DataPropertyAssertion(p, a, l)` / `NegativeDataPropertyAssertion(p, a, l)` in the ABox with fresh defined classes equivalent to `DataHasValue(p, l)`.

### 2.2 Three Compilation Shapes for Object Rules

Each object rule $\text{body}(\vec{x}) \to \text{head}(\vec{x})$ over $N$ is compiled into ordinary `SHOIQ` class and assertion axioms in one of three forms:

1. **Endpoint-grounded path rules (`frontend::rule_paths::path`)**:
   When the head is a single role atom $s(x_0, x_k)$ with $x_0 \neq x_k$ and the body is a simple chain of role atoms connecting $x_0$ to $x_k$ along directed steps $e_1, \dots, e_k$ (each $e_i$ a role $r$ or `ObjectInverseOf(r)`), only the endpoint $x_k$ is grounded over $a \in N$ ($|N|$ instances):
   $$G \sqcap \exists e_1.\bigl(G \sqcap \exists e_2.\bigl(\dots \sqcap \exists e_k.\{a\}\bigr)\bigr) \;\sqsubseteq\; \exists s.\{a\}.$$

2. **Rooted tree / feedback-vertex rules (`frontend::rule_paths::rooted_tree`)**:
   When the head is non-empty and all head atoms share a single subject variable $x_0$ (with no self-loop $r(x_0, x_0)$ in the head), the compiler selects a feedback vertex set $F \subseteq \text{Vars} \setminus \{x_0\}$ containing:
   - every target variable $u \neq x_0$ occurring in the head;
   - every variable $u$ occurring in a self-loop `ObjectPropertyAtom(r, ?u, ?u)`, `SameIndividualAtom(?u, ?u)`, or `DifferentIndividualsAtom(?u, ?u)` in the body;
   - one variable $u \neq x_0$ from each `SameIndividualAtom(?u, ?v)` or `DifferentIndividualsAtom(?u, ?v)` ($u \neq v$) in the body if neither $u$ nor $v$ is already in $F$;
   - vertices $u \neq x_0$ of maximum degree that break all cycles among the remaining variables $\text{Vars} \setminus F$.

   When $x_0 \notin F$, the free variables $T = \text{Vars} \setminus F$ form a single connected tree rooted at $x_0$, and every body atom whose terms all lie in $F \cup N$ (`fixed_atoms`) has its subject variable reached as the target of a role edge from $T$, only the variables in $F$ are grounded over assignments $\sigma: F \to N$ ($|N|^{|F|}$ instances). For each $\sigma$:
   - every tree variable $v \in T$ is guarded by $G$, with `SameIndividualAtom(?v, t)` compiled to $\{\sigma(t)\}$, `DifferentIndividualsAtom(?v, t)` compiled to $\neg\{\sigma(t)\}$, and each edge `ObjectPropertyAtom(r, ?v, ?w)` (or inverse) rolled into $\exists e.\text{Subtree}(w)$;
   - any fixed atom on $\sigma(t)$ is conjoined onto the nominal $\{\sigma(t)\}$ at the first edge where the tree of $x_0$ reaches $t$;
   - the head atoms at $x_0$ roll into $\text{Conclusion}_\sigma$, emitting one inclusion:
     $$\text{Premise}_\sigma \;\sqsubseteq\; \text{Conclusion}_\sigma.$$

   Instance counts on the target ontologies:
   - `ore_ont_8250` ($|N| = 62$): Rule 1 (9 variables, 10 body atoms, head `reachesSource(?vdisk, ?pint2)`) has $x_0 = \text{?vdisk}$ and $F = \{\text{?pint2}\}$, giving $62^1 = 62$ instances instead of $62^2 = 3,844$. Rule 2 (4 variables, `DifferentIndividualsAtom(?hyp, ?htype)`, head `MachineHostingUnsupportedDomain(?m)`) has $x_0 = \text{?m}$ and $F = \{\text{?htype}\}$, giving $62^1 = 62$ instances instead of $62^4 = 14,776,336$.
   - `ore_ont_6615` ($|N| = 16$): Rule 1 (6 variables, 3 head atoms with subject `?t-method` and targets `?sub-class`, `?t-class`) has $x_0 = \text{?t-method}$ and $F = \{\text{?sub-class}, \text{?t-class}\}$, giving $16^2 = 256$ instances instead of $16^3 = 4,096$.

3. **Anchor-lifted general rules (`frontend::ground_rules`)**:
   Any rule not covered by (1) or (2) selects a feedback vertex set $F$ containing all head variables, self-loop variables, one variable per `SameIndividualAtom` / `DifferentIndividualsAtom`, and cycle-breaking vertices so $\text{Vars} \setminus F$ is a forest. A fresh individual `anchor` with functional nominal links `link_a(anchor, a)` and `∀link_a.{a}` for each $a \in N$, plus a cover role `cover(anchor, a)` and `∀cover.G`, lifts fixed atoms to `∃link_a.C` and free tree components to `∃cover.Tree` at `{anchor}`, emitting $|N|^{|F|}$ `SubClassOf` axioms.

### 2.3 Hand-off to the Native `SHOIQ` Route and Object Guard

The compiled ontology $O'$ has no `DLSafeRule` axioms. `orchestrate` (`KM_GROUND_RULE_SOURCE`) hands $O'$ to the native `SHOIQ` completion bridge (`Route::HtBridge`, `konclude_ht::bridge`), restricts subject probes to source classes (`KM_GROUND_PRIVATE_CLASS_FILE`), and strips all generated private classes from published `subsumptions` and `unsatisfiable` lists.

When `--properties` (or a source TBox axiom) introduces an axiom that fails at a blank data node in the bridge's one-sorted completion graph (such as the hub axiom `⊤ ⊑ ∃S.{g}` emitted by `frontend::universal_role` for `P_⊤ ≡ ∃owl:topObjectProperty.B`), `KM_GROUND_RULE_SOURCE` retries the native bridge with the exact two-sorted object guard (`KM_BRIDGE_OBJECT_GUARD=1`, `frontend::object_guard`), which guards blank-failing inclusions with `G_obj` (`__objguard__`) while preserving global `DataPropertyRange` inclusions (`⊤ ⊑ ∀u.D`) unguarded so the bridge continues to recognize them as global ranges.

In the bridge admission and saturation path (`cb_to_ht`, `orchestrate::race`, `konclude_ht::bridge`, `konclude_ht::saturation::s07`):
- `n`-ary role chains (`chain-n` in `rbox`) compiled by `normalise` into binary chains over `__chain__k` are verified against `tin.chains` rather than fenced as `unknown-rbox`;
- `DisjointObjectProperties` (`role-constraint` in `rbox`), compiled by `parse` and `normalise` into `R(x,y) ∧ S(x,y) → ⊥` and consumed by `konclude_ht::bridge` via `disjoint_role_pair_clause`, is admitted by `bridge_fences_supported` when its clause is present in `tin.clauses`;
- a local datatype universal restriction `∀r.D` or existential restriction on a data role whose global range `R` is disjoint from `D` is admitted when the disjointness clause `D(y) ∧ R(y) → ⊥` is present in `tin.clauses`;
- `xsd:string` atomic data cardinality bounds up to $8$ are admitted, with `cell_literals_and_requirement` requiring at least $\max_i(\text{at-least}_i, \text{at-most}_i + 1)$ realizing values per cell;
- `successor_extension_has_pending_work` checks only the active pending worklists drained by `process_successor_functional_concepts_extensions` (excluding the permanent `copying_initializing_role_process_linker` list), and `add_qualified_functional_atmost_concept_extension_processing` deduplicates descriptors per node via `qualified_functional_atmost_concept_process_set` when extension processing is active.

### 2.4 Forest-Model Upper Bound on Named-Individual Object-Property Pairs (`NamedRoleBound`)

For ontologies with large named-individual domains (such as `ore_ont_15063` with $|N| = 1,605$ and `ore_ont_7345` with $|N| = 2,221$), naive endpoint grounding emits $|N|$ inclusions per rule and `--values` emits $|R| \cdot |N|$ probe classes, exceeding the native bridge's nominal and clause budgets.

When an ontology $O$ contains no `SameIndividual`, `HasKey`, non-tautological uses of `owl:topObjectProperty`, positive nominals (outside closed value-partition definitions $V \equiv \{a_1, \dots, a_k\}$ whose defined class $V$ never occurs positively elsewhere, and query probe definitions in `http://km.invalid/`), or positive `ObjectMaxCardinality` / `ObjectExactCardinality` with bound $\ge 1$, every consistent model $\mathcal{I}$ of $O$ can be forest-unravelled from the named individuals $N$ so that anonymous existential witnesses never merge with named individuals or connect two distinct named individuals. Under this forest-model invariant (`frontend::named_role_bound::NamedRoleBound`):
- the pairs $(r, a, b) \in N \times N$ that can hold in any consistent model are bounded above by the least fixpoint $E^+$ of the asserted `ObjectPropertyAssertion`s, universal diagonal self-loops $(r, a, a)$ from `ReflexiveObjectProperty(r)`, positive `ObjectHasSelf(r)`, and tree-folding `ObjectPropertyChain`s, closed under `SubObjectPropertyOf`, `InverseObjectProperties`, `SymmetricObjectProperty`, `TransitiveObjectProperty`, `ObjectPropertyChain`, and the `ObjectPropertyAtom` projection of `DLSafeRule`s (declining if any functional or inverse-functional role equates two distinct named individuals in $E^+$);
- correction (2026-11-20): the forest invariant does not keep anonymous witnesses from contributing edges between named individuals. A path can leave $a$ into its anonymous tree and return to $a$, and a role chain or transitive role turns it into a named edge ($s_1 \circ s_3 \sqsubseteq c_1$, $s_3^- \sqsubseteq s_1$, $s_1$ symmetric and $B \sqsubseteq \exists s_3^-.B$ give $c_1(a, a)$ for $B(a)$). The pairwise tree-folding test on the top-level chain misses nested chains, transitive roles and excursions inside a longer chain ($k \circ r \circ r^-$ around an ABox edge $k$). `named_role_bound::excursion_roles` now decides these on a finite abstraction of the forest model (one node for the named individuals, one per generating role, flags for derivations through anonymous nodes; see `docs/MODEL-EXPORT.md`, "Reconstructed structures are not models"), and every reported role joins the diagonal roles, whose targets are all named individuals;
- any rule whose body has no satisfying assignment in $E^+$ is vacuous in every consistent model and is eliminated (`ore_ont_7345`: all $4$ rules have $0$ reachable bindings because `Checkpoint_has_Approach` has no asserted edges; `ore_ont_12451`: all $3$ rules have $0$ reachable bindings, reducing classification time from $248\text{ s}$ to $32\text{ s}$);
- any rule whose reachable bindings in $E^+$ each have a connected body-role spanning tree rooted at a variable shared by all head atoms is compiled directly into one exact `SubClassOf` axiom per reachable binding without introducing the full $|N|$-nominal covering domain disjunction $G$ (`ore_ont_15063`: $5$ grounded instances instead of $1,605$);
- `orchestrate::abox_rows::extension` (`--values`) emits `V_{r,b} ≡ ∃r.{b}` probes only for targets $b$ reachable along $r$ in $E^+$ when $r$ has no universal diagonal self-loop.

For rule-free ontologies (`all_rules.is_empty()` and `vp_classes.is_empty()`) that contain `SameIndividual`, positive `ObjectHasValue`, positive `ObjectMaxCardinality` / `ObjectExactCardinality` with bound $\ge 1$, or negative `ObjectMinCardinality` / `ObjectExactCardinality` with bound $\ge 2$ (`forest_exact_for_rules == false`), `NamedRoleBound` extends the fixpoint with:
- wildcard-source target sets $W_{\text{src}}(r) = \{b \in N \mid (*, b) \in r^+\}$ seeded by positive `ObjectHasValue(r, b)` (`Concept::Exists(Role::Name(r), Nominal(b))`) and wildcard-target source sets $W_{\text{dst}}(r) = \{a \in N \mid (a, *) \in r^+\}$ seeded by positive `ObjectHasValue(ObjectInverseOf(r), a)` (`Concept::Exists(Role::Inverse(r), Nominal(a))`), plus forward anonymous-edge reachability `pos_existential_roles` (`Role::Name(r)` in a positive existential/min-cardinality or negated universal/max-cardinality restriction), backward anonymous-edge reachability `inv_existential_roles` (`Role::Inverse(r)` in a positive existential/min-cardinality or negated universal/max-cardinality restriction), and universal reachability $U(r)$ for every $r \in \text{inv\_existential\_roles}$;
- closure of $(E^+, W_{\text{src}}, W_{\text{dst}}, \text{self\_roles}, \text{pos\_existential\_roles}, \text{inv\_existential\_roles}, U)$ under `SubObjectPropertyOf`, `InverseObjectProperties` (which swaps $W_{\text{src}}$ with $W_{\text{dst}}$, swaps `pos_existential_roles` with `inv_existential_roles`, swaps functionality with inverse-functionality, and transposes $E^+$), `SymmetricObjectProperty`, `TransitiveObjectProperty`, and `ObjectPropertyChain` relational composition;
- an equivalence relation $\sim$ on $N$ initialized with `SameIndividual(a, b)` and closed in the same simultaneous fixpoint under functional roles (`FunctionalObjectProperty(r)`, positive `ObjectMaxCardinality(n, r, C)` / `ObjectExactCardinality(n, r, C)` with $n \ge 1$, and negative `ObjectMinCardinality(n, r, C)` / `ObjectExactCardinality(n, r, C)` with $n \ge 2$, propagating downward along subroles and swapping with inverse-functionality across `InverseObjectProperties` and `SymmetricObjectProperty`) and inverse-functional roles (`InverseFunctionalObjectProperty(r)`, positive `ObjectMaxCardinality(n, ObjectInverseOf(r), C)` with $n \ge 1$, and negative `ObjectMinCardinality(n, ObjectInverseOf(r), C)` with $n \ge 2$):
  1. whenever $(a, b_1), (a, b_2) \in E^+(f)$ (or $f \in \text{self\_roles}$ and $(a, b) \in E^+(f)$), $f \in \text{functional}$ merges $b_1 \sim b_2$ (and symmetrically $(a_1, b), (a_2, b) \in E^+(f)$ for $f \in \text{inv\_functional}$ merges $a_1 \sim a_2$);
  2. whenever a merging role $f \in \text{functional} \cup \text{inv\_functional}$ has a wildcard endpoint or an existential/min-cardinality occurrence that can create an anonymous edge on $f$ and merge an anonymous witness with a named individual or across anonymous trees ($f \in \text{functional}$ with $f \in U$, $W_{\text{dst}}(f) \neq \emptyset$, $f \in \text{pos\_existential\_roles} \land (W_{\text{src}}(f) \neq \emptyset \lor E^+(f) \neq \emptyset)$, or $(f \in \text{inv\_existential\_roles} \lor f \in \text{self\_roles}) \land W_{\text{src}}(f) \neq \emptyset$; or $f \in \text{inv\_functional}$ with $f \in U$, $W_{\text{src}}(f) \neq \emptyset$, $f \in \text{inv\_existential\_roles} \land (W_{\text{dst}}(f) \neq \emptyset \lor E^+(f) \neq \emptyset)$, or $(f \in \text{pos\_existential\_roles} \lor f \in \text{self\_roles}) \land W_{\text{dst}}(f) \neq \emptyset$), every named individual is treated as possibly merged (`all_named_merged = true`) and every active or existential role is widened to $U(r)$;
- congruence closure of $\sim$ across **all** object properties $s$: whenever $u \sim v$, every edge $(a, u) \in E^+(s)$ adds $(a, v) \in E^+(s)$, every edge $(u, b) \in E^+(s)$ adds $(v, b) \in E^+(s)$, every $u \in W_{\text{src}}(s)$ adds $v \in W_{\text{src}}(s)$, and every $u \in W_{\text{dst}}(s)$ adds $v \in W_{\text{dst}}(s)$;
- conservative definition polarity: for an `EquivalentClasses(C, E)` axiom where $C \neq \top$ is a named class occurring in at most one `EquivalentClasses` axiom, not occurring in $E$, and having no positive occurrence anywhere else in the ontology, $E$ is walked only in negative polarity ($E \sqsubseteq C$), since any model of $(\mathcal{O} \setminus \{C \equiv E\}) \cup \{E \sqsubseteq C\}$ satisfies $C \sqsubseteq E$ by shrinking $C^{\mathcal{I}} := E^{\mathcal{I}}$ without changing any role or individual interpretation;
- diagnostic environment switch: setting `KM_DISABLE_NAMED_ROLE_BOUND=1` (or `KM_NAMED_ROLE_BOUND=0`) disables `NamedRoleBound::compute` so that `orchestrate::abox_rows::extension` emits exact `V_{r,b} ≡ ∃r.{b}` probes for every `(r, b)` pair.

Because every TBox construct that can force a role edge to a named individual (`ObjectHasValue`, `ObjectHasSelf`, inverse existentials) or merge two individuals (`FunctionalObjectProperty`, `InverseFunctionalObjectProperty`, `ObjectMaxCardinality`, negated `ObjectMinCardinality >= 2`, including through anonymous witnesses) is collected globally across the ontology and closed simultaneously with the RBox hierarchy, property chains, and congruence of $\sim$ on all roles, `reachable_targets_by_full_iri(r)` is a sound upper bound on $\{b \in N \mid O \models r(a, b) \text{ for some } a \in N\}$.

## 3. Soundness and Completeness

**Proposition (Exactness of Rooted-Tree and Anchor-Lifted Grounding).**
Let $O$ be an OWL 2 DL ontology with DL-safe rules, let $N$ be its set of named individuals, and let $O'$ be the grounded ontology produced by `ground_rule_source::compile`.
1. Every DL-safe model $\mathcal{I}$ of $O$ extends to a model $\mathcal{I}'$ of $O'$ by interpreting $G^{\mathcal{I}'} = D_N^\mathcal{I}$, each private definition class by its defining expression, `anchor` as any element of $\Delta^\mathcal{I}$, $\text{link}_a^{\mathcal{I}'} = \{(\text{anchor}^{\mathcal{I}'}, a^\mathcal{I})\}$, and $\text{cover}^{\mathcal{I}'} = \{\text{anchor}^{\mathcal{I}'}\} \times D_N^\mathcal{I}$.
2. Conversely, the restriction of any model $\mathcal{I}'$ of $O'$ to the vocabulary of $O$ is a DL-safe model of $O$.

*Proof.*
For a rooted-tree rule $\text{body}(\vec{x}) \to \text{head}(\vec{x})$ with root $x_0$ and feedback vertex set $F \subseteq \text{Vars} \setminus \{x_0\}$, let $\sigma: F \to N$ be any assignment of named individuals to the variables in $F$. By induction on the finite tree $T = \text{Vars} \setminus F$ rooted at $x_0$, an element $e_0 \in \Delta^{\mathcal{I}'}$ belongs to $\text{Premise}_\sigma^{\mathcal{I}'}$ if and only if $e_0 \in G^{\mathcal{I}'} = D_N^{\mathcal{I}'}$ and there exist elements $e_v \in G^{\mathcal{I}'} = D_N^{\mathcal{I}'}$ for each $v \in T \setminus \{x_0\}$ such that adding $v \mapsto e_v$ to the interpretation $u \mapsto \sigma(u)^{\mathcal{I}'}$ ($u \in F$) satisfies every class, role, equality (`{a}`), and inequality (`¬{a}`) atom of $\text{body}$ (including any fixed atom conjoined onto $\{\sigma(u)\}$, since $\{\sigma(u)\}^{\mathcal{I}'} = \{\sigma(u)^{\mathcal{I}'}\}$ is a singleton). Similarly, $e_0 \in \text{Conclusion}_\sigma^{\mathcal{I}'}$ if and only if the head atoms hold at $x_0 \mapsto e_0$ and $u \mapsto \sigma(u)^{\mathcal{I}'}$ ($u \in F$). Quantifying over all $\sigma: F \to N$ and all $e_0 \in D_N^{\mathcal{I}'}$ is equivalent to quantifying over all variable assignments $\vec{x} \in (D_N^{\mathcal{I}'})^{\text{Vars}}$. The same bijection holds for endpoint-grounded path rules ($F = \{x_k\}$) and anchor-lifted rules (where $\text{anchor}^{\mathcal{I}'} \in (\exists \text{link}_a.C)^{\mathcal{I}'} \iff a^{\mathcal{I}'} \in C^{\mathcal{I}'}$ and $\text{anchor}^{\mathcal{I}'} \in (\exists \text{cover}.C)^{\mathcal{I}'} \iff \exists e \in D_N^{\mathcal{I}'}:\; e \in C^{\mathcal{I}'}$). Since $O'$ is a conservative extension of $O$ over the fresh private symbols, $O$ and $O'$ have the same consistency, class hierarchy, and individual and property entailments over the signature of $O$. $\square$

### Preservation Across Query Reductions and Sessions

- **Class hierarchy (`km classify`) and `km incremental-source`**: Both call `orchestrate::classify_with_evidence_mode`, which runs `data_source::automatic_candidate` and `KM_GROUND_RULE_SOURCE`.
- **Realization (`--realize`) and object property values (`--values`)**: Add only fresh class definitions `P_a ≡ {a}` and `V_{r,b} ≡ ∃r.{b}` over the existing named individuals $N$. No fresh named individual is introduced, so $D_N^\mathcal{I}$ is unchanged.
- **Object property hierarchy (`--properties`)**: Because `DLSafeRule` and `HasKey` mark `properties::source_shape` as `inverse_free = false`, `--properties` uses only fresh class definitions `P_r ≡ ∃r.B`, `P_{r^-} ≡ ∃r⁻.B`, and (when nominals or `owl:topObjectProperty` are present and `isolated_blank_element_admissible` does not already rule out `TOPPROP`) `P_⊤ ≡ ∃owl:topObjectProperty.B`. When `owl:topObjectProperty` occurs only as the super-property of `SubObjectPropertyOf(R, owl:topObjectProperty)` tautologies, no `ReflexiveObjectProperty` occurs, and every class axiom holds at an isolated blank element (`holds_at_blank`), extending any model with one fresh isolated blank element shows that no named property covers $\Delta^\mathcal{I} \times \Delta^\mathcal{I}$, so `P_⊤` is omitted. When `P_⊤` is emitted, `ground_rule_source::compile` runs before `frontend::universal_role` rewrites `P_⊤` with its fresh hub individual `g` (`<urn:km:internal:universal-role#hub>`), so $g$ is introduced only after rule grounding and never enters the DL-safe rule grounding domain $N$.

### Certificate Requests and the Rules Route

The ground-rule reduction has no Lean certificate. When a run consumes certificates (`KM_LEAN_CHECKERS`, `KM_REQUIRE_LEAN_CHECKERS`, `KM_CB_LEAN_REQUIRED`, `KM_CB_CERT_BUNDLE`, model export, an HT certificate request, `KM_RULES_LEAN_CERT`, `KM_RULES_LEAN_CHECKER`, `KM_RULES_INERT_CERT` or `KM_RULES_INERT_LEAN_CHECKER`), or with `KM_RULES_ROUTE_FIRST=1`, a rule ontology first takes the schedule of v1.6.5: the automatic route without the reduction, which sends it to the rules route (`ht_rules`) and its certificate. Only when that schedule declines (exit 3) or one of its workers exceeds its time or memory limit does the reduction answer; the run then records a `cannot_check` event (family `rules`, certificate `ground-rule-source`) and prints the decline reason. Any other failure, including a rejected certificate, fails the run. Default runs keep the reduction as the first attempt.

## 4. Built-in Atoms and Refusal Conditions

When an ontology contains no existential data value generators (`frontend::finite_data_rules::Scan::certified`) and all rule-head built-ins are result observers (`sqwrl:select` and its companions, projected by `parse::parse_rule_atoms`), `ground_rule_source::compile` evaluates body `BuiltInAtom`s (`swrlb:equal`, `swrlb:notEqual`, `swrlb:lessThan`, `swrlb:lessThanOrEqual`, `swrlb:greaterThan`, `swrlb:greaterThanOrEqual`, `swrlb:add`, `swrlb:subtract`) over the finite set of asserted data literals via `data_rules::finite_data_rule_plan` (`ore_ont_3726` and `ore_ont_7278`).

KM refuses with exit code 3 and an explicit message naming any unsupported `BuiltInAtom` IRI when:
- a rule contains a `BuiltInAtom` that cannot be evaluated over a finite constant-literal grounding (such as `ore_ont_714`, where `http://www.w3.org/2003/11/swrlb#add` binds a fresh variable used in a head `DataPropertyAtom` that generates unbounded new integer values), a data variable shared by two `DataPropertyAtom`s outside the finite-grounding certificate, or a data variable in the head;
- the total number of grounded rule instances after path, rooted-tree, and `NamedRoleBound` reduction exceeds the instance cap (`100,000`), or the compiled ontology lies outside the native `SHOIQ` bridge certificate and its fallback routes cannot decide the full construct combination without dropping clauses.

## 5. Literals Typed `rdfs:Literal` in the OWL API, HermiT, and `km incremental-source`

Nine corpus ontologies (`ore_ont_10906`, `13129`, `15516`, `237`, `2669`, `13880`, `5539`, `5206`, `8280`) contain literals typed `rdfs:Literal` (`"NULL"^^rdfs:Literal` in `DataPropertyAssertion`s across the eight `rdbowlizer` relational-mapping ontologies, and `"Diabetes"^^rdfs:Literal` / `"Hypertension"^^rdfs:Literal` in `DataPropertyAssertion`s and a `DLSafeRule` body `DataPropertyAtom` in `ore_ont_13129`).

### 5.1 What the OWL API and HermiT Do

1. **OWL 2 Specification**: Under the OWL 2 Structural Specification (Section 4.1) and Direct Semantics (Section 2.1), `rdfs:Literal` is the top data range ($\Delta_D$) and has no lexical space or lexical-to-value mapping $L_{rdfs:Literal}$. Writing `"lex"^^rdfs:Literal` is a syntax/profile error in strict OWL 2 DL.
2. **OWL API (`OWLLiteralImplNoCompression`)**: The OWL API Functional Syntax parser accepts `"lex"^^rdfs:Literal` syntactically and constructs an `OWLLiteral` whose lexical form is `"lex"` and whose datatype is `rdfs:Literal` (`isTopDatatype() == true`, `isRDFPlainLiteral() == false`).
3. **HermiT (`OWLClausification$DataRangeConverter.visit(OWLLiteral)`)**:
   - HermiT passes the literal to `Constant.create(lex, "http://www.w3.org/2000/01/rdf-schema#Literal")`, which calls `DatatypeRegistry.parseLiteral`.
   - Because `DatatypeRegistry` registers no `DatatypeHandler` for `rdfs:Literal`, **default HermiT (`Configuration.ignoreUnsupportedDatatypes = false`) throws `UnsupportedDatatypeException`** (`"Literals can only use the datatypes from the OWL 2 datatype map... The datatype 'http://www.w3.org/2000/01/rdf-schema#Literal' is not part of the OWL 2 datatype map and HermiT cannot parse this literal"`).
   - **When `Configuration.ignoreUnsupportedDatatypes = true`** (which Protégé and the ORE harness set), `DataRangeConverter.visit(OWLLiteral)` catches `UnsupportedDatatypeException` and calls `Constant.createAnonymous(lex)`, creating an opaque constant in `internal:anonymous-constants` keyed by `lex`. Two occurrences of `"lex"^^rdfs:Literal` map to the same interned `Constant`, which lies in `rdfs:Literal` (`InternalDatatype.RDFS_LITERAL`) and has no membership in any concrete datatype (`xsd:string`, `xsd:integer`, etc.).
   - On the eight `rdbowlizer` ontologies (`10906`, `15516`, `237`, `2669`, `13880`, `5539`, `5206`, `8280`), the object ABox, TBox `DisjointClasses`, and object `DLSafeRule`s entail an inconsistency independent of `"NULL"^^rdfs:Literal`, so HermiT reports `isConsistent() == false`. On `ore_ont_13129`, HermiT 1.4.3.456 throws `IllegalArgumentException: A SWRL rule uses a built-in atom, but built-in atoms are not supported yet` on its `swrlb:greaterThan` rule; the ontology itself is consistent.

### 5.2 Session Option for `km incremental-source` (`km-serve`)

- **Default CLI behavior (unchanged)**: `km classify` and `km incremental-source` default to `--unknown-datatypes=strict`, which rejects `"lex"^^rdfs:Literal` at `conformance::check_literal_datatypes` with exit code 2 (`"invalid OWL 2 DL input"`).
- **Session option**: `km incremental-source` now accepts `--unknown-datatypes=strict|free` on the command line and an optional `"unknown_datatypes": "strict" | "free"` field on JSONL `init` and `replace` commands (`engine/src/cli.rs`, `engine/src/incr_session.rs`, `engine/src/source_incremental.rs`). When `"free"` is enabled (`conformance::unknown_datatypes_free() == true`), `check_literal_datatypes`, `data_rules`, and `datatypes::vocabulary::literal_status` admit `"lex"^^rdfs:Literal` as an opaque value concept `__dt__val__"lex"^^rdfs:Literal` (equal to itself, inside `rdfs:Literal`, and undecided against concrete datatypes), matching HermiT's `Constant.createAnonymous(lex)` under `ignoreUnsupportedDatatypes = true`. Under `"unknown_datatypes": "free"`, `km incremental-source` reports `status: "ok", consistent: false, dropped: 0` on the eight `rdbowlizer` ontologies (`10906`, `15516`, `237`, `2669`, `13880`, `5539`, `5206`, `8280`) and `status: "ok", consistent: true, dropped: 0` on `ore_ont_13129`.
