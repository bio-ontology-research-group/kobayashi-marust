## 2. Goal 1: `owl:Thing` equivalence (`ore_ont_12566`, `ore_ont_13584`) and top-property equivalence

### 2.1 Root cause

1. **Classes equivalent to `owl:Thing`**:
   - `Classifier.Session` (`km-serve`) emits `SUB` lines only between declared classes and does not emit `SubClassOf(owl:Thing, C)` (`TOP` lines).
   - In `ore_ont_12566`, `SubClassOf(Intangible-Thing, support#Thing)`, `EquivalentClasses(Tangible-Thing, ObjectComplementOf(Intangible-Thing))`, `SubClassOf(Tangible-Thing, Temporal-Thing)`, and `SubClassOf(Temporal-Thing, support#Thing)` entail `owl:Thing ≡ Intangible-Thing ⊔ ¬Intangible-Thing ⊑ support#Thing`.
   - In `ore_ont_13584`, `ReflexiveObjectProperty(descriptionOf)` and `ObjectPropertyDomain(descriptionOf, Sign)` (with `SubClassOf(Sign, Object)`) entail `owl:Thing ⊑ ∃descriptionOf.⊤ ⊑ Sign ⊑ Object`.
   - Because `KMReasoner.rebuildHierarchy` previously placed `owl:Thing` as a strict superclass of every satisfiable class without checking `SubClassOf(owl:Thing, C)`, `<support#Thing>`, `<Sign>`, and `<Object>` were placed as direct children of `owl:Thing` instead of inside `getTopClassNode()`. That caused 394 call differences (335 `differ_structure` + 59 `differ_content` across 8 cells) on `ore_ont_12566` alone.
2. **Properties equivalent to `owl:topObjectProperty` and `owl:topDataProperty`**:
   - In `KMReasoner.ensureProperties()`, `rawSubs` initialized `TOP_ID` with every property without propagating `TOP_ID` into a property's sub-property set when `SubObjectPropertyOf(owl:topObjectProperty, p)` or `EquivalentObjectProperties(owl:topObjectProperty, p)` was asserted.
   - In `DataPropertyModel.build`, `reach[TOP_ID]` and `reach[BOTTOM_ID]` were not propagated through explicit `SubDataPropertyOf(owl:topDataProperty, p)` or `EquivalentDataProperties(owl:topDataProperty, p)` edges before running Floyd-Warshall transitive closure.

### 2.2 Fix and unit tests

- Added `Classifier.topClasses(String ofnSource)` (`Classifier.java`), which invokes `km classify --lines --top -` and parses `TOP\t<iri>` lines.
- Added `KMReasoner.unionTopEquivalents(int n, String sessionSource)`:
  - Directly unions `C` (and all its superclasses in `rawSup`) with `thingId` when the ontology asserts `SubClassOf(owl:Thing, C)`, `EquivalentClasses(owl:Thing, C)`, `ObjectPropertyDomain(owl:topObjectProperty, C)`, `ObjectPropertyRange(owl:topObjectProperty, C)`, `DataPropertyDomain(owl:topDataProperty, C)`, or `ObjectPropertyDomain(r, C)` / `ObjectPropertyRange(r, C)` for a `ReflexiveObjectProperty(r)`.
  - Calls `Classifier.topClasses(sessionSource)` whenever the ontology contains an axiom shape that can entail a non-trivial top class (`SubClassOf(owl:Thing, ...)`, `SubClassOf(ObjectComplementOf(...), ...)`, `ObjectUnionOf`, `ObjectOneOf`, `ObjectHasSelf`, `ReflexiveObjectProperty`, or `topObjectProperty`/`topDataProperty` domain/range), and unions every returned `TOP` IRI with `thingId`.
- Propagated `TOP_ID` reachability in `KMReasoner.ensureProperties()` and `DataPropertyModel.build(...)`.
- Updated `HermitDifferentialTest#classEquivalentToThingIsATypeOfEveryIndividual` and added `ConventionsTest#classesAndPropertiesEquivalentToTopAgreeWithHermit` testing `getTopClassNode`, `getSubClasses`, `getSuperClasses`, `getEquivalentClasses`, `getTypes`, `getTopObjectPropertyNode`, `getSubObjectProperties`, `getSuperObjectProperties`, `getEquivalentObjectProperties`, `getInverseObjectProperties`, `getTopDataPropertyNode`, `getSubDataProperties`, `getSuperDataProperties`, and `getEquivalentDataProperties` against HermiT.
- **Result on `ore_ont_12566`**: all 394 top-equivalence call differences (335 `differ_structure` + 59 `differ_content`) are eliminated (`0` `differ_structure` calls remain across both the 42-ontology and 40-ontology lists; `ore_ont_12566` score rises from 78% to 93%, with only the 3 Group A bottom-property domain/range cells differing).

## 3. Goal 2: `ore_ont_9662`, `13700`, `7532` (lazy per-kind precompute and separable/forest ABox rollup)

### 3.1 Diagnosis of which precompute step took the time

1. **`ore_ont_9662` (1,513 classes, 201 object properties, 1 individual) and `ore_ont_7532` (1,923 classes, 280 object properties, 2 individuals)**:
   - Both ontologies are SIO extensions containing `ReflexiveObjectProperty(SIO_000001)` alongside 201–280 object properties with inverses, transitive roles, role chains, and functional roles.
   - In the baseline, `KMReasoner.precomputeInferences` eagerly executed `ensureProperties()` (`km classify --lines --properties`, which takes > 180 s because of the reflexive role), `ensureRealized()` (`km classify --lines --realize`, which also exceeds 20 s because `ReflexiveObjectProperty` forces CB saturation over the ABox), and `ensureValues()` (`km classify --lines --values`). Because `ParityRun` gives the `precompute` phase a 300 s budget, `precomputeInferences` ran until the 300 s ontology timeout and prevented `ParityRun` from reaching the 4,500+ subsequent queries (`ok 17/4578` on `9662`, `ok 17/4623` on `7532`).
2. **`ore_ont_13700` (2,554 classes, 33 object properties, 7 data properties, 1,884 individuals; and its round-2 twin `ore_ont_2548` with 2,566 classes and 1,887 individuals)**:
   - Both are BFO/OGMS/TMO pharmacogenomics ontologies with `ReflexiveObjectProperty(ro#part_of)` (`ro#has_part`) and 1,884–1,887 individuals connected by a shallow DAG of `ObjectPropertyAssertion` edges (`ro#has_part`, `IAO_0000136`).
   - With `ReflexiveObjectProperty` + 1,884 individuals in the `km-serve` input, initial `isConsistent()` (`Classifier.Session` startup) timed out at 300 s (`consistency: 298,924 ms`, `ok 12/4151` on `13700`; `ok 12/4273` on `2548`). Without the ABox assertions, `km` classifies the TBox in **0.95 s**.

### 3.2 Plugin fixes

1. **Lazy per-kind `precomputeInferences` and `isPrecomputed`**:
   - `KMReasoner.precomputeInferences(InferenceType...)` now ensures the TBox class hierarchy (`ensureHierarchy()`, which classifies the TBox once in `Classifier.Session`) and records the requested `InferenceType` values in `precomputedTypes`, deferring `ensureRealized()`, `ensureProperties()`, `ensureDataProperties()`, and `ensureValues()` until a query of that kind is actually called.
   - `isPrecomputed(InferenceType)` checks `precomputedTypes.contains(inferenceType)` (preserving the HermiT convention of returning `false` for `CLASS_ASSERTIONS` and `SAME_INDIVIDUAL` when the ontology has 0 individuals).
   - Whole-revision one-shot calls (`ensureRealized`, `ensureProperties`, `ensureDataProperties`, `ensureValues`) cache `realizeFailure`, `propertiesFailure`, `dataFailure`, and `valuesFailure` across the revision when `Classifier.oneShot` fails or is interrupted (`cacheableWholeRevision`), so a single 20 s call timeout does not re-run the same timed-out command on every subsequent query.
2. **`ForestABoxRollup` (`protege/src/main/java/org/bioontology/kobayashimarust/protege/ForestABoxRollup.java`)**:
   - On ontologies with `ReflexiveObjectProperty` and an acyclic ABox over simple/transitive/inverse/sub-property roles (without nominals, rules, keys, negative assertions, or `SameIndividual` axioms), `ForestABoxRollup.tryBuild` rolls up the ABox assertions bottom-up into TBox proxy classes `__km_ind_<i>` (`SubClassOf(__km_ind_<i>, C)`, `SubClassOf(__km_ind_<i>, ObjectSomeValuesFrom(r, __km_ind_<j>))`, `SubClassOf(__km_ind_<i>, DataHasValue(p, lit))`) and classifies the rolled-up TBox in `Classifier.Session` in **1.2 s** instead of timing out at 300 s.
   - When the ontology contains only a small ABox without `ObjectPropertyAssertion` edges (`ore_ont_9662` has 1 individual, `ore_ont_7532` has 2 individuals), `ForestABoxRollup.tryRealizeSeparableABox` realizes the individuals directly from the classified TBox hierarchy in **0 ms** instead of invoking `km classify --realize`.
3. **Nominal-free existential probes for `OBJECT_PROPERTY_HIERARCHY` (`KMReasoner.propertiesByExistentialProbes`)**:
   - When the ontology has `ReflexiveObjectProperty` and >= 150 object properties (`ore_ont_9662` with 201 properties, `ore_ont_7532` with 280 properties), `ensureProperties()` runs a single TBox-only classification batch with existential probe pairs `SubClassOf(P_r_s, ∃r.W_r ⊓ ¬∃s.W_r)` over a fresh witness class `W_r` instead of `km classify --properties` (which adds 200–280 nominals and triggers CB blowup with `ReflexiveObjectProperty`). That reduces object-property hierarchy computation on `ore_ont_9662` and `ore_ont_7532` from **> 180 s (timeout)** to **6.4 s** and **8.1 s**, agreeing 100% with HermiT on all property hierarchy queries.

## 4. Goal 3: `ore_ont_8250`, `2526`, `16630`, `6615` (rules with nominals, fault isolation, and `8250` diagnosis)

### 4.1 Fault isolation when one kind of inference is refused, plus nominal-free property probes and rule pre-grounding

1. **Fault isolation across inference kinds**:
   - Lazy per-kind precompute ensures that when `km` refuses one inference kind (such as `--properties` or `--realize` with exit code 3), `precomputeInferences` does not throw and does not block class, data-property, or individual queries.
   - Cached failure fields (`realizeFailure`, `propertiesFailure`, `dataFailure`, `valuesFailure`) ensure that a declined worker call throws `UnsupportedOperationException` immediately on subsequent calls of that kind without re-invoking the native binary.
2. **Recovering `OBJECT_PROPERTY_HIERARCHY` on `ore_ont_2526`, `16630`, and `6615`**:
   - Why `km classify --lines --properties` failed with exit code 3 on `ore_ont_2526`, `16630`, and `6615`: `km classify --properties` synthesizes a fresh nominal `{__km_prop_x_i}` for every object property `r_i`. On ontologies with `DLSafeRule` + inverse roles + number restrictions (`SHIQ`), those fresh nominals cause the rule-aware taxonomy fence (`check_rule_taxonomy_fence` in `engine/src/orchestrate/rules.rs:845`) to reject the run (`unsupported: DL-safe rules reach class queries through a nominal, and the rule-aware taxonomy would omit ... (inverse+number(SHIQ))`).
   - When `Classifier.properties` throws `UnsupportedOperationException`, `KMReasoner.ensureProperties()` now falls back to `propertiesByExistentialProbes()` (`SubClassOf(P_r_s, ∃r.W_r ⊓ ¬∃s.W_r)` using fresh classes `W_r` instead of nominals) and computes `disjointObjectProperties` via `SubClassOf(D_r, ∃r.⊤ ⊓ ∃s.⊤)` instead of `IrreflexiveObjectProperty` with nominals.
   - Because `propertiesByExistentialProbes` introduces **zero nominals**, `km`'s rule-aware classifier accepts the input and computes the exact object property hierarchy, inverses, domains, ranges, and disjointness!
3. **Domain/range/type-filtered pre-grounding of DL-safe rules (`ForestABoxRollup.tryPregroundRules`)**:
   - On `ore_ont_6615` (and `ore_ont_2526`), each one-shot `km` invocation with ungrounded `DLSafeRule` took 6.1 s in `orchestrate::rules::saturate`, causing `ore_ont_6615` to abort at 300 s (`1,193 / 2,361` calls).
   - `ForestABoxRollup.tryPregroundRules` checks whether every `DLSafeRule` atom uses only roles and classes whose positive ABox/TBox domain/range/type over-approximation has <= 500 groundings across the ontology's named individuals, and replaces the `DLSafeRule` axioms with equivalent `SubClassOf(ObjectIntersectionOf(...), headAtom)` ground implications over `ObjectOneOf(ind)`.
   - On `ore_ont_6615`, all 3 rules have empty groundings on the 16 individuals, reducing the rule set to 0 ground axioms and cutting total KM wall time on `ore_ont_6615` from **300.3 s (aborted, 1,193/2,361 calls)** to **9.7 s (completed, 2,353/2,361 calls)**!
   - On `ore_ont_2526`, all 996 previously unsupported object-property calls are now answered and agree with HermiT (`2,305 / 2,305` calls ok in **10.3 s**, up from `1,313 / 2,305`; score rises from **71% to 93%**, with 0 unsupported cells).
   - On `ore_ont_16630`, all 621 previously unsupported object-property calls are now answered and agree with HermiT (`3,090 / 3,090` calls ok in **27.5 s**, up from `2,469 / 3,090` in 98.4 s; score rises from **69% to 91%**, with 0 unsupported cells).

### 4.2 Why `ore_ont_8250` is refused by `km-serve` (`Classifier.Session`) and `km classify`

We inspected `engine/src/serve.rs` and `engine/src/orchestrate/rules.rs` to determine why `ore_ont_8250` fails in `Classifier.Session`:
- `ore_ont_8250` contains **both** `DLSafeRule` axioms, **explicit nominals in the TBox** (`SubClassOf(:DedicatedServer, ObjectHasValue(:hasDedicatedServer, :true))`, where `:true` and `:false` are named individuals), **and** inverse roles + qualified number restrictions (`SHIQ`, e.g. `ObjectExactCardinality(1 :hasDedicatedServer :Boolean)`).
- Both `km classify` (`engine/src/orchestrate/classify.rs:146`) and `km-serve` (`engine/src/serve.rs:288` -> `orchestrate::rules::prepare_for_serve` at `engine/src/orchestrate/rules.rs:344` -> `check_rule_taxonomy_fence` at `engine/src/orchestrate/rules.rs:845`) call the exact same function `check_rule_taxonomy_fence`.
- When `rules_affect_taxonomy_via_nominals(ont)` is true (because the TBox itself contains nominals `:true` and `:false` alongside `DLSafeRule`), `check_rule_taxonomy_fence` runs `ht_clauses::translate_Checked` on the rule-grounded ontology and rejects whenever `fenced > 0` (`inverse+number(SHIQ)`):
  ```text
  out of fragment: DL-safe rules reach class queries through a nominal, and the rule-aware taxonomy would omit 1 clause(s) and 1 fenced construct(s) of the rule worker input (inverse+number(SHIQ)); a taxonomy over the stripped TBox would be incomplete
  ```
- Therefore, both `km classify ore_ont_8250.owl` (exit code 3) and `km-serve` on `ore_ont_8250.owl` (`ERR\tout of fragment...`) refuse initial classification for the same reason (`engine6`'s scope).
- Standalone reproducer written to: `/mnt/data1/leechuck/km-work/v170/scratch/w12/engine-items/ore_ont_8250_rules_nominals_shiq.ofn`.

By Section 2.2 of the W3C OWL 2 Direct Semantics specification, in every interpretation $\mathcal{I} = (\Delta^\mathcal{I}, \Delta_D, \cdot^\mathcal{I})$:
$$(\text{owl:bottomObjectProperty})^\mathcal{I} = \emptyset, \qquad (\text{owl:bottomDataProperty})^\mathcal{I} = \emptyset.$$
By Table 5 of the OWL 2 Direct Semantics specification:
- $\text{ObjectPropertyDomain}(P, CE)$ holds in $\mathcal{I}$ iff $\forall x, y: (x, y) \in P^\mathcal{I} \implies x \in CE^\mathcal{I}$.
- $\text{ObjectPropertyRange}(P, CE)$ holds in $\mathcal{I}$ iff $\forall x, y: (x, y) \in P^\mathcal{I} \implies y \in CE^\mathcal{I}$.

When $P = \text{owl:bottomObjectProperty}$ or $R = \text{owl:bottomDataProperty}$, the premise $(x, y) \in \emptyset$ is false for all $x, y$, so the implication holds vacuously for **every** class $CE$ in the signature (including `owl:Nothing`). By the OWL API `getObjectPropertyDomains(pe, direct)` specification, a named class $C$ is a domain of $pe$ iff $\mathcal{O} \models \text{ObjectPropertyDomain}(pe, C)$ (equivalently $\mathcal{O} \models \exists pe.\top \sqsubseteq C$). Since every named class is entailed as a domain/range of the bottom property, `direct = false` must return all class nodes, and `direct = true` (the most specific domain/range classes, i.e. direct superclasses of $\exists \bot.\top \equiv \bot$, or the bottom class node itself under the OWL API domain/range convention) is `{owl:Nothing}`. > If `direct` is `true`, only the direct instances of `ce` are returned, i.e., individuals $a$ such that $\mathcal{O} \models ce(a)$ and there is no named class $C$ strictly subsumed by $ce$ ($\mathcal{O} \models C \sqsubseteq ce$ and $\mathcal{O} \not\models ce \sqsubseteq C$) with $\mathcal{O} \models C(a)$.

Since `:Zinfandel` is a named class strictly subsumed by `¬:SweetFruitCourse` and `:Saucelito` is an instance of `:Zinfandel`, `:Saucelito` is **not** a direct instance of `¬:SweetFruitCourse`.

#### OWL 2 Direct Semantics and HermiT bytecode root-cause analysis
Under the OWL 2 Direct Semantics, `SubClassOf(:WhiteBurgundy, :WhiteWine)` entails $\text{:WhiteBurgundy}^\mathcal{I} \subseteq \text{:WhiteWine}^\mathcal{I}$ in every model $\mathcal{I}$, while the model with $\text{:ShortLeaf}^\mathcal{I} = \{d\}$, $\text{:WhiteWine}^\mathcal{I} = \{d, c\}$, and $\text{:WhiteBurgundy}^\mathcal{I} = \text{:DeepLeaf}^\mathcal{I} = \text{:Sub1}^\mathcal{I} = \{c\}$ witnesses $\mathcal{O} \not\models \text{:WhiteWine} \sqsubseteq \text{:WhiteBurgundy}$. Decompiling `org.semanticweb.HermiT.hierarchy.InstanceManager.getTypes(Individual, boolean)` with `javap -c` (offsets 51–499) reveals the exact bug in HermiT when realization has not been precomputed (`!m_isRealized`, or during bottom-up hierarchy realization):
1. HermiT performs a **bottom-up breadth-first search (BFS)** starting from `m_bottomNode` (`owl:Nothing`), pushing `current.getParentNodes()` into an `ArrayDeque` queue.
2. In `group_c.ofn` (and in `wine`, where `WhiteWine` has direct leaf subclasses such as `DryWhiteWine` / `SweetWhiteWine` while `WhiteBurgundy` has deeper subclasses `Meursault` -> `WhiteMeursault`), `:WhiteWine` is at **distance 2** from `owl:Nothing` (`owl:Nothing -> :ShortLeaf -> :WhiteWine`), whereas `:WhiteBurgundy` is at **distance 3** from `owl:Nothing` (`owl:Nothing -> :DeepLeaf -> :Sub1 -> :WhiteBurgundy`).
3. Consequently, the bottom-up BFS pops `:WhiteWine` **before** `:WhiteBurgundy`, tests whether `:corton` is an instance of `:WhiteWine` (`true`), and adds `Node(:WhiteWine)` to `result`.
4. #### Minimal ontology (`scratch/w12/goal6/group_d0.ofn`)
```owl
Prefix(:=<http://example.org/d0#>)
Ontology(<http://example.org/d0>
  Declaration(Class(:A))

```

#### Observed answers of HermiT 1.4.3.456 and KM
- **HermiT 1.4.3.456**:
  - On `group_d0.ofn` (0 declared data properties):
    - `getDisjointDataProperties(owl:bottomDataProperty)` -> **`Nodeset[Node( owl:topDataProperty )]`** (omits `owl:bottomDataProperty`!)
    - `isEntailed(DisjointDataProperties(owl:bottomDataProperty, owl:bottomDataProperty))` -> **`true`**
  - On `group_d.ofn` (1 declared data property `Declaration(DataProperty(:p))`):
    - `getDisjointDataProperties(owl:bottomDataProperty)` -> **`Nodeset[Node( owl:bottomDataProperty ), Node( :p ), Node( owl:topDataProperty )]`** (includes `owl:bottomDataProperty`!)
- **KM**:
  - On `group_d0.ofn`: `getDisjointDataProperties(owl:bottomDataProperty)` -> **`Nodeset[Node( owl:bottomDataProperty ), Node( owl:topDataProperty )]`**
  - On `group_d.ofn`: `getDisjointDataProperties(owl:bottomDataProperty)` -> **`Nodeset[Node( owl:bottomDataProperty ), Node( :p ), Node( owl:topDataProperty )]`**
  - `isEntailed(DisjointDataProperties(owl:bottomDataProperty, owl:bottomDataProperty))` -> **`true`**
*(ELK 0.6.0 throws `UnsupportedOperationException` on `getDisjointDataProperties`.)*

#### OWL 2 Direct Semantics argument
By Table 5 of the W3C OWL 2 Direct Semantics specification, $\text{DisjointDataProperties}(R_1, R_2)$ holds in an interpretation $\mathcal{I}$ iff $R_1^\mathcal{I} \cap R_2^\mathcal{I} = \emptyset$. For $R_1 = R_2 = \text{owl:bottomDataProperty}$, $(\text{owl:bottomDataProperty})^\mathcal{I} = \emptyset$ in every interpretation $\mathcal{I}$, and $\emptyset \cap \emptyset = \emptyset$. Therefore $\mathcal{O} \models \text{DisjointDataProperties}(\text{owl:bottomDataProperty}, \text{owl:bottomDataProperty})$ in every ontology $\mathcal{O}$ (regardless of whether $\mathcal{O}$ declares any named data properties). HermiT returns `owl:bottomDataProperty` when at least one named data property is declared, and returns `true` for `isEntailed(DisjointDataProperties(owl:bottomDataProperty, owl:bottomDataProperty))` even on `group_d0.ofn`, but omits `owl:bottomDataProperty` from `getDisjointDataProperties(owl:bottomDataProperty)` when the ontology has 0 declared data properties.

#### OWL 2 Direct Semantics argument
