# Nominal covers of the domain (v1.7.0, branch `v170/nominal-cover`)

An ontology with a cover `⊤ ⊑ {o1, …, ok}` has at most `k` elements in every
model. KM took minutes on small inputs of this kind that HermiT answers in
seconds. This note gives the cause and the two changes that remove it, with
their soundness and completeness arguments.

## 1. Cause

### 1.1 One-individual covers (shape 1): merge hypotheses over equal individuals

Inputs: `SubClassOf(owl:Thing ObjectOneOf(:a0))` with a number restriction over
an inverse role (`A ⊑ ≥2 s1⁻`) and nominal probes `V_i ≡ ∃s2.{a_i}` (the value
probes of `--values`), family `scratch/vchain/b2/m<k>.ofn`.

- The native bridge declines the source TBox (`unsupported=1`), so the run
  takes the `certified_nominals` route and the CB engine answers.
- The CB engine spends all the time in the ground context. In the clause set
  `→ N(x)`, `N(x) → x ≈ a0` (the cover) every individual `a_i` equals `a0`,
  but the ground context keeps one copy of every ground clause per individual
  name: it derives the units `→ a_i ≈ a0`, yet it does not rewrite the other
  clauses with them (no demodulation in the context calculus). Each query
  context `V_j` has a body-free bridge `⊤ → x ≈ a_i` for every `i`, so the
  merge hypotheses of docs/NOMINALS-CB.md section 10.1 push `V_j(a_i)` for
  every pair: `k²` hypotheses. Each hypothesis carries its own ground
  consequences over all pairs of individual names (`V_j(a_i) → s2(a_l, a_n)`,
  `… → Q(a_l)`), so the ground context grows as `k⁴` and the inferences
  between them faster. Measured on the captured engine input (`km engine`,
  one thread): k=6 0.7 s, 8 4.3 s, 10 14.6 s (CB `succ_wo_total` 6,533,
  18,916, 45,403). Dump: ground context of m6 has 5,539 clauses, 4,728 of
  them with one hypothesis `V_j(a_i)` in the body, 36 distinct hypotheses.
- `KM_NO_MERGE_HYPOTHESES=1` answers m10 in 0.07 s with the same output, so
  the hypotheses are the cost; they are needed for completeness in general
  (seed r1600), so the fix keeps them.

### 1.2 Covers of two to four individuals (shape 2): search over merges

Inputs: `⊤ ⊑ {a1, a2}`, `c1(a0, a0)` and 20 to 30 individuals
(`scratch/engine10/t4fuzz/u3/repro/`). `--realize --values` runs a first probe
run (fast), a model plan, and a residual run with one nominal probe per
individual plus the residual value probes. In the residual run the bounded
bridge attempt overruns its 8 s budget, the input goes to
`certified_nominals`, and the synchronous HT worker answers after about 50 s
(c97_130). `KM_BRIDGE_PROGRESS` shows single satisfiability tests with 8,000
and more backtracks at branching depth 26: every individual carries the
disjunction `a ≈ a1 ∨ a ≈ a2`, and dependency-directed backjumping jumps one
level at a time (`ddb_jumps` ≈ `drives`), so the tableau enumerates merge
choices. The CB engine on the same probe-extended ontology does not finish in
200 s (forced `nominals` route). Neither engine's search uses the fact that
the domain has at most two elements.

## 2. Change 1: one-element domain quotient (CB engine)

`engine/src/engine.rs`, `forced_domain_singleton` and
`add_domain_singleton_equalities`, called in `Engine::prepare_opts` before the
existing exact quotient `merge_asserted_ground_equalities`.

- **Rule.** Let `F` be the least set of concept names closed under body-free
  units `→ D(x)` and Horn clauses `B1(x) ∧ … ∧ Bn(x) → D(x)` with all `Bi ∈ F`.
  If some clause `B1(x) ∧ … ∧ Bn(x) → x ≈ o` (n ≥ 0) has all `Bi ∈ F`, add the
  unit `→ a ≈ o` for every other individual `a` of the clause set. The
  quotient that follows rewrites every individual to `o`.
- **Soundness.** Each `Bi ∈ F` holds of every element of every model of the
  clause set (induction over the closure), in particular of `a^I`; the merge
  clause then gives `a^I = o^I`. So each added unit is entailed by the clause
  set, and adding entailed clauses changes no model.
- **Completeness and exactness.** The clause set with the units has exactly
  the models of the clause set without them. The quotient by unit equalities
  between individuals (`merge_asserted_ground_equalities`, in use since
  v1.6 for `SameIndividual`) is exact: it replaces each individual by its
  class representative in every clause, which is a bijection between the
  models of the two clause sets that keeps every concept and role extension.
  The calculus then runs on the quotient unchanged; no rule, order or
  redundancy criterion of the CB calculus changes.
- **Scope.** Only the CB engine's own clause set; the cb-horn model builder
  (`cb_model`) calls `prepare_opts(…, false)` because it reads one context per
  individual. `KM_NO_DOMAIN_SINGLETON=1` switches the rule off (diagnostic).

## 3. Change 2: finite-cover route (covers of one to four individuals)

`engine/src/orchestrate/finite_cover.rs`, called from
`classify_with_evidence_inner` right after the frontend
(`finite_cover_evidence` in `engine/src/orchestrate/mod.rs`), before the
bridge-first attempt and every other route.

### 3.1 Procedure

1. Gate. The route runs only for the outermost classification of a call, not
   under a route forced at start-up (`KM_ROUTE` other than `auto`), and not with
   `KM_NO_FINITE_COVER`. It declines (and the existing routes answer) when the
   frontend dropped or did not carry an axiom, when the input has data roles,
   when the source text has a data construct, a datatype, a key, a DL-safe
   rule, the universal or empty role, or an anonymous individual, when the
   parse has an internal concept name, when no axiom has the form
   `SubClassOf(owl:Thing ObjectOneOf(o1 … ok))` or the equivalence, when
   `k > 4`, and beyond the size bounds (400 individuals, 400 asserted roles,
   20,000 classes, 3,000,000 ground clauses, chains longer than 6) or the
   conflict budget (2,000,000 conflicts over all solver calls).
2. Partitions. For each partition of the cover individuals into `m` blocks
   (Bell(k) partitions, at most 15), take the domain `{0, …, m−1}`, map each
   cover individual to its block, and give every other individual `a` one
   variable `e(a, d)` per element with an exactly-one constraint.
3. Grounding. Every class name `A` gets variables `A(d)`, every role name `r`
   gets `r(d, e)`. Every class expression gets a literal per element, defined
   by equivalence (Tseitin): `¬`, `⊓`, `⊔` directly; `∃R.C`, `≥n R.C` as the
   disjunction over `n`-subsets of elements of `R(d,e) ∧ C(e)`; `≤n R.C` as
   the negation of `≥n+1`; `∀R.C` as `¬∃R.¬C`; `{a}` as `e(a, d)` (or a
   constant for cover individuals); `∃R.Self` as `R(d, d)`; inverse roles by
   swapping arguments. Axioms become clauses over all elements: class
   inclusion, equivalence and disjointness; role inclusion, inverse,
   symmetric, asymmetric, reflexive, irreflexive, functional, inverse
   functional and disjoint roles; chains and transitivity over all paths;
   class, role and negative role assertions, same and different individuals,
   through the element variables.
4. Search. A CDCL solver (two watched literals, first-UIP learning, activity
   order, restarts, assumptions) decides each partition. The ontology is
   consistent iff some partition is satisfiable. For classification it keeps,
   per class `A`, the intersection of the types (sets of class names) of all
   elements in `A` over all models found. Then, for each class `A` and
   element `d`, it asks under assumptions for a model with `A(d)` (when no
   model had an `A` yet) and, for each remaining candidate `B`, for a model
   with `A(d) ∧ ¬B(d)`. Every model found shrinks the candidates of every
   class; an unsatisfiable call proves `A(d) → B(d)` in that partition. `A` is
   unsatisfiable iff no model of any partition has an element in `A`;
   otherwise its superclasses are the candidates that survive every
   partition and element.
5. Output. The answer goes through the same publication step as every engine
   answer (`map_engine_out_to_evidence`), keyed by the frontend's internal
   names, with `owl:Nothing` for unsatisfiable classes.

### 3.2 Soundness and completeness

- **Finite domain.** Under `⊤ ⊑ {o1, …, ok}` every element of a model `I` is
  some `oi^I`, so `|Δ^I| ≤ k`. The relation `oi ~ oj` iff `oi^I = oj^I` is a
  partition of the cover individuals, and `Δ^I` is in bijection with its
  blocks. So every model is isomorphic to an interpretation over
  `{0, …, m−1}` for one partition with the cover individuals at their blocks.
- **Grounding is exact over a fixed domain.** For a fixed finite domain, an
  interpretation of the names is exactly an assignment to the variables
  `A(d)`, `r(d, e)`, `e(a, d)` (with exactly one element per individual), and
  the Tseitin literal of each expression at `d` is true iff `d` is in the
  expression's extension (structural induction; the counting clauses
  enumerate all `n`-subsets of a domain of at most 4 elements). Each axiom
  holds in the interpretation iff its clauses hold. So the models of the
  clauses of a partition are exactly the models of the ontology over that
  domain and block map.
- **Entailments.** `O ⊨ A ⊑ B` iff no model of `O` has an element in `A \ B`;
  by the two points above iff no partition's clauses have a model with some
  `d` in `A(d) ∧ ¬B(d)`. The procedure removes `B` from `A`'s candidates only
  when it found such a model (sound), and stops only when the solver proved
  that no model has an element in `A` outside the remaining candidates, for
  every partition (complete). The solver's `Unsat` is exact: it learns only
  resolvents of its clauses; `Sat` comes with a total assignment that satisfies
  every clause.
- **Decline, never guess.** Every construct outside the grounding, every
  bound and the conflict budget lead to `None`, and the existing routes
  answer as before.

### 3.3 Interaction with the other row kinds

`--realize`, `--values` and `--different` compute their rows from
classifications of probe-extended ontologies (`realize.rs`, `abox_rows.rs`).
Each of these classifications enters `classify_with_evidence` and takes the
finite-cover route when its input has the cover, so the probe runs answer
exactly and fast. The route exports no model
(`model_export::record_declined`); the realization code then runs its exact
probe path instead of the model plan. No realization code changed.
