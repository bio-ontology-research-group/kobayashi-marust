# Finite data membership projection

Status: semantic proof checked. Runtime translation implemented in an isolated candidate; full CLI, reference, and certification validation are pending.

`FiniteDataMembership.lean` separates object and data domains and replaces each represented DataHasValue(p,v) with a fresh unary membership predicate on object owners. It proves equivalence under negation, conjunction, disjunction, object existential and universal restrictions, qualified object minimum and maximum cardinalities, nominals, and self restrictions. A disjoint sum of concept signatures models fresh private names.

The extension uses exactly the represented value memberships as data edges. The accompanying lemmas establish property inclusion, domains, ranges, functionality, disjointness, and negative assertions. Restricting an existing source data interpretation preserves its represented values. No owner unique-name assumption or object node for a literal is introduced.

Validation boundaries: source-wide admission, canonical literal decoder reuse, fresh-name allocation, exact occurrence accounting, parser rewrite, and routing/publication validation. Unknown data quantifiers, cardinalities, keys, rules, imports, datatypes and lexical forms must remain outside this projection. Its proof does not make the current legacy DataHasValue abstraction exact.

Candidate implementation: pre-scan only sources containing DataHasValue; bind each full property IRI plus observed lexical literal spelling to a canonical value-membership symbol; let recursive class parsing consume these bindings. Observe original source nodes for profile accounting while filtering represented data schema/assertion axioms out of object-role parsing. Add exact unary schema constraints and positive/negative owner assertions. Retain independent counts of generated ClassAssertion occurrences and discharge the original data-assertion coverage obligation only on complete admission. Source IRI names must still pass through the existing reserved-prefix escape path.

Candidate v1 passed 62/66 CLI checks. Both automatic and nominal CB routes passed every case. Forced general HT declined two satisfiable cases because its symbol installer required a clause definition for private atomic predicates occurring only in the ABox. Candidate v2 permits allocation when the typed assertion is exactly Name(marker); complex assertions retain the existing defining-clause requirement. This changes symbol registration, not inference rules. The semantic membership proof already quantifies over these fresh atomic predicates; source binding and installer validation remain implementation checks.

Candidate v2 passed all 66 synthetic checks. Four real ontologies (13383, 5564, 8006, 9096) had exact HermiT classification signatures, but automatic CB output reported seven dropped clauses each, so those runs are not accepted as complete. Forced general native HT yielded the same complete signatures with dropped=0 on all four. Candidate v3 routes only wholly admitted finite-data projections with a complete typed ABox to that existing native mechanism. Its converter must accept the full role and assertion payload without dropped/fenced constructs. Explicit user route selections are preserved. Whole-source admission is essential: this is not permission to run an unchecked approximation on other data syntax.
