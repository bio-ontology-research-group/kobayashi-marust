Too slow to ship this way (engine work, W5b):

- `getDifferentIndividuals`: median 622 ms against 50 ms, 37 calls past 20 s on 7 ontologies. One batch run with `{a} ⊓ {b}` per candidate, then one consistency run per candidate the batch leaves open, because km 5eea1411 misses some of these pairs (ore_ont_15667). Cost grows with the number of individuals times the classification time.
- `OBJECT_PROPERTY_ASSERTIONS` precompute: one realization per property; over 290 s on ore_ont_5841 (215 properties, 1,466 individuals), 122 s on ore_ont_13153, where HermiT needs seconds. Withdrawn from the precomputable types; values are computed on demand, one run per property (worst call 7.7 s on wine).
- `isEntailed(DataPropertyRange(p D))`: `∃p.¬D` timed out on three ontologies with data properties (food, wine, ore_ont_13545).
- `getDisjointClasses` of `∃r.C` (the complement `∀r.¬C` has to be classified): 3 time outs.

## Engine items found (wrong or refused km answers on extended inputs)

| Item | Reproducer | Effect on the plugin |
|---|---|---|
| `{p(a,b), NegativeObjectPropertyAssertion(p a c)}` reported inconsistent (no other axiom) | `scratch/w5/tmp/no.ofn` | Wrong in plain classification and realization of any ontology with a negative object property assertion. The reduction runs rewrite such assertions to `ClassAssertion(¬∃p.{c} a)`; plain classification still sends them. None of the 36 ontologies has one. |
| `{Transitive(p), p(b,c), p(a,b), ClassAssertion(¬∃p.{c} a)}` reported consistent; with the two assertions in the other order it is inconsistent | `scratch/w5/tmp/p7.ofn` | Reductions avoid negated nominals: assertion entailment, chains, transitivity and reflexivity use positive realization forms instead. |
| `{a} ⊓ {b}` satisfiable where `O ∪ {a = b}` is inconsistent (two colours with different values of a functional data property) | ore_ont_15667, `ColorBlue`, `ColorCyan` | getDifferentIndividuals confirms every open pair by refutation (the cost above). |
| `SameIndividual(a b)` added when the ontology already asserts it: 8 clauses dropped | IndividualsTest `SMALL` + `SameIndividual(:rex :rexy)` | Equal individuals are skipped. |
| Realization with `Q ≡ ¬{a}` does not finish (minutes, 10 cores) on a 30-axiom ABox | `scratch/w5/tmp/hang1.ofn` | Different individuals use the classification form. |
| Several nominal definitions in one run blow up (four small definitions: over 10 s; each alone 0.02 s); `¬{alice, rex}` on the ZOO test ontology takes over 60 s once its negative assertion is rewritten (6.8 s with the raw one) | `scratch/w5/tmp/p1.ofn`, `slow_q32.ofn` | Batches are kept homogeneous; such queries can time out. |
| Value classes for 12 properties in one realization: 54 s; one property per run: 0.3 to 0.5 s | ZOO test ontology | One property per run. |
| A fresh datatype is rejected ("outside the OWL 2 datatype map") | `scratch/w5/tmp/d.ofn` | No class form `∃u.T ⊑ ∃v.T` for the data property hierarchy (plan 2.2); that hierarchy stays refused outside the fragment. |
| `classify --realize` runs its engine worker with `KM_THREADS=16` although the caller set `KM_THREADS=1` | `/proc/<pid>/environ` of the worker | Thread budget of the parity runs was not 1 for realization runs. |
