# C1f: a two-sided certificate for the fast SHIQ route

Stage C1f. Branch `v170/c1f-closure` (from `development/v1.7.0`).
Scratch: `/mnt/data1/leechuck/km-work/v170/scratch/c1f/`.

## 1. The problem in one paragraph

The certified route answers from a candidate set `U` that must pass
`closedFastB`: every node of `U`, also every intermediate node that a
larger variant supersedes, must meet R1 to R6. Soundness of the "no"
answers (a live root type without `b`) holds for every `U`
(`fastRows_sound`); the closure conditions exist only for the "yes"
answers (every model element is simulated by a live root). On the GALEN
and FMA inputs the closure conditions force the growth (C1e, sections
1.3, 1.4): each back-propagation step is a new node, its child seeds hold
`fwd t L`, so it gets new child contexts, and so on. On the chemistry
inputs the closure conditions force a node per branch of the definer
disjunctions (section 1.2).

## 2. Three options

**(i) A consequence-based candidate structure with its own closure
check.** Contexts keyed by the filler, members are conditional facts
("if the parent has `P` then this node has `c`"), back propagation adds a
conditional fact to the parent context. The check must be complete:
from a closed structure and a model, build a simulation. A closed
structure of this kind does not list the model's types; it lists facts
about them, so the simulation needs a model construction from the
conditional facts (an unravelling, as in the completeness proof of a
consequence-based calculus). That proof is new and long: the existing
SHI and SHIQ completeness arguments map nodes to types and do not carry
over. Counting needs its own rules and proof.

**(ii) A quotient of the existing candidate set.** Identify nodes that
agree on the names that children and counting read. On GALEN the
contexts are already distinct on those names: 17 409 of 19 967 contexts
have distinct (seed, label) pairs and the seeds hold the universal
fillers that the children read (C1e, 1.3); on 6134 the distinct seeds
are the transitivity markers of the paths (1.4). A quotient that keeps
the closure conditions sound for completeness must keep these names, so
it does not shrink these inputs.

**(iii) Separate witnesses for the two directions (chosen).**

- "Yes" answers (`b ∈ row a → EntailsSub O a b`) come from a
  *derivation*: a list of clauses of a small consequence-based calculus,
  each derived by a rule from the ontology and earlier clauses. Each
  rule is sound, so every derived clause holds in every model. This is
  the direction where a consequence-based engine is strong, and its
  proof is a set of local semantic lemmas.
- "No" answers (`EntailsSub O a b → b ∈ row a`) come from a candidate
  set `U` that is **not** required to be closed: the live root types of
  `U` (the existing worklist elimination) give models, and
  `fastRows_sound` already proves, for every `U`, that every entailed
  name lies in every live root type that contains `a`.
- The route accepts a row when the two meet on the requested names: if a
  derived clause says `a ⊑ ⊥`, the row is `none`; otherwise the row is
  the derived names, and every requested name in the live root
  intersection of `U` must be derived. Otherwise it declines and the
  closure route (`closedFastB`) runs as before.

Why (iii): neither direction needs a completeness proof, so the closure
conditions disappear from the new route. The witness `U` needs one
model per requested name (for Horn inputs, the canonical model), not
the closure of every intermediate node, so the generator can compute
final types first (from the derivation) and build each context once.
The cost moves to the generator: if its derivation misses a
subsumption, the witness for that row dies or keeps the name, and the
route declines; it never answers wrong. Option (i) would decide; (iii)
certifies whatever the generator finds. On the corpus the generator is
the consequence-based saturation that km runs in seconds.

The statement `owlSHIQFast_sound` does not change: the generator returns
a `CandA` with an optional derivation field; the route tries the
two-sided check first and falls back to `closedFastB`.

## 3. The calculus

Names `Fin n`, roles `RoleT (Fin m)`, ontology `O` in ALCHIQ form (after
`encTransQ`, the elimination and the merge). A *clause* is
`⟨L, P, B, H, Q⟩`: a role set `L`, names `P` and `Q` at a predecessor
`y`, names `B` and `H` at an element `x`. It **holds** when for every
model `I` of `O` and all `y, x`:

    (∀ R ∈ L, R(y, x)) → P ⊆ type y → B ⊆ type x → (H ∩ type x ≠ ∅ ∨ Q ∩ type y ≠ ∅).

With `L = P = Q = ∅` the clause speaks of `x` alone (`y` is arbitrary;
domains are nonempty). `⟨∅, ∅, {a}, {b}, ∅⟩` is `a ⊑ b`,
`⟨∅, ∅, {a}, ∅, ∅⟩` is `a ⊑ ⊥`.

`upS R` is the sound part of the super-roles of `R` (`upS_sound`).
Every rule below has a conclusion `c` and accepts any clause above it:
`L, P, B, H, Q` may each grow (weakening is sound). Names are checked
below `n`, role codes below `2 m`.

| rule | premises | conclusion | why it holds |
|---|---|---|---|
| gci | `gci body head ∈ O` | `⟨∅, ∅, body, head, ∅⟩` | the gci |
| taut | | `⟨∅, ∅, {p}, {p}, ∅⟩` | |
| fwd | `allRight a S c ∈ O` | `⟨{S}, {a}, ∅, {c}, ∅⟩` | `a(y), S(y,x)` |
| bwd | `allRight a S c ∈ O` | `⟨{S⁻}, ∅, {a}, ∅, {c}⟩` | `S⁻(y,x)` is `S(x,y)` |
| up | `⟨∅, ∅, B, H, ∅⟩` | `⟨∅, B, ∅, ∅, H⟩` | the clause at `y` |
| resX | `c₁` with `p ∈ H₁`, `c₂` with `p ∈ B₂` | `⟨L₁∪L₂, P₁∪P₂, B₁∪(B₂∖p), (H₁∖p)∪H₂, Q₁∪Q₂⟩` | resolution at `x` |

| amo0 | upper `(a, 0, S, e)` | `⟨{S}, {a}, {e}, ∅, ∅⟩`, `⟨{S⁻}, {e}, {a}, ∅, ∅⟩` | no `S.e` neighbour |

| sib | upper `(a, 1, S, e)`, lower `(a₂, k ≥ 1, R₂, b₂)`, `S ∈ upS R₂`; `cₑ` as in clash; `c_r` with `L_r ⊆ upS R₂` | `⟨{S}, {a, a₂} ∪ Pₑ ∪ P_r, {e} ∪ (B_r∖b₂), H_r, Qₑ ∪ Q_r⟩` | the `S.e` successor `x` of `y` is the `R₂`-witness `z` |
| par | upper `(a, 1, S, e)`, lower `(a₂, k ≥ 1, R₂, b₂)`, `S ∈ upS R₂`; `cₑ`, `c_r` as in sib | `⟨{S⁻}, {e} ∪ (B_r∖b₂), {a, a₂} ∪ Pₑ ∪ P_r, Qₑ ∪ Q_r, H_r⟩` | the predecessor `y` of `x` is the `R₂`-witness `z` of `x` |

### 3.1 Pen proofs of the rules

Fix a model `I` of `O` and `y, x` with the premise of the conclusion.

- gci, taut, fwd, amo0: immediate from `satClause` (amo0: the one-element
  list `[x]` (or `[y]`) of `S.e` neighbours has length `1 > 0`).
- bwd: `I.rt S⁻ y x ↔ I.rt S x y` (`Interp.rt_flip`), then `allRight`.
- up: the premise holds for every pair, take the pair `(x, y)`.
- resX: apply `c₁` to `(y, x)`: `H₁` at `x` or `Q₁` at `y`. If the hit is
  `p`, then `B₂ ⊆ type x` and `c₂` gives `H₂` or `Q₂`. Otherwise the hit
  is in `H₁∖p` or `Q₁`. resY: the same at `y`.
- pred: `x` has `a`; `exRight` or `atLeast a k R b` with `k ≥ 1` gives `z`
  with `R(x, z)` and `b(z)`; every `S ∈ L₁` has `R ⊑* S` (`upS_sound`),
  so `S(x, z)` (`roleLe_sound`); `c₁` on `(x, z)` has an empty `H`, so
  `Q₁ ∩ type x ≠ ∅`.
- clash: `atLeast` gives a duplicate-free list of `k` witnesses `zᵢ` with
  `R₂(x, zᵢ)`, `b₂(zᵢ)`, so `S(x, zᵢ)` and `Lₑ` holds on `(x, zᵢ)`. If
  `cₑ` gives `Qₑ` at `x` for some `zᵢ`, done; otherwise every `zᵢ` has
  `e`, and `atMost a n S e` bounds the list by `n < k`.
- sib: `y` has `a`, `a₂`; take the `R₂`-witness `z` of `y`. `cₑ` on
  `(y, z)`: `Qₑ` at `y` (done) or `e(z)`. Then `[x, z]` are `S.e`
  neighbours of `y`; if `x ≠ z` the list has length `2 > 1`, so `x = z`.
  `c_r` on `(y, z)`: `L_r` holds (super-roles of `R₂`), `B_r∖b₂` holds at
  `x = z` and `b₂(z)`; it gives `H_r` at `x` or `Q_r` at `y`.
- par: `x` has `a`, `a₂`; take the `R₂`-witness `z` of `x`. `cₑ` on
  `(x, z)`: `Qₑ` at `x` (an `H` hit of the conclusion) or `e(z)`. `y` has
  `e` and `S(x, y)` (from `S⁻(y, x)`), so `[y, z]` are `S.e` neighbours
  of `x` and `y = z`. `c_r` on `(x, z)`: its `B_r` holds at `z = y` (the
  conclusion's `P`), it gives `H_r` at `y` (the conclusion's `Q`) or
  `Q_r` at `x` (the conclusion's `H`).

**Theorem (derivation soundness).** If every step of a certificate
passes its rule check against the steps before it, every clause of the
certificate holds. Induction on the position.

### 3.2 The route

`cbClassify O req C`: let `d` be the derivation of `C`. Check `d`
(theorem above) and the *witness conditions* of `C`: well-formed arrays
(`wfB`), every node passes `nodeOKA` and its pool entries `entryOKA`,
`cacheOKA`, one root per request. Compute the live nodes (`aliveFast`)
and the rows `fastRowsA`. For each request `a`:

- if `d` holds `⟨∅, ∅, B, ∅, ∅⟩` with `B ⊆ {a}`: row `none`;
- else if the witness row of `a` is `some W` and every requested `b ∈ W`
  has `⟨∅, ∅, B, H, ∅⟩` in `d` with `B ⊆ {a}`, `H ⊆ {b}`: row `some`
  (the requested names of `W`);
- else decline.

**Theorem (`cbClassify_spec`).** If `cbClassify O req C = some rows` then
every requested name has a row, and for every row `p`: `p.1 ∈ req`,
`p.2 = none ↔ p.1` is unsatisfiable, and `p.2 = some L → ∀ b ∈ req,
b ∈ L ↔ EntailsSub O p.1 b`.

Proof. `none`: the derived clause says `a ⊑ ⊥` in every model; the
converse is the definition. `some L`: the witness row is `some W`, so by
`fastRows_sound` `a` is satisfiable (row not `none`) and every entailed
`b` lies in `W`; a requested `b ∈ W` has a derived clause, which gives
`EntailsSub O a b`; so for a requested `b`, `b ∈ L ↔ b ∈ W ↔ EntailsSub`.
The step from the array elimination to `fastRows` (`fastRowsA_eq`) used
`ClosedP` only through its node, entry and cache parts; it is restated
for the weaker witness predicate (`WitP`), and `ClosedP → WitP`.

The restriction to requested `b` (instead of every `b`) is the only
change to the row statement; `sriq_bit_rows` reads requested names only,
so `owlSHIQFast_sound` keeps its statement.

## 4. The generator (unproved)

1. **Saturation.** Contexts: one root context per requested name (core
   `{a}`), one successor context per (label `upS R`, filler `b`) of a
   lower clause. A context stores clauses with `B = {core}` (plus
   conditions `P` on its predecessor) and a set of hypotheses (names
   that some predecessor holds and that occur in a clause with a `P`
   part). Rules: hyperresolution through gcis, fwd/bwd, pred (to every
   predecessor context with that lower clause), the counting rules;
   conditional facts keep minimal condition sets. Each derived clause
   records its step. The result: for each requested `a`, the derived
   names and whether `a ⊑ ⊥`.
2. **Witness.** Top down from the roots, a candidate set with the exact
   keys of `FastDefs` (`childKey`): a node's type is the closure of its
   seed under the gcis and the conditional facts of its saturation
   contexts whose conditions hold in the parent type; pools hold the
   default specs, the merged specs of functional roles and the grown
   specs when the parent is the witness. Each context is built once.

## 7. The generator as built (unproved, `lean/SRIQFast/CB.lean`)

Saturation as in section 4, with these details found necessary:

- Static clauses (gcis, back universals) are emitted once per ontology
  position, not per context (this cut GALEN steps from 18 to 9 million
  in 100 s).
- A learned rule is installed only if the context lacks it and lacks
  its head under a weaker condition (`wantRule`).
- Disjunctions: a gci with several heads whose body holds becomes a
  clause `⟨Lc, P, {core}, heads, ∅⟩`; a rule with exactly one body name
  missing, that name a disjunction head and a clash head, gives a
  clash clause `⟨Lc, P, {core, h}, ∅, ∅⟩`; `resX` removes `h` from the
  disjunction. Heads of disjunctions get their successor contexts, so
  the counting rules can refute them.
- Witness: types from the derived facts whose label and conditions
  hold; a disjunction takes an at-most definer whose bound already
  holds for the node's demands (the "free definer" of C1e, section 6),
  else a fresh head; a child reuses a larger type made for the same
  spec when its back set fits the parent; merged specs for functional
  roles; the parent-witness growth of the label.
- Budgets in the probe: saturation 5 s (`KM_SRIQF_CBMS`), witness
  60 000 nodes (`KM_SRIQF_WITMAX`); past either the route declines to
  the closure route.

## 10. Open

- **Saturation volume on GALEN.** The unproved Lean saturation reaches
  40 000 events per second; GALEN needs far more than 300 s. km's
  engine keys successor contexts by the unconditional trigger set and
  sends only fact triggers to the core; doing the same here would cut
  the conditional facts. The certificate check is not the bottleneck.
- **Chemistry.** Derive the counting refutations of the definer
  disjunctions (ordered resolution over the disjunction clauses
  instead of one-name clash clauses).
- **FMA (6134) and the witness.** Exact keys force one context per
  marker set; a witness with fewer contexts needs a relaxed `entryOK`
  (child seed below the parent's forward set) and a new soundness
  proof of the elimination, or a quotient of the markers.
- **9835, 15203** were not reached.
- Goal 2's closure system with filler-keyed contexts and its
  completeness proof were not built: option (iii) replaced it (section
  2). The completeness argument it would need is not written.
