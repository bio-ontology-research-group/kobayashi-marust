## 2. What OWL API 4.5.29 and HermiT 1.4.3.456 Do

We inspected the bytecode of `owlapi-distribution-4.5.29.jar` and
`org.semanticweb.hermit-1.4.3.456.jar` in `~/.m2/repository` and confirmed each
case with minimal ontologies executed directly against OWL API 4.5.29 and
HermiT 1.4.3.456.

### 2.1 Anonymous individuals in `ObjectHasValue` and `ObjectOneOf`

#### OWL 2 specification

In the OWL 2 Structural Specification, the functional-syntax productions
`ObjectOneOf := 'ObjectOneOf' '(' Individual { Individual } ')'` (Section 8.1.4)
and `ObjectHasValue := 'ObjectHasValue' '(' ObjectPropertyExpression Individual ')'`
(Section 8.2.3) reference the general `Individual := NamedIndividual | AnonymousIndividual`
nonterminal, but Section 11.2 ("Global Restrictions on Axioms in OWL 2 DL")
states:

> Anonymous individuals are only allowed in the following axiom types:
> `ObjectPropertyAssertion`, `DataPropertyAssertion`, `AnnotationAssertion`, and
> `NegativeAnnotationPropertyAssertion`.

Note that `ClassAssertion(C _:a)` is permitted by Section 9.6.3 and the Section
11.2 tree conditions; `ObjectHasValue` and `ObjectOneOf` with anonymous
individuals are forbidden in OWL 2 DL.

#### OWL API 4.5.29 behaviour

`org.semanticweb.owlapi.functional.parser.OWLFunctionalSyntaxParser` parses
`Individual()` in both `parseObjectHasValue()` and `parseObjectOneOf()` and
constructs `OWLObjectHasValueImpl(property, OWLAnonymousIndividual)` and
`OWLObjectOneOfImpl(Set<OWLIndividual>)` without rejecting anonymous individuals.

#### HermiT 1.4.3.456 behaviour

HermiT processes class expressions in three stages:

1. **Simplification (`org.semanticweb.HermiT.structural.ExpressionManager`)**:
   - `DescriptionSimplificationVisitor.visit(OWLObjectHasValue)` rewrites every
     `ObjectHasValue(R, ind)` to
     `ObjectSomeValuesFrom(R, ObjectOneOf(ind))` regardless of whether `ind` is
     named or anonymous.
   - Under negation, `ComplementNNFVisitor.visit(OWLObjectHasValue)` rewrites
     `ObjectComplementOf(ObjectHasValue(R, ind))` to
     `ObjectAllValuesFrom(R, ObjectComplementOf(ObjectOneOf(ind)))`.
2. **Normalization (`org.semanticweb.HermiT.structural.OWLNormalization`)**:
   - In `AxiomVisitor.visit(OWLClassAssertionAxiom)`, if the asserted class
     expression is `ObjectHasValue(R, ind)` or `ObjectSomeValuesFrom(R, ObjectOneOf(ind))`,
     HermiT converts the class assertion directly into
     `m_factAxioms.add(df.getOWLObjectPropertyAssertionAxiom(R, subject, ind))`.
   - In `ClassExpressionNormalizer.visit(OWLObjectSomeValuesFrom)`:
     ```java
     OWLClassExpression filler = object.getFiller();
     if (OWLNormalization.isSimple(filler) || OWLNormalization.isNominal(filler)) {
         return object;
     }
     ```
     Because `OWLNormalization.isNominal(OWLObjectOneOf)` returns `true` without
     inspecting the individuals inside `OWLObjectOneOf`, `visit(OWLObjectSomeValuesFrom)`
     returns `ObjectSomeValuesFrom(R, ObjectOneOf(_:a))` immediately without
     recursing into `visit(OWLObjectOneOf)`.
   - In `ClassExpressionNormalizer.visit(OWLObjectAllValuesFrom)`:
     ```java
     if (OWLNormalization.isSimple(filler)
             || OWLNormalization.isNominal(filler)
             || OWLNormalization.isNegatedOneNominal(filler)) {
         return object;
     }
     ```
     Again, `ObjectAllValuesFrom(R, ObjectOneOf(_:a))` and
     `ObjectAllValuesFrom(R, ObjectComplementOf(ObjectOneOf(_:a)))` return
     immediately without visiting `OWLObjectOneOf`.
   - In `ClassExpressionNormalizer.visit(OWLObjectComplementOf)`:
     When the operand is `OWLObjectOneOf` (`isNominal(operand)`), HermiT either
     applies `optimizedNegativeOneOfTranslation` (when the ontology has no
     inverse roles, emitting `ClassAssertion(definer, ind)` for every individual
     in the `ObjectOneOf` without checking `ind.isAnonymous()`) or leaves
     `ObjectComplementOf(ObjectOneOf(_:a))` in the inclusion disjunct (when
     inverse roles are present).
   - Only when a positive `ObjectOneOf(_:a)` is not guarded by `∃`, `∀`, or `¬`
     (for example `SubClassOf(:A ObjectOneOf(_:a))` or
     `ClassAssertion(ObjectOneOf(_:a) :x)`) does execution reach
     `ClassExpressionNormalizer.visit(OWLObjectOneOf)`:
     ```java
     for (OWLIndividual ind : object.getIndividuals()) {
         if (ind.isAnonymous()) {
             throw new IllegalArgumentException(
                 "Error: The class expression " + object
                 + " contains anonymous individuals, which is not allowed in OWL 2 "
                 + "(erratum in first OWL 2 spec, to be fixed with next publication of minor corrections).");
         }
     }
     ```
3. **Clausification (`org.semanticweb.HermiT.structural.OWLClausification`)**:
   - `getIndividual(OWLIndividual)` maps `ind.isAnonymous()` to
     `Individual.createAnonymous(ind.asOWLAnonymousIndividual().getID().toString())`,
     whose internal URI is `"internal:anonymous#" + id`.
   - `NormalizedAxiomClausifier.getConceptForNominal(OWLIndividual)` maps an
     anonymous individual to `AtomicConcept.create("internal:anon#" + id)` and
     adds the ground fact `[internal:anon#_:a](internal:anonymous#_:a)` to
     `m_positiveFacts`. For named individuals, `getConceptForNominal` also adds
     `AtomicConcept.INTERNAL_NAMED(ind)`; for anonymous individuals it omits
     `AtomicConcept.INTERNAL_NAMED`.
   - In `org.semanticweb.HermiT.Reasoner`, `m_namedIndividuals` contains only
     `OWLNamedIndividual`s from the ontology signature, and DL-safe rules /
     `HasKey` axioms guard their variables with `AtomicConcept.INTERNAL_NAMED`.

#### Semantics HermiT implements and relation to OWL 2 Direct Semantics

HermiT implements **ontology-wide Skolem-constant semantics** for anonymous
individuals: every occurrence of a blank-node identifier `_:a` across the
ontology -- whether in `ClassAssertion`, `ObjectPropertyAssertion`,
`DataPropertyAssertion`, `ObjectHasValue`, or `ObjectOneOf` -- denotes the same
single unnamed domain element `internal:anonymous#_:a`. Because that constant is
excluded from `m_namedIndividuals` and lacks `AtomicConcept.INTERNAL_NAMED`, it
never appears in `getInstances`, `getTypes`, `getSameIndividuals`,
`getDifferentIndividuals`, or `getObjectPropertyValues`, and never binds
variables in `HasKey` or DL-safe SWRL rules.

Does this semantics follow from the OWL 2 Direct Semantics for the RDF graph
(where an anonymous individual is an existential variable), or is it HermiT's
own choice?

- **The shared-constant semantics across the ontology follows from the OWL 2
  Direct Semantics.** In OWL 2 Direct Semantics Section 2.5 ("Ontologies"), as
  in the RDF Simple and D-entailment semantics for blank nodes, anonymous
  individuals $\_:a_1, \dots, \_:a_k$ are existentially quantified at the
  **ontology root**: an interpretation $\mathcal{I}$ satisfies an ontology $O$
  iff there exists an assignment $\alpha : \{\_:a_1, \dots, \_:a_k\} \to \Delta^{\mathcal{I}}$
  under which $\mathcal{I}[\alpha]$ satisfies every axiom in $O$. They are not
  locally existentially quantified per axiom or per class expression. Extending
  the interpretation of `ObjectOneOf` ($\{a_1, \dots, a_n\}^{\mathcal{I}[\alpha]} = \{a_1^{\mathcal{I}[\alpha]}, \dots, a_n^{\mathcal{I}[\alpha]}\}$)
  and `ObjectHasValue` ($(R\text{ value }a)^{\mathcal{I}[\alpha]} = \{x \in \Delta^{\mathcal{I}} \mid (x, a^{\mathcal{I}[\alpha]}) \in R^{\mathcal{I}}\}$)
  to evaluate anonymous individuals under the same ontology-level assignment
  $\alpha$ makes $\exists \_:a_1 \dots \_:a_k.\,\bigwedge_{\phi \in O} \phi$
  equisatisfiable with the Skolemized ontology $O[\_:a_i \mapsto c_i]$ where
  each $c_i$ is a fresh individual constant outside the public query signature
  $\Sigma$. Because queries over $\Sigma$ cannot mention $\_:a_i$, standard
  first-order Skolemization preserves ontology consistency and all entailments
  over $\Sigma$, provided that $c_i$ is excluded from the named-individual
  sort (`INTERNAL_NAMED`) over which `HasKey` and DL-safe SWRL variables range.
- **HermiT's syntactic boundary is HermiT's own implementation artifact.**
  Accepting `ObjectHasValue(R _:a)`, `ObjectSomeValuesFrom(R ObjectOneOf(_:a))`,
  `ObjectAllValuesFrom(R ObjectOneOf(_:a))`, and `ObjectComplementOf(ObjectOneOf(_:a))`
  while rejecting bare positive `ObjectOneOf(_:a)` in `SubClassOf(:A ObjectOneOf(_:a))`
  has no semantic basis; it happens only because `ClassExpressionNormalizer`
  returns early on `isNominal(filler)` in `visit(OWLObjectSomeValuesFrom)` and
  `visit(OWLObjectAllValuesFrom)` before `visit(OWLObjectOneOf)` can run.

#### Minimal ontologies and HermiT 1.4.3.456 confirmation

1. **Ontology-wide identity of `_:b1` in `ObjectHasValue`:**
   ```owl
   Prefix(:=<http://example.org/t#>)
   Ontology(
     Declaration(Class(:A))
     Declaration(Class(:B))
     Declaration(ObjectProperty(:r))
     Declaration(NamedIndividual(:x))
     InverseFunctionalObjectProperty(:r)
     SubClassOf(:A ObjectHasValue(:r _:b1))
     ClassAssertion(ObjectHasValue(:r _:b1) :x)
     ClassAssertion(:B :x)
   )
   ```
   If `_:b1` were locally existentially quantified (`∃:r.⊤`), `:A ⊑ :B` would
   not hold. Because `_:b1` denotes a single Skolem constant shared by both
   axioms and `:r` is inverse-functional, every instance of `:A` must equal `:x`
   and belong to `:B`. HermiT 1.4.3.456 reports `isConsistent() = true` and
   `getSuperClasses(:A, true) = {:B}`.

2. **`ObjectOneOf(_:b1)` under `ObjectSomeValuesFrom` vs bare positive `ObjectOneOf(_:b1)`:**
   ```owl
   Prefix(:=<http://example.org/t#>)
   Ontology(
     Declaration(Class(:A))
     Declaration(ObjectProperty(:r))
     SubClassOf(:A ObjectSomeValuesFrom(:r ObjectOneOf(_:b1)))
   )
   ```
   HermiT 1.4.3.456 loads this ontology and reports `isConsistent() = true`.
   In KM's lenient mode, Skolemizing `_:b1` to a fresh internal named individual
   accepts both `ObjectHasValue` and `ObjectOneOf` uniformly under the same
   ontology-wide Skolem-constant semantics.

### 2.2 Anonymous-individual forest restrictions (`anonymous_individual_forest_no_root`, 37 files)

#### OWL 2 specification

OWL 2 Structural Specification Section 11.2 requires the anonymous-individual
assertion graph of an OWL 2 DL ontology to be a forest whose connected
components each have a single named individual as root, with no self-loops, no
cycles, and at most one property assertion between any pair of anonymous
individuals.

#### OWL API 4.5.29 and HermiT 1.4.3.456 behaviour

OWL API 4.5.29 parses `ClassAssertion`, `ObjectPropertyAssertion`, and
`DataPropertyAssertion` on anonymous individuals without checking Section 11.2.
HermiT's `OWLNormalization$AxiomVisitor` rejects anonymous individuals in
`SameIndividual`, `DifferentIndividuals`, `NegativeObjectPropertyAssertion`, and
`NegativeDataPropertyAssertion` (`OWLNormalization.java:603, 618, 653, 676`),
but never checks the Section 11.2 forest/root/self-loop conditions on positive
assertions. `OWLClausification$FactClausifier` translates every positive
assertion on `_:a` into ground ABox facts on `Individual.createAnonymous(id)`.

#### Minimal ontology and HermiT 1.4.3.456 confirmation

```owl
Prefix(:=<http://example.org/t#>)
Ontology(
  Declaration(Class(:C))
  Declaration(ObjectProperty(:r))
  Declaration(NamedIndividual(:n1))
  Declaration(NamedIndividual(:n2))
  ClassAssertion(:C _:b1)
  ObjectPropertyAssertion(:r _:b1 _:b1)
  ObjectPropertyAssertion(:r :n1 _:b1)
  ObjectPropertyAssertion(:r :n2 _:b1)
  SubClassOf(ObjectHasSelf(:r) owl:Nothing)
)
```
This ontology violates Section 11.2 in three ways (a self-loop on `_:b1` and two
named roots `:n1, :n2` reaching `_:b1`). HermiT 1.4.3.456 loads it without error
and reports `isConsistent() = false` because `r(_:b1, _:b1)` triggers
`ObjectHasSelf(:r) ⊑ owl:Nothing`.

### 2.3 Non-RFC3987 IRIs (`non_ascii_iri_parse_error`, 5 files; `bracket_in_iri_parse_error`, 2 files)

#### Are the IRIs legal under RFC 3987?

No:

1. In `ore_ont_10197`, `ore_ont_11411`, `ore_ont_16542`, `ore_ont_9694`, and
   `ore_ont_9881`, the rejected token is:
   ```text
   <http://puls.cs.helsinki.fi/med/expression1#en-Baden-Wrttemberg-N>
   ```
   where `` is `U+FFFD` (`\xEF\xBF\xBD`, the Unicode Replacement Character).
   RFC 3987 Section 2.2 defines:
   ```abnf
   ucschar = %xA0-D7FF / %xF900-FDCF / %xFDF0-FFEF
           / %x10000-1FFFD / %x20000-2FFFD / %x30000-3FFFD
           / %x40000-4FFFD / %x50000-5FFFD / %x60000-6FFFD
           / %x70000-7FFFD / %x80000-8FFFD / %x90000-9FFFD
           / %xA0000-AFFFD / %xB0000-BFFFD / %xC0000-CFFFD
           / %xD0000-DFFFD / %xE1000-EFFFD
   ```
   The Specials block `U+FFF0..U+FFFF` (including `U+FFFD`) is excluded from
   `ucschar`.
2. In `ore_ont_20` and `ore_ont_5753`, the rejected tokens contain unescaped `[`
   and `]` in the IRI fragment (`<http://www.ontologydesignpatterns.org/cp/owl/situation.owl#[event:Event,]>`,
   `<http://data.linkedmdb.org/resource/movie/director#LinkedMDB:[http://data.linkedmdb.org/resource/director/10002]>`).
   In RFC 3987 Section 2.2, `[` and `]` belong to `gen-delims` and are allowed
   only in `IP-literal` host subcomponents, not in `ipath` or `ifragment`.

Because neither class is a legal RFC 3987 IRI, KM's strict parser (`km_owl_functional_syntax`)
is right to reject them.

#### OWL API 4.5.29 and HermiT 1.4.3.456 behaviour

In OWL API 4.5.29, `org.semanticweb.owlapi.functional.parser.CustomTokenizer.readFullIRI()`
scans from `<` to the next `>` and accepts every character between them without
checking RFC 3987 character classes. `IRI.create(String)` stores the raw string
verbatim, and HermiT uses `entity.getIRI().toString()` as the internal string
identifier for concepts, roles, and individuals.

#### Minimal ontology and HermiT 1.4.3.456 confirmation

```owl
Ontology(
  Declaration(Class(<http://example.org/t#Baden-Wrttemberg>))
  Declaration(Class(<http://example.org/t#[Event,]>))
  SubClassOf(<http://example.org/t#Baden-Wrttemberg> <http://example.org/t#[Event,]>)
)
```
OWL API 4.5.29 parses both IRIs verbatim and HermiT 1.4.3.456 reports
`<http://example.org/t#[Event,]>` as a direct superclass of
`<http://example.org/t#Baden-Wrttemberg>`.

### 2.4 Literals typed `rdfs:Literal` (9 files) and unknown datatypes (4 files)

#### OWL 2 specification

OWL 2 Structural Specification Section 4 ("Datatype Maps") and OWL 2 Direct
Semantics Section 2.1 place `rdfs:Literal` at the top of the data range
hierarchy ($\text{rdfs:Literal}^{\mathcal{I}} = \Delta_D$), not in the lexical
datatype map: `rdfs:Literal` has no lexical space and no lexical-to-value
mapping $L_{\text{rdfs:Literal}}$, so `"..."^^rdfs:Literal` is ill-formed in
OWL 2 DL. Similarly, datatypes outside the OWL 2 datatype map that lack a
`DatatypeDefinition` axiom have no interpretation in strict OWL 2 DL.

#### OWL API 4.5.29 and HermiT 1.4.3.456 behaviour

OWL API 4.5.29 parses `"..."^^rdfs:Literal` and arbitrary datatype IRIs into
`OWLLiteralImplNoCompression` and `OWLDatatypeImpl`.

In HermiT 1.4.3.456 (`org.semanticweb.HermiT.structural.OWLClausification$DataRangeConverter`):
- `DatatypeRegistry` has no literal parser for `rdfs:Literal` or unknown
  datatype IRIs; `DatatypeRegistry.parseLiteral` throws
  `UnsupportedDatatypeException`.
- When `Configuration.ignoreUnsupportedDatatypes` is `false` (the default of
  `new Configuration()`, used when `ReasonerFactory.createReasoner(ont, new SimpleConfiguration())`
  is called), `DataRangeConverter` lets `UnsupportedDatatypeException` propagate.
- When `Configuration.ignoreUnsupportedDatatypes` is `true` (the default in
  Protégé via `ProtegeReasonerFactory` and `ReasonerFactory.createReasoner(ont)`),
  `DataRangeConverter.visit(OWLLiteral)` catches `UnsupportedDatatypeException`
  and returns `Constant.createAnonymous(literal.getLiteral())`
  (`"internal:anon-constants#" + lexicalForm`), and `visit(OWLDatatype)` records
  unknown datatypes in `m_allUnknownDatatypeRestrictions`.

This is the opaque-value semantics already implemented by KM's
`--unknown-datatypes=free` option (`docs/V1.7.0-RULES-SHOIQ.md` Section 5 and
`docs/DATATYPES.md`). Note one difference in HermiT's implementation: in
HermiT's `DatatypeManager.loadConjunctionFrom` (`DatatypeManager.java:810`),
`ROOT_CONSTANT_NODE`s created for ABox `DataPropertyAssertion` constants are
skipped (`if (node.getNodeType() == Tableau.NodeType.ROOT_CONSTANT_NODE) continue;`),
so HermiT fails to detect an ABox clash between
`DataPropertyAssertion(:dp :a "NULL"^^rdfs:Literal)` and
`ClassAssertion(DataAllValuesFrom(:dp DataComplementOf(DataOneOf("NULL"^^rdfs:Literal))) :a)`,
whereas it does detect the same clash when both are written as class expressions
`SubClassOf(:A DataHasValue(:dp "NULL"^^rdfs:Literal))` and
`SubClassOf(:A DataAllValuesFrom(:dp DataComplementOf(DataOneOf("NULL"^^rdfs:Literal))))`.
KM's opaque-value encoding treats both forms identically and soundly detects
the clash in both.

#### Minimal ontology and HermiT 1.4.3.456 confirmation

```owl
Prefix(:=<http://example.org/t#>)
Prefix(rdfs:=<http://www.w3.org/2000/01/rdf-schema#>)
Ontology(
  Declaration(Class(:A))
  Declaration(Class(:B))
  Declaration(DataProperty(:dp))
  Declaration(Datatype(:customDt))
  SubClassOf(:A DataHasValue(:dp "NULL"^^rdfs:Literal))
  SubClassOf(DataSomeValuesFrom(:dp DataOneOf("NULL"^^rdfs:Literal)) :B)
  DataPropertyRange(:dp :customDt)
)
```
With `ignoreUnsupportedDatatypes = true` (via `ReasonerFactory.createReasoner(ont)`),
HermiT 1.4.3.456 reports `isConsistent() = true` and `getSuperClasses(:A, true) = {:B}`.

### 2.5 Undeclared `AnnotationProperty` (4 primary files, 2 secondary files)

OWL 2 Structural Specification Section 5.8.1 requires every entity used in an
OWL 2 DL ontology, including annotation properties, to be declared. OWL API
4.5.29's `OWLFunctionalSyntaxParser` creates `OWLAnnotationProperty` instances
on the fly without requiring `Declaration(AnnotationProperty(...))`, and HermiT
1.4.3.456 ignores annotations during normalization.

#### Minimal ontology

```owl
Prefix(:=<http://example.org/t#>)
Ontology(
  Declaration(Class(:A))
  Declaration(Class(:B))
  AnnotationAssertion(:undeclaredProp :A "note")
  SubClassOf(:A :B)
)
```
HermiT 1.4.3.456 reports `isConsistent() = true` and `getSuperClasses(:A, true) = {:B}`.

### 2.6 Non-XSD character escape `\~` in `xsd:pattern` (1 file: `ore_ont_9600`)

In `ore_ont_9600`, two `DatatypeRestriction` ranges use `xsd:pattern` with `\\~`
(`"[\\~]..."`). XML Schema Part 2 Appendix F allows single-character backslash
escapes only for `.\?*+{}()|[]^$-` (`SingleCharEsc`); escaping `~` is a syntax
error (`FORX0002`). HermiT 1.4.3.456 compiles `xsd:pattern` facets with
`dk.brics.automaton.RegExp`, which accepts `\<c>` for any character `<c>` as a
literal `<c>`.

#### Minimal ontology

```owl
Prefix(:=<http://example.org/t#>)
Prefix(xsd:=<http://www.w3.org/2001/XMLSchema#>)
Ontology(
  Declaration(Class(:A))
  Declaration(DataProperty(:dp))
  SubClassOf(:A DataSomeValuesFrom(:dp DatatypeRestriction(xsd:string xsd:pattern "[\\~]abc")))
)
```
HermiT 1.4.3.456 loads this ontology and reports `isConsistent() = true` and
`isSatisfiable(:A) = true`. In KM, `xsd:pattern` facet restrictions are outside
the decided datatype fragment (`engine/src/frontend/datatypes/vocabulary.rs`), so
under `--lenient` `ore_ont_9600` passes structural validation (`rc = 0` instead
of `rc = 2`) and reports `DROPPED 5` for the five pattern-restricted clauses.

## 3. Lenient Mode Design (`--lenient` and `lenient` Session Option)

### 3.1 CLI and session interface

- `km classify --lenient` (or `--lenient=true`, `KM_LENIENT=1`; disabled by
  default, `--lenient=false` or `KM_LENIENT=0`) enables lenient mode for one
  classification run.
- `km incremental-source --lenient` sets the session default to lenient mode,
  and `init` / `replace` JSONL commands accept `"lenient": true | false`
  alongside `"unknown_datatypes": "free" | "strict"`.

### 3.2 Source-level rewrites (`engine/src/frontend/lenient.rs`)

When lenient mode is off, `lenient::rewrite_source` is not called and KM's
behaviour and output are byte-identical to strict mode. When lenient mode is on,
`lenient::rewrite_source` transforms the input Functional Syntax document into a
valid OWL 2 DL Functional Syntax document before `conformance::check_user_source`,
profiling, routing, and the certified reasoning pipeline run:

1. **Non-RFC3987 characters in `<...>` FullIRIs**:
   Any `<...>` token that `km_owl_functional_syntax::full_iri_valid` rejects has
   its non-RFC3987 characters replaced by collision-free ASCII markers
   `__km_lenient_uXXXX__` (or `__km_lenient_UXXXXXXXX__`). Before public output
   is emitted (`Classification`, `JsonClassification`, `Realization`,
   `PropertyHierarchy`, `DataPropertyHierarchy`, `AboxRows`, and `Taxonomy`),
   `lenient::unescape_iri` restores the exact original IRI characters.
   Recorded as: `LENIENT	escaped non-RFC3987 character(s) in N IRI(s)`.
2. **Non-XSD `\~` escape in `xsd:pattern` facet literals**:
   Inside `DatatypeRestriction(... xsd:pattern "...")`, if `\\~` causes XSD
   regex compilation to fail and replacing `\\~` with `~` compiles as a valid
   XSD regular expression, the literal is rewritten to use `~`.
   Recorded as: `LENIENT	unescaped \~ in N xsd:pattern literal(s)`.
3. **Anonymous individuals in `ObjectHasValue` / `ObjectOneOf` and Section 11.2
   forest violations**:
   If any anonymous individual `_:id` occurs inside `ObjectHasValue` or
   `ObjectOneOf`, or if `conformance::anonymous::check` rejects the anonymous-individual
   assertion graph for a Section 11.2 forest/root/self-loop/multi-edge
   violation (while still rejecting anonymous individuals in `SameIndividual`,
   `DifferentIndividuals`, `NegativeObjectPropertyAssertion`, and
   `NegativeDataPropertyAssertion`, which HermiT also rejects), every anonymous
   individual `_:id` in the ontology is Skolemized to a fresh declared named
   individual `<urn:km:lenient:anon#km_anon_...>` with a corresponding
   `Declaration(NamedIndividual(<...>))` injected at the start of `Ontology(...)`.
   Skolemized anonymous individuals are excluded from `iri_map`/`named`, from
   `realize`/`values`/`different` output, and from DL-safe rule / `HasKey`
   named-individual variable binding, matching HermiT's
   `Individual.createAnonymous` / `internal:anon#` semantics.
   Recorded as: `LENIENT	skolemized N anonymous individual(s) in ObjectHasValue/ObjectOneOf`
   and/or `LENIENT	skolemized N anonymous individual(s) violating OWL 2 section 11.2 forest restrictions`.
4. **Undeclared `AnnotationProperty` entities**:
   Any `AnnotationProperty` IRI used in an axiom without a matching
   `Declaration(AnnotationProperty(iri))` has the missing declaration injected at
   the start of `Ontology(...)` (OWL API always emits declarations for `Class`,
   `ObjectProperty`, `DataProperty`, and `Datatype`, and only omits
   `Declaration(AnnotationProperty(...))`; strict declaration checking for those
   four kinds is preserved).
   Recorded as: `LENIENT	declared N undeclared AnnotationProperty entity/entities`.
5. **Literals typed `rdfs:Literal` and unknown datatypes**:
   Lenient mode enables opaque-value handling for `rdfs:Literal`-typed literals
   and unknown datatypes (equivalent to `unknown_datatypes=free`) and records a
   `LENIENT` note when such literals or data ranges occur in the input:
   `LENIENT	accepted N literal(s) typed rdfs:Literal as opaque data value(s)`
   and/or `LENIENT	accepted N unknown datatype occurrence(s) as free`.

### 3.3 Output format

- In `--lines` mode (`km classify --lines --lenient`), each applied lenient
  rewrite or acceptance is emitted as a `LENIENT\t<description>` line immediately
  after `DROPPED`.
- In JSON mode (`km classify --lenient` and `km incremental-source`), when one
  or more lenient rewrites/acceptances were applied, the result object carries
  `"lenient": ["<description>", ...]`. When `--lenient` is off (or when no
  lenient rewrite was needed), the `"lenient"` key is omitted so the JSON output
  is byte-identical to strict mode.

### 3.4 Soundness Note: Which Lenient Rewrites Preserve OWL 2 Direct Semantics and Which Follow HermiT

**Rewrites that preserve OWL 2 Direct Semantics over the public named signature (anonymous-individual Skolemization and undeclared annotation properties).**
In OWL 2 Direct Semantics Section 2.5, anonymous individuals $\_:a_1, \dots, \_:a_k$ are existentially quantified at the ontology root: an interpretation $\mathcal{I}$ satisfies an ontology $O$ if and only if there exists an assignment $\alpha : \{\_:a_1, \dots, \_:a_k\} \to \Delta^{\mathcal{I}}$ under which $\mathcal{I}[\alpha]$ satisfies every axiom in $O$ (whether `ClassAssertion`, `ObjectPropertyAssertion`, `DataPropertyAssertion`, or, when evaluated under the same assignment $\alpha$, `ObjectHasValue` and `ObjectOneOf`). Replacing each $\_:a_i$ by a fresh individual constant $c_i \notin \Sigma$ outside the public signature $\Sigma$ (and excluding $c_i$ from the named-individual domain $D_N^{\mathcal{I}}$ over which `HasKey` and DL-safe SWRL variables range, as well as from `iri_map`, `named`, and `realize`/`values`/`different` output) is standard first-order Skolemization: every model $\mathcal{I}$ of $O$ with witness assignment $\alpha$ expands to a model $\mathcal{I}'$ of $O[\_:a_i \mapsto c_i]$ by setting $c_i^{\mathcal{I}'} = \alpha(\_:a_i)$, and the $\Sigma$-reduct of any model $\mathcal{I}'$ of $O[\_:a_i \mapsto c_i]$ satisfies $O$ under $\alpha(\_:a_i) = c_i^{\mathcal{I}'}$. Consequently, for every axiom or query $\psi$ over the public named signature $\Sigma$ (consistency, class subsumption $C \sqsubseteq D$, realization $C(a)$, property hierarchy, and named-individual assertions $r(a, b)$, $a = b$, $a \ne b$), $O \models \psi$ if and only if $O[\_:a_i \mapsto c_i] \models \psi$ ($O \cup \{\neg\psi\}$ is unsatisfiable if and only if $O[\_:a_i \mapsto c_i] \cup \{\neg\psi\}$ is unsatisfiable, since $\psi$ mentions no $c_i$). Similarly, injecting `Declaration(AnnotationProperty(p))` for undeclared annotation properties adds only a non-logical declaration axiom whose satisfaction condition in OWL 2 Direct Semantics is vacuous ($\text{true}$ in every interpretation). Minimal example where ontology-level existential semantics entails a named-signature subsumption `:A ⊑ :B` and Skolemization preserves it:
```owl
Prefix(:=<http://example.org/t#>)
Ontology(
  Declaration(Class(:A)) Declaration(Class(:B))
  Declaration(ObjectProperty(:r)) Declaration(NamedIndividual(:x))
  InverseFunctionalObjectProperty(:r)
  SubClassOf(:A ObjectHasValue(:r _:b1))
  ObjectPropertyAssertion(:r :x _:b1)
  ClassAssertion(:B :x)
)
```
In every model $\mathcal{I}$ and root assignment $\alpha$, any $y \in \text{A}^{\mathcal{I}}$ satisfies $(y, \alpha(\_:b_1)) \in r^{\mathcal{I}}$, and $(\text{x}^{\mathcal{I}}, \alpha(\_:b_1)) \in r^{\mathcal{I}}$ with inverse-functionality of $r$ forces $y = \text{x}^{\mathcal{I}} \in \text{B}^{\mathcal{I}}$, so $O \models \text{A} \sqsubseteq \text{B}$.

**Rewrites that follow HermiT 1.4.3.456 instead of the strict OWL 2 / RFC 3987 / XSD specifications (`rdfs:Literal`-typed literals, unknown datatypes, non-RFC3987 IRIs, and `\~` in `xsd:pattern`).**
Four lenient acceptances depart from the strict W3C normative specifications in order to match OWL API 4.5.29 and HermiT 1.4.3.456 under Protégé's default configuration (`ignoreUnsupportedDatatypes = true`): (1) literals typed `rdfs:Literal` (`"lex"^^rdfs:Literal`) and (2) unknown datatypes without a `DatatypeDefinition` are ill-formed in strict OWL 2 DL because `rdfs:Literal` has no lexical-to-value mapping $L_{\text{rdfs:Literal}}$ and unregistered datatype IRIs are outside the OWL 2 datatype map, but HermiT maps `"lex"^^rdfs:Literal` and unknown-datatype literals via `Constant.createAnonymous(lex)` to opaque constants in $\Delta_D$ keyed by lexical form and leaves unknown datatype ranges unconstrained (`unknown_datatypes=free`); (3) `<...>` IRIs containing `U+FFFD` or unescaped `[` / `]` violate RFC 3987 Section 2.2, but OWL API's `CustomTokenizer.readFullIRI()` and HermiT treat the raw character sequence between `<` and `>` as an opaque symbol identifier (which KM matches by reversible ASCII marker escaping); and (4) `\\~` inside `xsd:pattern` violates XML Schema Part 2 Appendix F (`SingleCharEsc`), but HermiT's `dk.brics.automaton.RegExp` treats `\\~` as a literal `~`. Minimal example where `"NULL"^^rdfs:Literal` is ill-formed under strict OWL 2 DL but accepted by HermiT (`ignoreUnsupportedDatatypes = true`) and KM (`--lenient`) as an opaque constant equal to itself:
```owl
Prefix(:=<http://example.org/t#>)
Prefix(rdfs:=<http://www.w3.org/2000/01/rdf-schema#>)
Ontology(
  Declaration(Class(:A)) Declaration(Class(:B)) Declaration(DataProperty(:dp))
  SubClassOf(:A DataHasValue(:dp "NULL"^^rdfs:Literal))
  SubClassOf(DataSomeValuesFrom(:dp DataOneOf("NULL"^^rdfs:Literal)) :B)
)
```
Strict OWL 2 DL rejects `"NULL"^^rdfs:Literal` (`rc = 2`); under HermiT (`ignoreUnsupportedDatatypes = true`) and KM (`--lenient`), both occurrences denote the same opaque constant in $\Delta_D$, entailing `:A ⊑ :B`.

### 3.5 Unified `NamedRoleBound` Extension for `SameIndividual`, `ObjectHasValue`, and Equality Merges

In `engine/src/frontend/named_role_bound.rs`, `NamedRoleBound` is extended so that a single audited bound covers rule-free ontologies containing `SameIndividual`, `ObjectHasValue`, and functional, inverse-functional, or max-cardinality merges (such as the SWEET ontologies in the 30-file parity sample):
- Positive `ObjectHasValue(r, b)` seeds $b \in W_{\text{src}}(r)$ (`(*, b)` in $r$) and positive `ObjectHasValue(ObjectInverseOf(r), a)` seeds $a \in W_{\text{dst}}(r)$ (`(a, *)` in $r$).
- An equivalence relation $\sim$ on named individuals is initialized from `SameIndividual` and closed in the Datalog fixpoint alongside `SubObjectPropertyOf`, `InverseObjectProperties`, `SymmetricObjectProperty`, `TransitiveObjectProperty`, and `ObjectPropertyChain` under merges induced by `FunctionalObjectProperty`, `InverseFunctionalObjectProperty`, and positive `ObjectMaxCardinality` / `ObjectExactCardinality` (with bound $\ge 1$).
- Whenever $u \sim v$ is derived, congruence closes $E^+(s)$, $W_{\text{src}}(s)$, and $W_{\text{dst}}(s)$ across **all** object properties $s$ (not only the merging role), so any role pointing at $u$ also includes $v$ in its reachable target bound. When a merging role has unconstrained targets in $N$, every active or existential role is widened to universal target reachability. See `docs/V1.7.0-RULES-SHOIQ.md` Section 2.4 for the full specification.

### 5.2 Adjudication of all 293 `differ_content` calls and 46 `hermit_error` calls

Every single one of the 293 `differ_content` calls and 46 `hermit_error` calls
across the 30 ontologies falls into an adjudicated category where KM is right
under OWL 2 Direct Semantics and HermiT 1.4.3.456 is incomplete or defective:

1. **Bottom-property domains and ranges (`142` `differ_content` calls across 24
   ontologies: 48 `getObjectPropertyDomains(owl:bottomObjectProperty)`, 48
   `getObjectPropertyRanges(owl:bottomObjectProperty)`, 46
   `getDataPropertyDomains(owl:bottomDataProperty)`)**:
   - Under OWL 2 Direct Semantics, `owl:bottomObjectProperty` and
     `owl:bottomDataProperty` have empty extensions in every interpretation, so
     every class `C` satisfies $\exists \bot.\top \sqsubseteq C$. Consequently,
     the direct domain/range is `{owl:Nothing}` and the non-direct domain/range
     is the set of all named classes (which KM returns). HermiT 1.4.3.456
     returns `{owl:Thing}` for both `direct = true` and `direct = false` (known
     HermiT defects `H2` and `H5` in `protege-parity/parity_adjudication.py`).

2. **Entailed `getDataPropertyValues(ind, dp)` from TBox `DataHasValue` axioms
   (`97` `differ_content` calls across 19 SWEET ontologies)**:
   - In the SWEET ontologies (e.g. `ore_ont_14255`, `ore_ont_6504`,
     `ore_ont_13941`, `ore_ont_14593`), chemical elements and spatial directions
     are punned as both classes and named individuals via
     `ClassAssertion(:Al :Al)` and `SubClassOf(:Al DataHasValue(:atomicNumber "13"^^xsd:integer))`,
     or `ClassAssertion(:Right :Right)` and
     `SubClassOf(:Right DataHasValue(:hasDimension "3"^^xsd:integer))`.
   - Under OWL 2 Direct Semantics, $\text{Al}^{\mathcal{I}} \in \text{Al}^{\mathcal{I}}$
     together with $\text{Al}^{\mathcal{I}} \subseteq (\exists \text{atomicNumber}.\{13\})^{\mathcal{I}}$
     entails `DataPropertyAssertion(:atomicNumber :Al "13"^^xsd:integer)`.
   - Decompiling `org.semanticweb.HermiT.Reasoner.getDataPropertyValues` shows
     that HermiT 1.4.3.456 does not run tableau entailment checks for
     `getDataPropertyValues`; it inspects only explicitly asserted ABox
     `m_dlOntology.getDataPropertyAssertions()` (already noted in
     `protege/src/test/java/org/bioontology/kobayashimarust/protege/ReductionsTest.java:376`).
     HermiT returns `[]` on all 97 calls, whereas KM returns the entailed
     literal (e.g. `{"13"^^xsd:integer}`).

3. **Transitive `getSameIndividuals(ind)` on 3+-element `SameIndividual` chains
   (`54` `differ_content` calls across 20 SWEET ontologies)**:
   - In the SWEET ontologies, synonyms are linked by binary `SameIndividual`
     chains of length 3 or 4, such as `SameIndividual(:Alive :Live)` and
     `SameIndividual(:Live :Living)` in `ore_ont_6504`, or
     `SameIndividual(:Benzene :Benzol)` and `SameIndividual(:Benzene :C6H6)` in
     `ore_ont_14255`.
   - By the symmetry and transitivity of equality in OWL 2 Direct Semantics,
     `getSameIndividuals(:Living)` is `{:Alive, :Live, :Living}` and
     `getSameIndividuals(:Benzene)` is `{:Benzene, :Benzol, :C6H6}`, which KM
     returns on all 54 calls.
   - Decompiling `org.semanticweb.HermiT.hierarchy.InstanceManager`
     (bytecode offsets 126--149 of the deterministic individual-equivalence
     merge loop) shows a bug in HermiT 1.4.3.456: when merging equivalence set
     `eq7` (for `ind5`) into `eq6` (for canonical node `ind4`), HermiT executes
     `eq6.addAll(eq7); m_individualToEquivalenceClass.put(ind5, eq6);` without
     updating `m_individualToEquivalenceClass` for the other individuals that
     were already in `eq7`. Those individuals keep pointing to the stale subset
     `eq7` (e.g. `{:Live, :Living}` missing `:Alive`), causing HermiT to omit
     members of the equivalence class whenever `getSameIndividuals` is queried
     on a non-canonical member of a 3+-element chain.

4. **HermiT exceptions on valid OWL 2 DL entailment queries (`46` `hermit_error`
   calls: 44 `isEntailed(DisjointDataProperties(...))` across 22 ontologies and
   2 `isEntailed(InverseObjectProperties(...))` on `ore_ont_6635`)**:
   - Known HermiT bugs `H3` and `H4` in `protege-parity/parity_adjudication.py`:
     HermiT rewrites `DisjointDataProperties` into a class expression containing
     `DataMaxCardinality(1 owl:topDataProperty ...)`, which its own validator
     rejects with `IllegalArgumentException`, and throws `NullPointerException`
     (`subroleNode is null`) on `isEntailed(InverseObjectProperties(...))` when
     the ontology has no inverse object properties. KM answers all 46 queries.

### 5.3 Unsupported calls (`102` `km_unsupported`) and timeouts

- The 102 `km_unsupported` calls are honest `UnsupportedOperationException`

- On 21 of the 22 SWEET ontologies (`anonymous_individual_in_ObjectHasValue`),

  `getObjectPropertyValues` (`146`--`155` `hermit_timeout` calls per ontology,
  plus `4,291` on `ore_ont_14367` where HermiT times out in class hierarchy
  inference), whereas KM completes all class, property, individual, and
  object-property-value inferences within the per-call budget (`0` `km_timeout`
  across all 22 SWEET ontologies).
- On `ore_ont_2513` and `ore_ont_9654` (`anonymous_individual_forest_no_root`,
  large ABoxes with cyclic anonymous-individual graphs), HermiT times out during

  and crashes on `ore_ont_9654`.
- On `ore_ont_12955` (`literal_unknown_datatype`), both HermiT and KM hit the
  300 s ontology budget during `precomputeInferences`.
